# v3 门禁、审查与工作流修复计划

状态：**当前工作区审计与修复入口；不代表问题已修复或验收已通过。**

审计基线：`integration/v3` / `311b215`，包含基线之后尚未提交的工作区修改。审计范围是 S03、S06—S10、S12，生成受理与执行、恢复、发布及相关前端交接。本文只覆盖这些缺口；账号、备份、界面重建沿用既有规范，不在此扩范围。

## 0. 执行入口

实施最终确认、图片重试、旧接口、恢复、候选修正或发布修复时，先读本文，再按下表读取权威规则。每步先写能通过真实 HTTP 入口复现缺陷的测试，再改实现；私有函数探针只用于定位。

| 分支 | 权威规则 | 主要实现入口 |
|---|---|---|
| 受理、最终确认、重试、恢复 | [提示词确认契约](../../docs/architecture/prompt-confirmation-v3.md) | `s06.py`、`s07.py`、`s08.py`、`generation_cycle.py`、`generation_recovery.py` |
| 裁决、软硬约束、独立审查 | [门禁与工作流 v3](../../docs/architecture/workflow-gates-v3.md) | `adjudication.py`、`s03.py`、`s09.py`、`s10.py` |
| 额度、并发、历史与验收 | [SRS v3](SRS_v3.md) 第 9—13 节 | `acceptance.py`、`workflow/tables.py` 及迁移 |
| 展示、内联图片与登录隔离 | [纯对话改造](modify_v3.md) | `WorkflowPanel.vue`、`ChatPage.vue`、工作流投影 |

冲突以现行 SRS 和提示词确认契约为准。修复不得把“准备提示词”解释为“已授权生图”，也不得把“批准报告”解释为“批准图片”。

## 1. 审计结论与修复边界

当前正常主链已有独立裁决和 S07 后停点，但存在旧接口、重试、修正图与恢复旁路。以下编号用于实现、测试和验收追踪。

| 编号 | 等级 | 当前证据 | 必须修复的行为 |
|---|---|---|---|
| GF-01 | 阻断 | S08/S09 重试仅检查风险勾选后直接创建并调度图片任务 | 每个新的图片执行尝试都先展示该次冻结请求，并取得独立的最终确认 |
| GF-02 | 阻断 | 页面展示正／负向提示词；`Generation.prompt` 只保存正向文本 | 展示、确认、持久化和适配器消费同一完整执行请求 |
| GF-03 | 阻断 | 旧 `/confirm` 与 `/generations` 路由仍调用旧服务 | 普通网络入口统一收拢到 v3 受理与最终确认；历史读取保持可用 |
| GF-04 | 高 | 最终确认未绑定操作者／登录上下文，关键校验在创建任务事务之外 | 原子保存最终授权和唯一执行尝试，事务内重验全部依赖 |
| GF-05 | 高 | `recheck_candidate` 接受任意同项目 quarantined generated 资产 | 只审查与原任务有受控派生关系的不可变图片字节 |
| GF-06 | 高 | S12 从历史请求重建规则目录并据此放行 | 使用服务端版本化目录；历史请求只作证据，兼容判定显式失败关闭 |
| GF-07 | 中 | S03 澄清免独立审查；S12 仍保留旧澄清审查路径 | 统一正常与恢复的澄清契约，并校验问题只用于收集阻塞信息 |
| GF-08 | 中 | 软偏好映射到快照但缺少确定性执行覆盖 | 已确认的软偏好须进入提示词；成图只将硬约束作为放行条件 |
| GF-09 | 高 | 发布事务未重验全部图片／清单批准与文件绑定 | 发布提交前在写事务内复核全部授权、资产、字节和当前任务 |
| GF-10 | 中 | 多阶段写入分属不同事务，操作审计与业务提交分离 | 为中间状态提供明确恢复；敏感授权／发布与必要审计一致提交 |

“通过既有测试”不关闭 GF 项。每项须保留反例、修复后结果、受影响旧场景和残余未知。

## 2. 修复顺序

按 GF-03 → GF-01/02/04 → GF-05/06 → GF-07/08 → GF-09/10 串行执行。前一步完成真实入口回归后再进入下一步；不得先做界面替换来掩盖后端旁路。

### 2.1 GF-03：封闭旧写入旁路

1. 枚举所有确认、生图、重试、恢复和发布路由，标明正常入口、只读历史入口及调用服务。完成条件：每个写入口都有唯一归属，无未分类入口。
2. 旧 `/api/projects/{id}/confirm` 和 `/api/projects/{id}/generations` 对已有项目返回稳定的 `LEGACY_FLOW_DISABLED`，不修改项目、不调用模型。新客户端只调用工作流准备与最终确认命令。
3. 历史详情、结果找回和下载保留对象归属、内容批准和当前访问校验；旧 URL 仅做无副作用定位。
4. 将已有 `LEGACY_FLOW_DISABLED` 测试执行到真实路由，并覆盖无参数、伪造批准、同 request ID、未知任务和账号禁用。

完成条件：所有旧写入旁路均不可达，旧内容仍按历史门禁可读，模型与图片调用次数符合明确动作。

### 2.2 GF-01/02/04：统一最终执行授权

**不变量：**准备意图只授权提示词编制和审查；图片执行必须消费一份已展示、已批准、已冻结、获当前用户最终确认的请求。风险确认只授权新准备意图，不替代图片最终确认。

1. 建立版本化 `ExecutionRequest` 与最终授权记录。请求至少包含完整实际 prompt（含负向内容的实际处理方式）、参考资产 ID／实际内容摘要／用途、单图数量、尺寸、格式、适配器／模型和服务配置指纹；不保存密钥。最终授权绑定项目、run、原准备意图、操作者、登录命令上下文、执行请求摘要和稳定命令 ID。
2. 在 S07 独立批准后原子保存执行请求、等待状态和必要审计，再向前端公开。前端展示的字节语义与适配器请求一致；若适配器只有单 prompt，合并在审查和展示之前完成，不能点击后再拼接。
3. 最终确认在一个 `BEGIN IMMEDIATE` 事务中重验账号、操作者、项目／run／意图、登录命令上下文、需求 revision、提示词及批准、参考文件与摘要、输出参数和配置指纹。最终授权、唯一执行尝试及必要审计一起提交，提交后才调度网络调用。
4. 准备和最终确认分别使用规范 UUID 与独立幂等域。同 ID 同参返回原事实，异参冲突；最终确认复用原用量与三类槽位。数据库以唯一约束保证同一意图至多一个图片执行尝试，唯一 request ID 的冲突处理同时校验原参数。
5. 失败、质量拒绝或未知结案后的新任务先创建新准备意图并重新编制／展示；点击确认才执行。修提示词动作在获批后停回等待，不直接调度图片。恢复未最终确认的任务只回等待；已有有效授权的原任务才按提交事实恢复。

完成条件：正常、重试、修文本、S12、进程重启和旧接口都不能在无有效最终授权时创建图片执行尝试或调用供应商；每次图片请求可追溯到用户看到的完整内容。

### 2.3 GF-05：绑定修正图派生关系

1. 将修正图建为独立、不可变执行事实，记录原任务、原资产、修正来源／操作者、实际字节摘要和生成／编辑适配器调用；客户端资产 ID 不是派生证明。
2. 复核只接受当前任务登记的修正版本，拒绝任意项目资产、跨任务资产和已被替换的候选。原任务与原资产保持历史事实，不以改写其绑定冒充新版本。
3. 修正图重新执行完整图片门禁和交付绑定；失败／未知不展示。普通历史读取不能触发修正。

完成条件：无关资产反例被拒绝，原图／修正图及各自批准可追溯，历史记录不被覆盖。

### 2.4 GF-06：恢复沿用服务端规则

1. 持久化规则集版本和目标绑定，恢复时按当前支持的版本取得服务端目录；历史目录仅用于解释旧证据。
2. 当前版本不支持或目录内容不兼容时保持阻断，要求按新契约重新审查。正常和 S12 调用同一裁决函数，不从历史请求接受 blocking、适用性或证据权限变化。
3. 已批准的旧产物按明确的版本兼容规则读取；新授权不继承旧审查。

完成条件：篡改的历史目录不能放行；所有支持版本均有正常／恢复等价测试，不支持版本安全拒绝。

### 2.5 GF-07/08：澄清与约束语义一致

- 澄清只包含为解除 blocking 缺项所需的问题，校验其长度、证据、范围和无副作用；不公开未审建议正文。正常与恢复复用同一校验和状态投影，删除旧恢复分支对“已独立审查澄清”的依赖。
- 执行快照的每个 executable 字段都要在冻结请求中有明确去向。软偏好加入独立、可解释的覆盖检查或结构化编制校验，但 S09 仅把适用硬约束作为成图放行条件。
- 用户锁定／解锁改变强度时形成新需求快照并使旧确认失效。

完成条件：背景、配色、文字布局、参考处理及锁定变化都有“卡片 → 快照 → 实际请求 → 质检”的正反例；一般软偏好 unknown 不否决其他条件均通过的图片。

### 2.6 GF-09/10：原子发布与可恢复写入

1. 发布前读取真实文件并测量摘要；最终写事务内重验当前主体、原任务、Delivery、Asset、图片批准、清单批准、需求／执行快照及文件摘要。任一项失效则不发布。
2. 将发布记录、任务状态、意图交付、槽位释放和必要审计作为同一提交边界；文件系统失败与数据库失败分别验证回退及可恢复状态。
3. 为 S07/S09/S10 每个事务边界定义重启后的唯一合法状态。恢复只消费已持久化事实，不补造缺失批准；候选预算不因恢复重置。
4. 工作流敏感变更与必要审计同事务提交。普通只读操作不写业务审计，模型故障记录不包含秘密或完整私有正文。

完成条件：每个写点注入故障都留下已定义且可恢复的状态；过期、撤销、换图、改摘要、禁用与跨连接竞争均不能发布。

## 3. 回归矩阵

每项测试记录原准备意图、最终授权、图片尝试、用量、槽位、供应商调用和可见资源，避免只断言 HTTP 200。

| 场景 | 必须证明 |
|---|---|
| 正常准备与等待 | 只受理一次；获批后等待；GET／刷新／退出／重启均零图片提交 |
| 最终确认与竞争 | 操作者／登录上下文有效；同参幂等、异参冲突；独立连接最多一个执行尝试，不新增计数 |
| 重试与质量拒绝 | 新准备计一次；新实际请求重新展示并确认；风险勾选本身零图片调用 |
| 修文本与 S12 | 原意图预算不重置；新候选重新独立审查；未最终确认只回等待 |
| 未知与结案 | 只核实原任务；结案不伪称远端取消；新任务仍需完整准备和最终确认 |
| 展示即执行 | 捕获适配器实际请求，逐字段匹配冻结请求，含负向处理、参考内容版本、尺寸与服务指纹 |
| 候选修正 | 跨任务／同项目无关资产拒绝；受控派生图重新质检，原历史不被改写 |
| 发布与访问 | 报告 pass 不替代图片 pass；撤销、过期、错字节和禁用不能发布；历史图仍受当前访问门禁 |
| 旧入口 | 所有旧写接口无副作用拒绝；旧读取／定位不调用模型、不补授权 |

后端相关回归通过后，再验证前端：提示词默认全文、旧按钮失效、发布图片追加原对话且无自动跳转、切号及迟到响应不串数据。真实模型和真实浏览器证据另行记录，不能用桩测试替代。

## 4. 完成定义

1. GF-01—GF-10 每项都有当前基线的失败反例、修复提交、真实接口回归和对应 SRS 验收映射。
2. 路由清单中不存在绕过准备受理、最终确认、独立审查、次数／槽位或发布门禁的写路径。
3. 每个外部图片调用均能关联唯一的冻结请求、有效最终授权和原用量账本；无授权／重复／过期／错上下文调用数均为零。
4. 正常、恢复和历史路径保持目标、规则版本、字节摘要和批准关系可追溯。
5. 失败或未知项保持开放；文档更新、既有测试通过、页面可打开均不单独代表完成。
