## 1. 目标、范围及继承关系

### 1.1 产品目标

用户通过局域网可信 HTTPS 入口登录，在自己的工作区内描述商品与画面要求、核对并授权一次生成、查看通过审核的图片并提出修改。管理员维护账号、额度及后端模型配置，但不因管理员身份获得他人的创作内容读取权。

### 1.2 范围

| 纳入 v3 | 明确不纳入 v3 |
|---|---|
| 邮箱＋密码、管理员建号、一次性设置／重置链接 | 自助注册、邮箱收件权验证、SMTP、手机号、第三方登录、MFA |
| 管理员与普通用户、个人数据隔离、会话撤销 | 企业组织、团队协作、项目共享、公开或免登录分享 |
| 本地服务器上的局域网 HTTPS、多设备浏览器使用 | 公网、穿透、云托管、多节点高可用或互联网暴露 |
| 轻量生成次数与并发控制、统一后端模型密钥 | 用户自带密钥、充值、支付、金额扣费或费用封顶承诺 |
| 一个工作台、三个用户状态、历史版本与反馈 | 批量生图、多 SKU、多尺寸包、精确局部编辑 |
| 有界历史归属迁移、本地备份、脱敏安全审计 | 账号删除、邮箱修改、新增项目删除或批量清理管理界面 |

本地部署不等于离线推理。界面与账号功能不得依赖参考站服务；业务模型调用仍可访问管理员配置的外部服务。

### 1.3 对旧规范的明确覆盖

| 旧约束或冲突 | v3 决定 | 保留部分 |
|---|---|---|
| v1/v2 的本机单用户、账号排除项 | 改为局域网、多账号个人工作区 | 单商品、单次单图及原有业务范围 |
| 旧阶段页面、桌面沟通／结果双列、卡片工作流、共壳成果 Body 与自动成果跳转 | 重建唯一聊天主体，提示词全文后最终确认，图片内联追加；全部修改回唯一原输入框，旧 URL 仅只读定位 | U1／U2／U3、历史快照与内容门禁保留；读取和历史定位不能隐式生成 |
| v2 的一种方形输出尺寸 | 继承 4K 修订的单一配置尺寸，见第 12 节 | 一次只生成一张；历史尺寸快照不静默改写 |
| 原来的项目关联／内容放行 | 在其前面增加账号鉴权与所有权校验 | G00—G08、批准、撤销、过期与隔离继续有效 |
| 旧 `approved_by=user` 等逻辑标识 | 用户动作另绑定真实账号 ID 与授权事件 | 模型职责标识不转化为账号权限 |
| 额外建议参与否决、按创意／光影字段自动推导硬项 | 按第 9.2 节区分服务端必审规则与软偏好 | 事实、安全、权限、明确硬项未知时仍不放行 |
| 编制覆盖错误直接等同用户需求变化 | 原快照未变的可修复文本错误按原意图有界处理 | 实质需求变化重新确认；技术故障及图片提交不自动重试 |

v2 的独立识图／需求审查、用户需求确认事实、成图质检、原子发布、技术故障不自动重试与重启不自动调用模型继续有效。最终需求卡不再作为复杂可见配置面板；需求齐备后的准备受理仅授权编制／审查，真实提示词获批并展示后还须独立的最终图片确认。旧“需求确认后自动编制并生图”顺序不再适用。

## 2. 术语与信任边界

### 2.1 术语

| 术语 | 本文含义 |
|---|---|
| 账号角色 | `admin` 或 `user`，表示应用管理权限；不是 TEXT/VISION 等模型职责 |
| 用户状态 | 第 8 节的三个创作交互状态；不是账号启用状态或后端阶段枚举 |
| 所有者 | 业务项目唯一归属的稳定账号 ID，不是可编辑邮箱、客户端传入 ID 或审批角色字符串 |
| 会话 | 服务端可撤销的登录状态，与对话记录、工作流运行及浏览器待提交记录分开 |
| 一次性链接 | 绑定一个账号及用途的设置／重置密码凭证，不是完整登录会话或资源分享链接 |
| 准备授权 | 明确创作／修改动作授权原意图在预算内编制和审查提示词，不授权图片提交 |
| 生成授权 | 用户核对完整已批准实际提示词后，对当前执行快照的单次明确图片授权；与准备受理和长期需求确认记录分开 |
| 已受理任务 | 第 9、10 节规定的事务提交完成并获得稳定任务 ID 的一次生成意图 |
| 归属隔离／内容隔离 | 前者阻断未分配给账号的数据，后者阻断未获内容批准的产物；解除一个不解除另一个 |

v2 的 revision、artifact、approval、policy version、quarantine 等术语继续有效，不把所有状态压成 `succeeded`。

### 2.2 安全目标与不承诺项

| 主体或边界 | 必须实现的保护 | 不作出的承诺 |
|---|---|---|
| 未登录局域网访问者 | 不能读取业务数据、管理账号或消耗模型额度 | 局域网天然可信、隐藏入口即安全 |
| 已登录普通账号 | 不能读写其他人的数据，不能提升权限或绕过额度／内容门禁 | 仅靠 UUID 难猜或前端过滤实现隔离 |
| 应用管理员 | 管理能力最小化、敏感操作审计，无直接代登功能 | 能阻止拥有重置链接的恶意管理员间接接管账号 |
| 服务器维护者／操作系统管理员 | 限制目录与凭据访问，提供受控初始化和恢复 | 端到端加密、零知识、数据库／内存对主机管理员不可读 |
| 模型服务商 | 仅发送必要业务输入，明确服务商标识、用途与数据类别 | 我方单方面保证服务商不保留、不训练或永不泄露 |
| 用户下载后的文件 | 应用内访问仍鉴权，下载动作归属正确 | 下载到应用外后仍由应用权限持续保护 |

应用管理员是受信任的账号恢复方。模型服务配置、主机磁盘、备份及证书私钥由受信任维护者管理；本文不把“管理员默认没有内容查看接口”描述为对维护者的密码学隔离。

## 3. 局域网部署与网络边界

- **V3-NET-01 受控入口。** 正式模式只通过可信 HTTPS 的同一应用源提供页面、API 和私有资源。局域网监听地址、允许的主机名／地址及防火墙范围必须显式配置；不得自动开启公网映射或穿透。后端、数据库、数据目录与备份目录不直接发布到局域网。
- **V3-NET-02 证书与开发隔离。** 提供本地证书信任、更新及失效排障指引，浏览器无需绕过安全警告。纯 HTTP 例外只用于明确启用、只绑定回环地址的开发环境；不能用该开关在局域网运行正式账号服务，也不能全局关闭 TLS 校验。
- **V3-NET-03 来源与最小暴露。** 校验允许的 Host／Origin，限制 CORS；带凭据请求不使用通配来源。只信任明确配置代理传递的转发头，客户端自报 IP 不决定限流或权限。允许匿名读取的仅为公共页面、无敏感内容的构建资源及必要最小健康状态；其余按第 7 节默认拒绝。数据库不可用或鉴权配置失效时，业务接口安全关闭，不退回无登录模式。

## 4. 账号建立、恢复与密码

### 4.1 账号生命周期

- **V3-ACC-01 首次初始化。** 首个管理员只能经服务器本机维护命令建立；邮箱由维护者指定，密码经不回显的交互输入设置，不从默认值、命令参数或日志取得。初始化并发执行也只能成功一次；已有管理员时拒绝再次初始化。未初始化时网页只提示联系维护者，不提供远程建管理员入口。
- **V3-ACC-02 管理功能。** 管理员可以列出账号的必要标识／状态、创建普通用户、禁用／恢复普通用户、签发一次性链接及配置额度。普通用户不能调用这些能力。首版不要求管理员晋升界面，也不提供自助改角色、账号删除、邮箱修改或直接代登接口。管理员作为创作者仅访问自己的业务工作区。
- **V3-ACC-03 身份与状态。** 使用不可变账号 ID。邮箱去除首尾空白后按大小写不敏感的唯一登录标识处理，创建与登录使用同一规则；不验证邮箱收件权、不把它当实名或第二认证因素。区分待设置密码、可登录、已禁用；只有完成有效密码设置且未禁用的账号才能登录。禁用立即阻断新请求并撤销会话及未使用设置／重置凭证；恢复不复活旧会话或凭证，也不让待设置账号跳过激活。
- **V3-ACC-04 用户改密与恢复。** 登录后改密须校验当前密码。忘记密码页面只说明联系管理员，不伪装发送邮件。管理员为普通用户签发一次性链接，经线下渠道核实本人后交付；用户自己设置最终密码。管理员密码遗失经服务器本机受控维护命令恢复，完成后撤销其全部会话及凭证，记录恢复事件。维护能力不暴露为匿名或普通用户网络接口。

### 4.2 一次性链接

- **V3-ACC-05 凭证约束。** 凭证使用密码学安全随机源，随机强度见第 12 节；服务端仅存校验摘要，绑定账号、用途、创建／过期／使用／撤销时间。有效期见第 12 节，签发新链接使同账号旧链接失效。完整凭证只在签发时向已认证的授权管理员显示一次；不得通过列表、日志或之后查询取回，也不能访问项目、图片或管理员接口。具体安全细化参考 S4，线下交付方式是本产品选择，不照搬其邮件流程。
- **V3-ACC-06 使用与泄漏防护。** 链接来自配置的可信应用地址，不从任意 Host 头拼接；链接页不加载第三方脚本、遥测或远程装饰资源，设置 `Referrer-Policy: no-referrer` 并避免在日志、历史跳转和错误中保留凭证。只打开链接不消费凭证、不改密码；有效 POST 提交时原子完成密码更新、凭证消费及会话撤销，重复、过期、错用途或禁用账号均拒绝。仅签发重置链接不修改已有密码；成功设置／重置后回到正常登录流程，不自动生成已登录会话。

### 4.3 密码与认证防护

以下为已确认“密码安全存储、登录防滥用”的技术验收细化，不增加外部身份服务或合规认证承诺。

- **V3-PWD-01 密码策略。** 密码按单因素方式保护，长度策略见第 12 节；接受空格、Unicode、粘贴、自动填充及密码管理器，不静默截断或去除密码空白。若采用 Unicode 规范化，设置和验证必须一致并有用例。拒绝本地弱口令列表中的常见密码；不向外部服务发送待验证密码。不额外强制大小写／数字／符号组合或无风险依据的定期改密。参考 S6。
- **V3-PWD-02 密码存储。** 使用维护中的密码库执行 Argon2id，参数下限见第 12 节，独立随机盐及算法／参数元信息随哈希保存。不得使用明文、可逆加密、普通快速摘要或固定盐代替密码哈希；库缺失时安全失败，不能降级。调整成本应有目标设备测量与测试，不能悄悄降低下限。参考 S1。
- **V3-PWD-03 防猜测与枚举。** 登录、链接签发及凭证验证分别有后端限流、请求体大小和计算资源上限；登录同时约束账号标识与可信来源，跨客户端／并发请求仍生效。达到配置阈值返回受限结果及可重试指引，不永久锁死账号。错误密码、未知账号、禁用及未激活账号使用相同对外失败信息，避免明显短路时序泄露；内部原因仅记脱敏审计。未知账号路径不得绕过相当的密码验证成本。技术设计须固定默认阈值与限流存储策略，测试不能只验证按钮防抖。

## 5. 登录会话与浏览器隔离

- **V3-SES-01 服务端会话。** 使用高熵、不透明、可撤销的服务端会话；随机强度见第 12 节，服务端保存校验摘要和账号、创建、活动、到期、撤销元信息。正式 Cookie 使用 `Secure`、`HttpOnly`、`SameSite=Strict`、`Path=/`，不设置跨子域 Domain，采用兼容这些约束的 `__Host-` 名称。登录后换发新标识，防止固定会话；不把登录令牌、密码或密钥放入 URL、localStorage、sessionStorage、前端包或可读 Cookie。参考 S2。
- **V3-SES-02 时限。** 空闲与绝对时限见第 12 节，由服务端时间强制执行，过期后拒绝原会话，活动请求不能复活过期状态。有效的用户主动操作可续空闲时限，绝不续绝对时限；轮询、任务进度、自动刷新与保持连接不算活动。若用输入活动通知，须限频并使用服务端收到时间，不能相信客户端时间戳。不提供“记住我”长期登录。
- **V3-SES-03 多端与撤销。** 同账号可有多个设备会话；个人账号页展示自己会话的必要客户端信息和活动时间，支持撤销指定／其他会话，不返回会话凭证。普通退出撤销当前会话；成功改密、成功重置及禁用按第 4 节撤销全部会话。其他会话下一次请求即被拒绝，不能仅等待浏览器 Cookie 自行消失。客户端信息是提示，不宣称准确识别物理设备。
- **V3-SES-04 请求安全。** 所有改变状态的操作，包括登录、退出、密码设置／重置、账号管理、上传、确认、生成及额度调整，都要有与当前上下文匹配的 CSRF 防护和来源验证；GET 不承担这些变更。SameSite、局域网地址或仅检查 Referer 都不能单独代替该控制。对返回地址做同源白名单校验，不接受任意外部跳转。参考 S5。
- **V3-SES-05 退出与迟到响应。** 会话失效立即隐藏业务操作并引导登录；已保存需求／任务仍归原账号，重新登录只查询，不自动重发请求。显式退出、账号切换或其他标签页身份改变时清理业务界面、查询缓存、临时图片 URL 和未发送内容；迟到响应必须匹配当前账号及项目上下文，不能回填到新账号。浏览器历史返回须重新验证身份，私有响应使用 `Cache-Control: no-store`，不得进入共享缓存或离线缓存。旧的未按账号隔离的恢复元数据不能给任意新账号自动恢复。

## 6. 系统防护与敏感信息

- **V3-SEC-01 后端强制。** 所有受保护操作由后端取得当前有效主体，再做角色、对象归属及操作门禁；不相信客户端传入的 `user_id`、`owner_id`、角色、批准标志或额度。批量字段赋值使用允许列表，数据库查询／命令使用参数化方式，文件访问在核验的数据根目录内按受控对象解析。用户输入、文件名、模型返回和远端定位信息不能成为任意文件／网络访问入口。
- **V3-SEC-02 不可信内容。** 用户文字、OCR、模型输出与错误按数据处理；页面使用安全文本／严格过滤渲染，不执行其中的脚本或任意 HTML。生产 CSP 至少约束脚本来源、嵌入、表单目标和基础地址，并验证不存在放开任意内联执行的宽泛例外。上传类型、大小、解码、防解压炸弹及模型提示注入边界继承 v2，不因登录而放宽。
- **V3-SEC-03 密钥与错误。** 模型密钥只留后端受限配置，不进入业务数据库、账号表、日志、提示词、前端、文件名或下载包；TLS 私钥及备份同样受文件权限保护。普通用户只读模型可用性及必要服务商说明，不能获取密钥、完整配置地址或内部堆栈。管理员也不通过诊断接口读回明文密钥；管理后端配置不要求新增网页密钥编辑器。公共错误收敛为安全信息和关联 ID，内部脱敏记录保留排障能力。

这些要求提供可验证的应用安全基线，不等同于法律合规认证、渗透测试通过或对全部攻击面的保证。

### 7.2 对象级规则

- **V3-ACL-01 唯一归属。** 每个可服务项目有一个稳定所有者，子对象通过已核验的项目关系继承归属。消息、参考文件、生成记录、workflow run、role call、artifact、review、approval、delivery、legacy item、恢复记录及含业务内容的诊断均在该边界内。不能因某子表没有 `user_id` 就跳过校验，也不强制每个子表重复存所有者字段。
- **V3-ACL-02 全出口覆盖。** 列表、分页总数、搜索、详情、历史、缓存、错误摘要、轮询／事件流、缩略图、下载及将来新增接口均默认拒绝，按主体过滤后再返回。前端构建资源与业务私有图片目录分开，禁止以静态目录、源文件 URL、供应商 locator、缩略图替代路径绕开校验。参考 S3。
- **V3-ACL-03 状态与响应。** 无有效会话的业务请求返回未认证结果；已认证但非管理员的管理操作返回拒绝。非本人对象和不存在对象对外统一为不可获得，不能泄露其存在、文件名、版本数或审批内容；本人对象未获内容放行时按 v2 的安全状态返回，不能把它误判为他人对象。管理员无通用“跳过归属”分支。
- **V3-ACL-04 交叉校验。** 创建、引用、下载、找回及后台任务同时校验账号与所有关联对象的项目一致性，不能把 A 的参考图、生成 ID、幂等请求或批准记录拼到 B 的项目。确认、审批、生成意图中记录实际操作者账号及不可变关联事件；保留业务审查角色，不由模型签发账号授权。共享内容缓存只能在内容与权限均验证后命中，不能跨所有者复用私有正文。
- **V3-ACL-05 长任务边界。** 后台任务携带服务端持久化的所有者、授权及版本，不能依赖“当前浏览器账号”。退出、浏览器关闭或会话过期不撤销已经明确授予该任务的授权；任务可按既有预算继续，但结果始终只归原所有者。账号禁用后禁止新增模型调用和发布；已经发给远端的请求不宣称取消成功，已返回内容仅安全保存／隔离。恢复账号后由用户核实或手动恢复，不自动重生、重发或批量审查。

## 8. 前端：一个工作台，三个用户状态

### 8.1 登录与账号页面

- **V3-UX-01 视觉参考。** 参考 `https://x.ailzd.com/login` 于本次讨论时观察到的浅灰青背景、克制几何装饰、左侧品牌说明、右侧登录卡片和黑色主按钮。品牌采用“电商生图工作台”，文案围绕商品创作，不复制参考站名称、Logo、营销指标、模型广场、号池或充值业务。装饰通过本地资源或界面代码实现，不依赖参考站脚本、字体或图片服务，不以动画阻碍输入；尊重减少动态效果偏好。
- **V3-UX-02 认证交互。** 提供邮箱、密码、显示／隐藏密码、提交中／失败／受限状态，以及联系管理员的密码恢复指引；不展示虚假的注册或邮件找回入口。输入有可见标签、键盘焦点和关联错误，支持密码管理器及相应 autocomplete。一次性链接无效／过期时仅展示安全指引，不泄露其他账号信息。个人账号区提供改密、本人会话和安全记录的必要视图；管理区按第 7 节展示建号、状态、链接签发及额度功能。

### 8.2 三状态与后台阶段的映射

| 用户状态 | 进入／完成条件 | 当前操作与呈现 |
|---|---|---|
| U1 描述与完善 | 新会话、实质修改或仍有阻塞信息；需求整理与各独立审查继续有效 | 在唯一底部输入框发送图文、补充、说明用途；问候、解释和暂缓不创建需求版本或准备意图 |
| U2 准备、待确认与执行 | 明确创作／修改受理后准备真实提示词；独立批准后持久化等待；最终确认后才可提交图片 | 提示词默认全文展开、可复制，紧随“确认使用以上提示词生成”；执行时一条轻量状态及后端允许的恢复动作 |
| U3 查看与调整 | 当前需求对应的图片已发布且可访问 | 新的助手图片消息追加在原对话，可放大和下载；实质修改在原输入框发送后回 U1 |

- **V3-UX-03 纯对话创作。** 创作外壳重建为浅灰紫背景、圆角白色侧栏与主面板；侧栏直接展示新建、搜索与本人完整会话列表，主区仅有当前对话标题、唯一消息流和底部图文输入。移除需求表单、参考用途下拉、复杂确认卡、工作流／任务面板、阶段导航和独立成果切换；不能把旧工作台缩小、隐藏或搬进气泡。新会话只显示简短欢迎与原输入框，首次明确发送才创建创作记录。发布后图片留在原对话，不自动跳页。必要账号、本人用量与数据使用说明保留为轻量入口，登录和管理页面本轮不重做。
- **V3-UX-04 连续版本与历史。** 一条会话包含需求、参考图、澄清、真实提示词、图片和修改历史，每次出图不另建会话。每张图绑定本轮需求、实际执行提示词和交付版本，旧图保留在原消息位置。回看、放大、下载历史不改需求或修改基准、不调用模型、不暗建分叉；默认延续当前最新方案。参考用途、需求及提示词修改均在唯一原输入框表达，不设编辑器、反馈输入或第二套表单。实质变化才创建新需求版本并重新准备、展示和最终确认；“好的”“继续”和查看提示词不授权生图。
- **V3-UX-05 可用与私密。** 消息独立滚动，固定输入不遮挡正文；Enter 发送、Shift+Enter 换行，中文选字不发送，上滚阅读不强制拉底。320／768／1440 CSS 像素可用，窄屏为同一侧栏的单层抽屉，软键盘、焦点、附件和放大关闭可达。执行中可写草稿但不提交新请求、不暗排队。草稿及附件准备态仅在页内、按账号／登录生命周期／项目隔离；退出、切号和跨标签失效清理，晚到响应不得写入新上下文。不新增本地业务数据库或跨设备草稿同步。
- **V3-UX-06 会话与图文输入。** 新建／搜索／切换／重命名作用于本人真实项目；搜索覆盖服务端所有本人标题，所有者过滤先于分页，重命名仅改元数据。文件选择、粘贴、拖入均在原输入区，发送前可预览／替换／移除，发送后附件属于对应用户消息。参考用途通过对话说明，不明确时追问，引用绑定稳定图片标识和版本。服务端当前单参考图能力与消息附件关系需按确认契约核验，前端不得伪装支持多附件。旧阶段／成果 URL 仅定位相应会话或真实历史结果，不恢复独立成果工作流、不调用模型。

## 9. 单次确认与生成授权

### 9.1 授权与交付边界

- **V3-GEN-01 准备与最终确认分离。** 明确创作／修改且需求齐备、最终需求获独立批准后，后端校验有效账号、本人项目、revision／需求摘要、参考依赖、输出配置、额度及槽位，原子受理提示词准备。一个逻辑意图只计一次。准备授权仅允许预算内编制与审查，不授权图片提交；已批准真实提示词全文展示后，用户必须明确点击“确认使用以上提示词生成”，同意图下持久化最终授权才可生图。普通交流、查看、刷新、重新进入和“继续”均不能替代最终确认。
- **V3-GEN-02 展示即执行。** 服务端将待确认快照及最终授权绑定到操作者、所属项目、意图、需求版本／摘要、提示词版本／摘要、批准、实际参考依赖与输出参数。正文是实际传给生图模型的完整提示词；实际请求含负向提示词时一并展示。S07 独立批准后持久化等待，S08 不得自动穿透。点击后只消费被确认的不可变请求，不重新编写或切换提示词。修改、批准失效、依赖变化或上下文不匹配后，旧确认在服务端失效，新提示词重新展示与确认；不把未批准候选或内部系统／审核自由文本公开。
- **V3-GEN-03 幂等与恢复。** 准备与最终确认分别具稳定幂等标识，同标识异参拒绝；最终确认复用原意图、计数和占用，不重复受理或提交。未最终确认的等待经刷新、退出、重新登录与进程重启保持，不自动生图。已提交或事实未知时核实原任务，不因超时、文本修复、旧接口或恢复动作创建第二次提交。故障保留真实状态与原快照，技术重试为零；文字候选修复仍受 V3-GATE-04 的原意图、预算和重新展示规则限制。
- **V3-GEN-04 读取与交付。** 页面加载、历史、轮询、旧 URL 兼容定位、放大和下载只读，不编制提示词、不补授权、不触发图片调用。原受理任务的合法执行另行归因。仅实际发布且访问门禁通过的图片可作为助手消息追加；供应商成功、文件落盘或报告通过不等于发布。撤销、过期、缺失与失败真实呈现，不用私图缓存或其他版本兜底。每轮仍为第 12 节的一张图及单一尺寸，反馈不覆盖旧图，不新增局部画布编辑或历史分叉。

技术细化见[确认契约](../../docs/architecture/prompt-confirmation-v3.md)，不把逻辑状态名视为已存在的接口或数据库字段。

### 9.2 门禁与工作流修订

本节承接审计提出的修订，不以降低统一阈值替代风险分层。规则判定、快照、恢复与实施顺序见[门禁与工作流 v3](../../docs/architecture/workflow-gates-v3.md)；界面投影见[前端设计第 3.3 节](../../docs/architecture/frontend-design-v3.md#33-等待失败与恢复)。

- **V3-GATE-01 服务端裁决。** 规则目录、适用性、阻断／建议属性及允许证据由服务端确定。适用必审项只有合法证据支持的 pass 才放行；模型不能用 not_applicable 自行免审。合法建议的 fail／unknown 不否决已满足的必审项；安全发现、非法证据和未知协议不能借建议标签被忽略。
- **V3-GATE-02 约束分层。** 商品身份、准确文字、数量、参考用途、输出参数及用户明确必须／禁止项保持硬约束；一般审美与模型创意为软偏好，只有用户明确锁定才升级。强度随卡片展示、确认和版本绑定；确认卡片不隐含将全部建议变硬。软偏好差异单独反馈，不抵消硬失败，也不因其未知自动阻断成图。
- **V3-GATE-03 完整快照。** 获批的商品、创意与完整视觉决策有可追溯执行去向，覆盖背景、配色、文字布局和参考处理，不依赖重复填字段。用户看到的卡片、授权、提示词与质检绑定同一不可变快照；历史版本保持原语义，升级不改写旧批准。
- **V3-GATE-04 原意图修复。** 类型化区分可修复文本错误、实质需求变化、内容拒绝、证据不足、协议错误、技术故障与远端未知。原快照和授权有效、可证明尚未提交生图时，格式或非危险编制偏差可按第 12 节预算修复并重新审查，不强迫用户修改未变需求，不新增生成次数。真实新内容或硬项变化回 U1；技术故障自动重试为零，图片已提交或受理未知时不得借修文本重发。多句覆盖不因标点误拦，准确文案、数量、否定及语义仍须正确。
- **V3-GATE-05 安全呈现。** 服务端提供安全原因类别及实际可用动作；原对话的一条轻量状态区分补信息、修编制、等待提示词最终确认、内容未放行、故障与待核实，不恢复工作流面板。未批准建议／报告不作为解释泄露；只有真实需求修改才经原输入框创建新版本，图片内联，历史定位、导航与刷新不触发模型调用。
- **V3-GATE-06 审查职责。** 正常与恢复路径使用同一裁决和批准绑定。报告批准不替代图片批准，最终需求、执行提示词、交付和访问门禁继续有效。减少逐角色审查是后续评估项，须明确替代校验、证据与批准后实施；本次不授权删除既有独立审查或无界重试。

## 10. 用户额度与并发

- **V3-LIM-01 规则。** 默认次数窗口、个人活跃上限和实例并发上限见第 12 节；管理员可配置有效正整数，普通用户不能修改。个人视图提供本人的用量／限制与拒绝原因。管理员自己的创作任务同样受限；降低限额不抹去已用记录、不自动取消已受理任务，新提交按新限额检查。不提供余额、充值或金额承诺；此限制不是全部 TEXT/VISION 调用成本上限。
- **V3-LIM-02 受理与计数。** 后端在提示词准备开始前的同一事务中检查账号状态、归属、幂等、额度和槽位，创建稳定意图并计一次、占用原三类槽位后才算受理；不是改为按最终点击或出图成功计数。提示词等待和同一快照的最终确认不再计数／占槽。预校验或事务失败不计、不占；受理后准备失败、未最终确认而明确放弃、图片失败、未知或审查失败仍保留一次。等待保留占用，只有可证未提交的明确放弃或真实终态才释放；超时不自动释放或生成。同任务文字修复、恢复、只读核实、找回和幂等重放不另计；实质变更新需求后的新受理或明确风险新任务按新意图计一次。超过限制在模型调用前拒绝，不排队或自动重交。第 12 节的次数口径与参数不变，改变它们须另行确认。
- **V3-LIM-03 一致性与未知状态。** 受理账本、活跃槽位与恢复状态持久化，并发请求、重启及计时窗口切换不能穿透限制或清零用量；单项目活跃限制继续继承 v2。结果未知不能仅凭超时自动当作“未受理”并再次生图；其核实／人工结案遵循 v2，人工结束本地跟踪不宣称取消远端任务。并发上限约束本实例编排的活跃任务，不保证供应商内部任务数量或费用。

## 11. 历史数据、审计与本地恢复

### 11.1 归属迁移与保留

- **V3-DATA-01 先备份、再认领。** 实施前识别实际生效的数据根目录、数据库及文件集合，不能因包内目录为空就忽略仓库兼容布局里的旧数据；有多个不一致来源时停止并要求维护者选择来源，不静默合并或挑一个覆盖。制作并验证完整备份后，由初始化管理员明确确认接收指定旧数据。未认领项目保持归属隔离，任何普通网络接口均不得返回正文或资产；新账号从空工作区开始。迁移可重复执行而不重复归属、丢失记录或篡改历史快照，失败有明确回滚／保持隔离结果。
- **V3-DATA-02 双重门禁与生命周期。** 认领只确定所有者，不自动批准 `legacy_unreviewed` 文字／图像，不伪造历史操作者或补写内容批准；历史确认不能替代当前账号的新生成授权。业务记录、已发布图、参考依赖及审批证据随版本保存，原有失败图片和普通诊断清理按第 12 节及 v2 第 7.2 节执行。所有清理在核验的数据目录内进行，不能误删历史依赖或把归属未定的旧资产当作新失败图销毁。首版不新增项目删除或批量清理界面。
- **V3-DATA-03 最小持久化。** 保存账号、密码哈希、会话校验元信息、一次性凭证校验元信息、所有者关联、实际操作者、生成受理账本、恢复状态和安全审计；凭证原文不落库。角色候选、批准和模型原始响应的保留继续遵循 v2，只留必要结构／摘要，不无限保留无效原始输出。业务记录不能被混入普通日志后获得更宽访问权限。

### 11.2 安全审计

- **V3-AUD-01 事件。** 记录登录成功／失败／受限、退出／撤销、设置／重置／改密、建号、禁用／恢复、额度变化、权限拒绝、旧数据认领及本机维护／恢复事件。至少有服务端时间、事件类型、操作者／目标的必要稳定标识、结果、安全原因代码及关联 ID；适用时记录可信来源与管理员变更前后值。未知账号使用脱敏标识，不把用户输入的密码当作诊断字段。
- **V3-AUD-02 访问与完整性。** 普通用户仅查看本人必要安全事件，不能查询别人的账号或管理操作正文；管理员可查看必要管理／安全审计，但不借日志读取他人对话、图片、密钥、完整 Cookie、密码、一次性链接、完整图片 Base64 或未过滤供应商错误。敏感管理变更与其审计记录一致提交，审计写入失败不能静默完成未记录的敏感操作；网页不提供修改、删除或清空审计功能。保留期见第 12 节，记录用 UTC 时间并在界面按适当时区显示。

### 11.3 备份、恢复与运维

- **V3-OPS-01 一致性备份。** 受信任维护者配置受限备份目录，建议另一块磁盘。服务运行时按第 12 节频率制作可恢复的一致快照，停机后启动检查补做；数据库采用包括相关 WAL 状态的一致性方式，文件及清单与对应数据库快照一致，不能只复制一个正在写入的主数据库文件。覆盖账号／归属、项目、图片依赖、审批、额度及恢复记录，并有摘要和完整性清单。只在新备份验证成功后轮换旧备份；失败保留上次可用副本并向维护者报告。备份不通过网页下载，也不包含模型密钥或 TLS 私钥。
- **V3-OPS-02 受控恢复。** 恢复须进入维护状态、停止业务写入、验证备份并保留回退点，错误备份不能覆盖当前可用数据。重新开放前核验所有者／文件／审批关联，撤销全部恢复出来的会话及一次性凭证，按原时间执行到期规则，不复活过期访问。后台意图、原提交及计数恢复后不自动重发或调用模型；快照之后受理记录有缺口时保守阻断新生图，直到窗口结束或维护者有审计地核实，不能假装额度未使用。恢复所需配置秘密由维护者另行准备，不从普通业务备份读回。
- **V3-OPS-03 部署说明与边界。** 提供可验证的本地启动、局域网地址／防火墙、证书信任与更新、管理员初始化／恢复、数据根目录选择、备份／恢复及故障说明。正式服务采用最小必要系统权限。主机断电、磁盘丢失、服务关闭期间的可用性不作保证；同盘备份不防磁盘损坏。活动数据到期规则不承诺物理安全擦除，已有备份中的旧快照随备份轮换到期。数据权限、审计或迁移无法可靠核验时停止相应能力，不能开放匿名兼容通道。

## 15. 安全细化的原始参考

以下官方原始资料于 2026-10-31 查阅。它们支持密码、会话与授权的技术细化，不替代本次产品决定；管理员线下交付、时限、额度和部署范围以本文为准。后续资料变化需要评估，不自动改写已确认范围。本产品不因此宣称符合 NIST 的完整身份保证级别或通过 OWASP 认证。

- **S1** OWASP [Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)：密码哈希、独立盐、Argon2id 成本。
- **S2** OWASP [Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)：TLS、Cookie 属性、固定会话、服务端过期和撤销。
- **S3** OWASP [Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)：默认拒绝、逐请求校验、对象与静态资源权限。
- **S4** OWASP [Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)：随机、限时、单次凭证，可信链接源与正常重新登录。
- **S5** OWASP [Cross-Site Request Forgery Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)：CSRF 控制与来源校验，SameSite 只是纵深控制。
- **S6** NIST [SP 800-63B-4，Password Verifiers](https://pages.nist.gov/800-63-4/sp800-63b.html#passwordver)：单因素口令长度、长口令支持、弱口令检查与非强制组合规则。

本文是已确认需求及其可验收安全细化；新增功能、改变管理员信任边界、扩大网络暴露或降低安全控制时，须先提出具体差异并获得明确确认。
