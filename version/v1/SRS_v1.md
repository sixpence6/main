# 电商生图智能体 SRS v1

状态：产品范围与技术方向已确认；模型服务商与接口协议待确定。  
日期：2026-10-28  
使用者：产品发起人本人。  
读者：实现本产品的开发者与编码智能体。

## 1. 目标与决策依据

用户用自然语言描述想要的电商图片，可选上传一张参考图；LLM 将描述整理为可确认的生图需求，再调用用户自行配置的视觉生图 API，返回一张可预览、可下载的图片。用户可以补充反馈，重新生成。

本版只验证一条闭环：**配置模型 → 描述需求 → 确认需求 → 生成图片 → 反馈重生或下载**。

### 1.1 已确认的用户要求

- 主要供本人使用，优先满足自用。
- 自然语言是完整可用的输入方式，上传图片可选。
- 使用两类模型：LLM 与用户所称的 VLLM／视觉模型，分别接入自己的 API Key。
- 产出最小可用 v1 的需求文档，核心功能控制在 3–5 个。

原始《电商生图智能体-场景与痛点说明.md》用于理解场景与痛点，其中的多智能体角色、平台覆盖和功能优先级属于候选建议。此次范围以用户后续要求和本文为准。

### 1.2 技术澄清后确认的范围与实现默认值

| 项目 | v1 决策 |
|---|---|
| 使用形态 | 本机运行的单用户 Web 应用，服务仅监听本机地址 |
| 技术方向 | Vue + FastAPI 前后端分离开发；具体技术与接口约定见《TECH_DESIGN_v1.md》 |
| 模型配置 | 两组配置分别从后端本机 `.env` 读取；网页只显示配置状态，不能修改 Key |
| 图片用途 | 通过描述指定主图、场景图或促销图；共用一条生成流程 |
| 单次任务 | 一个商品、一份当前需求、一个生成请求、单张结果 |
| 尺寸 | 首版固定为所选生图模型支持的一种方形尺寸；接入时填写精确像素并在生成前显示 |
| 图片输入 | 0 或 1 张 PNG/JPEG，单文件不超过 10 MB；界面同时显示供应商的更严格限制 |
| 结果修改 | 根据反馈更新完整提示词，再生成一张图片；上传的原始参考图继续使用 |
| 历史范围 | SQLite 保存需求、对话、任务及版本记录，图片保存到本机目录；刷新后恢复，重启后可查看已有记录 |
| 生图执行 | 后端后台任务执行；前端约每 2 秒查询状态；后端重启后未完成任务标为“结果未确认”，不自动重跑 |
| LLM 回复 | 完整返回问题或需求卡，等待时显示加载状态 |
| 日常启动 | 开发时分别启动前后端；日常由 FastAPI 提供构建后的 Vue 网页和 API |
| 调用方式 | 用户明确点击生成后才调用生图 API；每次点击最多提交一个生图请求 |

使用形态、技术方向、配置方式、持久化、后台任务、重启行为、LLM 回复方式及日常启动方式已由用户确认。单张输出、默认方形尺寸与文件限制沿用首版方案；具体供应商约束在接入时核实。

## 2. 模型职责与接入前提

本文用 `VISUAL` 指代用户所说的视觉模型服务。它必须具备图片生成能力；“视觉模型”这一名称本身不能证明它能够生图。

| 模型角色 | 输入 | 输出 | 职责 |
|---|---|---|---|
| LLM | 用户文字、当前需求卡、修改意见 | 澄清问题、结构化需求、完整生图提示词 | 理解与整理需求 |
| VISUAL | 生图提示词、可选参考图、固定尺寸 | 可获取的生成图片 | 文生图；存在参考图时生成参考图引导的图片 |

- 两套配置相互独立，分别包含服务地址、模型标识和 API Key；允许来自同一或不同服务商。
- 首版各适配一种确定的接口协议。可配置服务地址不代表兼容任意供应商。
- 当前供应商未定，先预留每类模型的 `API_KEY`、`BASE_URL`、`MODEL` 和适配接口；未配置时可使用界面与查看历史，对应模型操作提示未配置，不返回模拟成图。
- 为完整验收可选图片输入，所选 VISUAL 接口须同时支持纯文字生成和参考图输入。
- 视觉服务只有图片理解能力时，配置检查应指出缺少生图能力，不能将图片描述文本视作成功结果。
- LLM 可以是纯文本模型。本版不要求它自动识别参考图，图片直接传给 VISUAL；用户通过文字说明图中商品及预期效果。
- 有参考图时以它作为视觉依据；只有文字时按描述创作。两种方式均由用户判断是否符合真实商品，不宣称自动保证实物一致或平台过审。

## 3. 必须跑通的五个核心功能

### F1. 独立配置两个模型服务

**输入：** LLM 与 VISUAL 各自的服务地址、模型标识、API Key。

**行为：**

1. 用户在后端本机 `.env` 中分别填写两组配置，修改后重启服务生效。
2. 网页只显示每类模型是否配置、所选模型与可用能力；浏览器及配置查询接口均不返回 API Key，网页没有修改 Key 的入口或 API。
3. 启动时检查配置字段与适配器声明的能力；实际认证与连通性由真实调用验证。配置完整与调用成功分别显示；空配置不妨碍应用启动和历史查看。
4. 请求从本机后端发往相应服务，日志、需求卡、图片文件名及下载内容均不包含 API Key。

**完成标准：** 两个角色分别读取各自后端配置完成真实调用；网页不能读取或修改 Key。任一角色缺少配置时，对应操作给出明确补充提示，并保留已输入的需求。

### F2. 用对话整理并确认生图需求

**输入：** 非空自然语言描述，例如“帮我做一张陶瓷杯主图，暖色厨房背景，突出杯子的质感”。

**行为：**

1. 用户无需写专业提示词，即可发起需求整理。
2. LLM 提取商品、用途、风格、画面要求、需呈现的文字，生成一份可编辑需求卡和完整生图提示词。
3. 商品主体或用户明确提到的价格、活动信息不清楚时，LLM 集中提出必要问题；其他缺省项给出可见建议，由用户在卡片中修改或确认。
4. 商品材质、功能、认证、价格等用户未提供的事实保持未指定；风格建议可以补全，商品事实不能编造。
5. 用户确认当前需求卡后才可生成。用户改动描述、需求卡或参考图后，旧提示词与确认均失效；由 LLM 重新整理，展示同一版本的卡片和完整提示词，再确认、生成。
6. 用户原文与成功整理的结果写入数据库；LLM 一次性返回完整内容，等待时显示加载状态。

**完成标准：** 不上传图片也能得到可编辑、可确认的需求卡；最终提交给 VISUAL 的提示词与当前确认版本一致。

### F3. 可选上传一张参考图

**输入：** 0 或 1 张参考图，以及用户的文字描述。

**行为：**

1. 无图时使用文生图路径，生成入口正常可用。
2. 上传后显示缩略图，支持移除和替换；本版把图片统一作为生成参考，不额外区分素材库类型。
3. 文件格式、有效性及大小在调用模型前检查；供应商要求更严格时提前提示。
4. 有图时将当前参考图实际提交给支持参考图输入的 VISUAL 接口；接口不支持时显示原因，允许用户移除图片改用文字生成。
5. 后续反馈重生沿用当前原始参考图，除非用户显式移除或替换。
6. 参考图保存为本机文件；替换或移除当前引用时，保留历史版本依赖的图片。

**完成标准：** 有图、无图两条路径均通过真实模型调用验收；上传的图片不能只停留在界面预览中。

### F4. 按确认需求生成单张图片

**输入：** 已确认的需求版本、可选参考图、可用的 VISUAL 配置。

**行为：**

1. 生成前展示当前用途、提示词、是否附参考图、输出尺寸和数量一张。
2. 用户点击后提交一次请求；后端先保存任务再返回任务编号，后台执行生成，页面约每 2 秒查询状态。前后端共同阻止重复提交。
3. 服务返回异步任务时，由适配器查询同一任务的状态；查询状态不再次提交生成。
4. 将供应商返回的图片数据或结果地址转换为本机可预览、可下载的图片文件；只收到任务编号或临时地址尚不算交付完成。
5. 明确错误进入失败状态；远端是否完成不确定时标为“结果未确认”。均保留需求、参考图及已有结果，等待用户决定下一步。
6. 新建任务或刷新页面不能触发新的生图请求；刷新后从数据库恢复原任务及状态。当前请求使用提交时的需求快照。
7. 后端重启后，将未完成任务标为“结果未确认”，保留远端任务编号（若有），不自动重新提交。用户主动再生成前提示原请求可能已计费；按供应商能力决定能否进一步查询原结果。

**完成标准：** 用户经过确认并点击一次，可以得到一个实际可打开的图片文件；失败时可以恢复操作，且不会自动重试产生额外生图请求。

### F5. 反馈重生、版本预览与下载

**输入：** 成功结果及用户反馈，例如“背景换成浅灰色，商品保持居中”。

**行为：**

1. LLM 在当前需求上应用反馈，保留用户未要求改变的文字约束，展示更新后的需求卡与完整提示词。
2. 用户确认并点击重新生成后创建新版本，继续遵守 F3、F4。
3. 任务中的成功版本按时间展示缩略图，用户可以选中任一版本查看、下载；历史记录可在刷新或重启后查看，重生失败不覆盖旧版本。
4. 下载文件的扩展名与实际编码一致；下载成功的文件可在浏览器之外打开。
5. 本版将修改解释为重新生成，提示词保留约束不等同于像素或商品细节不变；不承诺“只改一处，其余像素完全不变”。

**完成标准：** 完成“首图成功 → 输入反馈 → 确认重生 → 新图成功 → 仍能下载前一版及新版”的全过程。

## 4. 最小交互与任务状态

采用中文单页界面：顶部显示只读的模型配置状态；左侧为描述输入、参考图、需求卡与历史任务入口；右侧为生成状态、当前图片、版本缩略图和下载按钮。视觉风格采用中性色和一个强调色，暂不建设品牌视觉系统。

正常流程：

`后端配置模型 → 输入需求／可选上传图 → LLM 整理 → 用户确认 → 提交后台任务并查询状态 → 成功预览 → 下载或反馈重生`

| 状态 | 允许的下一步 |
|---|---|
| 编辑中 | 发送需求给 LLM |
| 整理中 | 等待结果；失败后修改或手动重试 |
| 待确认 | 编辑需求卡、确认当前版本 |
| 可生成 | 点击生成；修改输入后返回编辑中 |
| 生成中 | 查看状态；阻止重复生成和修改本次请求内容 |
| 成功 | 下载、查看当前任务版本、提交反馈或开始新任务 |
| 失败 | 保留输入和成功版本，修改配置／需求或手动重试 |
| 结果未确认 | 查看保留的任务信息；确认可能重复计费后再主动提交新生成任务 |

开始新任务不删除旧任务及图片。刷新页面恢复当前任务；重启后可以查看历史记录，但未完成生成不会自动重跑。需要修改模型配置时提示在本机编辑后端 `.env` 并重启。

## 5. 最小数据与异常要求

需求卡至少包含：商品描述、图片用途、风格、构图／场景要求、需呈现的文字、固定输出尺寸、参考图标识及完整生图提示词。需要呈现的文字为空时表示不要求加字。

SQLite 至少保存：任务标识、对话记录、当前需求及确认版本、执行状态和结果版本。每个生成版本记录提交时的需求快照、提示词、模型标识、参考图标识、时间与本机图片位置；图片写入本机目录，API Key 仅由后端本机配置加载，不写入数据库。

| 异常 | 必须行为 |
|---|---|
| LLM 认证失败、额度不足或不可用 | 显示可理解的错误；保留用户原文；允许修改后端配置并重启后重试 |
| LLM 返回内容不能形成有效需求卡 | 显示整理失败；保留原文；不进入生成 |
| 参考图损坏或超出限制 | 在生图请求前提示替换或移除 |
| VISUAL 认证失败、限流或额度不足 | 显示错误；不清空需求和历史成功版本 |
| 生图等待超时或远端任务状态未知 | 显示“结果未确认”；保留已有任务标识；用户手动再次提交前提示上次请求可能已经计费 |
| 后端在生成期间重启 | 保留任务快照和已有结果；将未完成任务标为“结果未确认”；不自动重新生图 |
| 结果地址下载失败或内容不是有效图片 | 显示交付失败；保留已返回的信息；重新获取现有结果不触发再次生成 |
| 图片文字错误或商品细节变化 | 用户可以反馈重生；系统保持原图可下载，不显示自动质检通过或商品保真保证 |

等待上限按所选接口文档配置并明确显示。区分本机整理耗时、远端等待和交付结果；不对尚未实测的速度、成本或生成质量承诺数值指标。

## 6. v1 范围外

账号与支付、多商家管理、多智能体团队、模型自动选择、多 SKU 批处理、多平台规则库、自动合规认证、多尺寸派生、图层编辑、精确局部改图、独立素材库、自动店铺上架、点击率与销量归因均留到后续版本。

本版保留“需求整理者 + 生图执行者”的职责划分，通过一次顺序工作流实现，不要求多智能体框架。

## 7. 端到端验收

| 编号 | 场景与操作 | 通过条件 |
|---|---|---|
| AC-01 | 在后端 `.env` 分别填写两套真实服务配置，执行需求整理和生成 | 两个请求分别使用正确配置；网页、配置接口、日志和结果中没有 API Key；网页不能修改 Key |
| AC-02 | 只输入商品与图片要求，不上传图片 | 获得需求卡，确认后生成一张实际图片并成功下载 |
| AC-03 | 输入描述并上传一张有效参考图 | 参考图实际进入视觉生成请求，成功返回并下载图片 |
| AC-04 | 描述中缺少商品主体，或促销价格存在歧义 | LLM 提出必要问题；未确认需求前不提交生图请求；不自行编造价格 |
| AC-05 | 修改已确认的需求或替换参考图 | 旧确认失效；重新确认后才允许生成；本次结果关联新需求快照 |
| AC-06 | 连续点击生成，或服务返回异步任务 | 只提交一个生成请求；异步查询沿用同一个远端任务标识 |
| AC-07 | 首图后输入反馈并重新生成 | 新需求体现反馈；已有约束保留；新版与前版均可预览、下载 |
| AC-08 | 使用错误密钥，或模拟服务报错／超时／无效图片结果 | 按异常表展示原因并保留输入与成功版本；不会自动再次生成 |
| AC-09 | 上传不支持的文件、移除图片后再次生成 | 非法文件在调用前被阻止；移除后走纯文字生成路径 |
| AC-10 | 生成中刷新页面 | 恢复原任务并继续查询其状态，不再次提交生成请求 |
| AC-11 | 已有成功版本后重启服务 | 历史需求、对话、版本和图片仍可查看下载；模型配置从后端 `.env` 重新加载 |
| AC-12 | 在生成未完成时重启服务 | 未完成任务变为“结果未确认”；不自动重新生图；保留旧结果 |
| AC-13 | API 配置留空后启动应用 | 网页和历史查看可用；对应模型操作明确提示未配置，不显示模拟生成成功 |
| AC-14 | 开发前后端分别运行，再构建前端以日常模式启动 | 开发通过代理访问 API；日常只启动 FastAPI 即可打开网页并调用 API |

**完成定义：** 所有验收项通过，其中 AC-01、AC-02、AC-03、AC-07 必须使用实际配置的两类 API 完成；异常可通过受控模拟验证。用提示词文本、占位图或模拟生成结果不能代替真实生图验收。

## 8. 接入前待确定的最少信息

| 编号 | 待确定项 | 解决方式 |
|---|---|---|
| OPEN-01 | LLM 服务商、模型标识、服务地址和公开接口文档 | 当前留空；确定后据官方文档适配，API Key 由用户写入后端 `.env` |
| OPEN-02 | VISUAL 服务商、模型标识、服务地址和公开接口文档 | 当前留空；确定后核实文生图、参考图输入、输出格式、商用条件及任务查询方式 |
| OPEN-03 | 固定方形像素尺寸、文件限制和等待上限 | 根据 OPEN-02 的官方文档确定，在配置与界面中明确显示 |

这些信息影响 API 适配与真实验收，不扩展五个核心功能。若所选 VISUAL 仅能识图，或缺少参考图生成能力，应先更换为满足要求的生图接口，或由用户明确调整对应范围和验收项。
