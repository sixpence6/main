# 对话引导失败验收修订：可编辑提示词与显式生成确认

日期：2026-11-10（Asia/Shanghai）。范围：现有四角色、聊天入口与 PreparedPrompt 确认链路；未引入逐阶段业务审查。

## 用户验收失败与原因

用户反馈“没有引导我去做，而是一轮直接生成”。原 P0 测试通过证明了已编码的自动执行规则，但不能替代产品验收：用户已否定自动图片执行体验，并明确要求生图前展示、直接修改提示词和确认。

当前基线存在三处直接原因：S07 编制完成调用 `collaboration.execute_prepared` 自动签发最终确认；工作流投影隐藏 direct 模式的预览并将等待转换为 compile_prompt 动作；前端也按 direct 模式隐藏提示词卡片。另有模型 ready 且仅给出主体请求时，兜底引导只识别“高级”等形容词，不能覆盖普通“帮我做钢笔宣传图”。

## 当前交互契约

1. 初始模糊主体请求先提一个关键方向问题；模型自行填默认不能覆盖此引导。已明确方向、历史修改继承已有方向或用户委托设计，可直接进入提示词准备。
2. 每次图片调用前必须展示完整正向、反向提示词及实际尺寸、数量、参考信息。即使“直接做”“你来定”，也停在持久化的 `S07 needs_input / awaiting_confirmation`，不自动签发最终执行授权。
3. 提示词直接在卡片文本框中编辑，聊天输入框继续保留。点击“确认使用以上提示词生成”时，如有编辑，先保存用户原文形成新快照，再以新快照执行显式确认；不调用模型再改写用户编辑。
4. 编辑只修改正向、反向文本，输出参数与参考绑定沿用当前准备请求。空白正向文本不能确认；保存失败保留编辑且不能执行旧提示词；旧预览确认返回冲突。
5. 新快照编辑与旧快照失效在同一事务提交。唯一最终授权、原意图计数及执行幂等沿用现有实现；确认后实际执行请求和历史提示词指向同一份用户确认文本。
6. 刷新、重开、重复编制、恢复准备均停在等待。纯讨论、暂停、未解决问题不能由确认旧快照绕过。已提交及结果未知任务仍按原任务恢复，不能补发。

## 实现与验证

- 后端取消自动最终确认及 compile_prompt 的执行捷径；工作流返回预览和 confirm_prompt／edit_prepared_prompt 动作。
- 新增 edit_prepared_prompt 本地保存命令，复用已存在的快照、版本、权限、批准适配记录。记录 user_edited 与 user-edit:exact-text，内容审查仍关闭，没有增加审查模型调用。
- 前端所有当前流程显示可编辑卡片；正向与反向文本框分别有可见标签、长度限制、忙碌禁用和焦点样式。确认后冻结为只读回执。
- 后端新增 `test_editable_prompt_confirmation.py`，覆盖明确请求等待、数据库无提前任务与授权、刷新／重复编制不执行、精确文本保存、旧快照拒绝、同最终命令幂等、模糊请求引导、委托只准备、空白拒绝及暂停后旧确认拒绝。
- 原端到端场景通过测试辅助函数显式发起最终确认后才断言交付；等待验收专用测试使用原 `_drain`，不会由辅助函数代签确认。
- 前端提示词卡片测试覆盖 direct 模式显示、编辑后先保存再确认新快照、保存失败不执行、空白禁用、重复点击、确认回执、窄屏及键盘可访问性。

## 验收边界

这次验证使用可控模型与图片适配器，不产生付费供应商调用；不能声称真实模型对所有自然语言输入的引导质量已通过用户验收。新引导兜底仍使用中文模式，模型判断依赖真实任务继续验证。浏览器级视觉和用户最终体验验收不由 DOM 自动化替代。
