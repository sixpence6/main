# GF-07/08 澄清与约束语义验收

基线：`668a064`（GF-03、GF-01/02/04、GF-05、GF-06 已完成）。
范围：`version/v3/workflow-gate-remediation-v3.md` §2.5（GF-07、GF-08）。

## 修复的旁路

1. S03 澄清问题原先只校验总长度，未校验单题长度、链接/联系方式、建议正文或问题形态；未审查的建议文本可能通过 `questions` 暴露给用户。
2. S03 恢复分支（`s12._resume_s03_review`）重放历史 `request_json` 时信任持久化的 `task.allowed_evidence_ids`；篡改历史检查点可扩大证据许可，让未经当前服务端许可的证据支撑“通过”。
3. 澄清恢复分支在展示前直接信任历史生产者问题文本，未复用正常分支的同一问题校验。
4. 软偏好原先仅靠“不进入 hard rules”间接排除；编制候选声明覆盖软偏好时没有结构化校验，可能声称覆盖任意值。
5. 用户锁定/解锁改变强度时，旧需求确认的失效路径已存在，但没有真实 HTTP 反例证明旧确认被撤销且不会执行图片。

## RED 反例与修复

新增 `backend/tests/test_gf07_08_constraint_semantics.py`：
- `test_invalid_clarification_question_is_not_exposed`（3 个参数）：建议正文、外部链接、超长问题均返回 `409 REVIEW_INVALID`；S03 blocked，问题正文不出现在工作流视图，零产物、零图片调用。
- `test_soft_preference_feedback_does_not_veto_a_passing_image`：质量报告包含软偏好反馈但所有适用硬规则通过时，仍进入 S10 并恰好提交一张图片。

新增 `backend/tests/test_gf07_08_recovery_clarification.py`：
- `test_recovery_clarification_uses_server_evidence_not_tampered_history`：篡改 S03 恢复检查点的 `task.allowed_evidence_ids` 为 `foreign-evidence`，恢复 reviewer 引用该证据时返回 `409 REVIEW_INVALID`；不产生批准、不提交图片，重放请求的证据列表由当前服务端事实生成。

修改 `backend/tests/test_v3_p1_t11_constraint_layers.py::test_http_confirmation_records_locks_and_rejects_changed_strength`：
- 首次确认记录 `user_locks={}`；用同一卡片提交 `user_locks={"style_keywords": ...}` 时返回 `409 REQUIREMENTS_CHANGED`，活动 `requirements_card` 批准被撤销，`prompt_preview` 为空，零图片调用。

修改 `backend/tests/test_v3_p1_t10_execution_snapshot.py::test_execution_snapshot_flows_confirm_compile_qc_and_history`：
- 编译后显式点击最终确认，再等待质量检查；断言每个 executable 快照字段都有非空 destination，且冻结请求的 `execution_requirements` 与确认快照一致（背景、配色、文字布局、参考处理等字段继续进入实际请求）。

## 残余风险

- 澄清问题语义校验是确定性的安全过滤，不替代审查模型对“是否仅为解除 blocking 缺项”的语义判断；服务端仍以审查通过的问题集合为准。
- 旧 V2 前端测试的 prompt_plan artifact 读取路径尚未迁移；后续若需要全量绿色，应按 `prompt_preview`/历史读取接口更新。
