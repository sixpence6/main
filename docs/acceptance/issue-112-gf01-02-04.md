# Issue #112 GF-01/02/04 验收记录：统一最终执行授权

## 1. 范围与结论

- 工单：GF-01/02/04（`version/v3/workflow-gate-remediation-v3.md` §2.2），父任务 #112。
- 目标：准备意图只授权提示词编制与审查；图片执行只消费已展示、已批准、已冻结、获当前用户最终确认的请求；失败、质量拒绝、未知结案后的重试/新任务必须先创建新准备意图并重新编制、展示、等待最终确认。
- 基线：`integration/v3` 的 `fe80293`（GF-03 旧写入口封闭后）。
- 本票生产代码变更：`main/backend/app/workflow/stages/s07.py`、`s08.py`、`s09.py`。
- 测试变更：新增 `backend/tests/test_gf01_retry_reconfirmation.py`；更新 `backend/tests/test_t65_generation_cycle.py`、`backend/tests/test_t68_recovery.py`、`backend/tests/test_issue_113_t01.py`、`backend/tests/test_issue_117_t05.py`。
- 结论：`retry_generation`、`retry_rejected_generation`、`revise_prompt_and_retry`、`start_new_generation` 不再直接创建 Generation/GenerationJob 或调度图片供应商；它们创建新的准备意图、占用新的受理计数与三类槽位、重新运行提示词编制和独立审查，然后停在 S07 `needs_input` 等待最终确认。最终确认仍由 `final_confirmation._confirm_prompt_once` 在 `BEGIN IMMEDIATE` 中重验并只创建一个执行尝试。

## 2. 修复的旁路

修复前：

- `s08._start_replacement` 在验证风险确认后，直接读取既有已批准提示词，创建新 Generation/GenerationJob，并调用 `_schedule`。`retry_generation` 与 `start_new_generation` 因此绕过最终确认。
- `s09._retry_rejected_generation` 复用同一 `_start_replacement`，质量拒绝后的重试同样直接执行。
- `s09._revise_prompt_and_retry` 在创建新意图前先编制提示词，再调用 `_start_replacement` 直接执行。
- `s08.handle` 与 `s09.handle` 对上述重试动作统一调用 `require_image_execution()`，该函数恒抛 `FINAL_CONFIRMATION_REQUIRED`，使重试完全不可用，而不是进入“重新准备并等待最终确认”。

修复后：

- `_start_replacement` 增加可选 `revision_note`；只创建/重放新准备意图，然后切到 S07 并调用 `s07._compile(ctx, revision_note, allow_known_rejection=True)`。不加载旧提示词、不创建任务、不调度。
- `s08.handle` 只对 `submit_generation` 保留 `require_image_execution()`；重试/风险新任务进入准备流程。
- `s09` 的纯质量重试与文字修复都走 `_start_replacement`；`revise_prompt_and_retry` 把用户文字作为 `revision_note` 传入同一次重新编制，不再提前编译或直接执行。
- `s07._ensure_image_unsubmitted` 按当前 `intent_id` 检查既有任务，避免旧失败/拒绝/未知任务阻止新准备意图。

- 项目/工作流：新意图 `accepted`，首个意图保持 `failed`，run 停在 S07 `needs_input`；提示词预览为待确认状态。
- 账本：2 个 `GenerationIntent`、2 条 `GenerationUsage`、6 个 `GenerationSlot`（前 3 个已释放，后 3 个 live）。
- 执行面：任务、最终授权和 Visual `submit_calls` 在最终确认前均不增加；确认后恰好增加 1 个任务、1 个授权、1 次图片调用。

## 8. 结论

GF-01/02/04 的“重试/修复/未知结案后直接执行图片”旁路已关闭。所有重试类动作先创建新的准备意图，重新编制并展示含负向内容的完整提示词，停在 S07 等待当前用户最终确认；只有最终确认才创建一个执行尝试并调用图片供应商。每次调用可追溯到已展示的冻结请求。
