# Markdown 角色交接三路径验证

日期：2026-11-10（Asia/Shanghai）。

## 行为与验证范围

四角色默认输出 Markdown 原文，适配器不请求 JSON response_format。原文独立保存并直接加入下游输入，超过界面摘要长度的视觉方案仍完整传递。数据库及界面仍使用程序生成的结构化记录，这些记录不再是模型必须填写的输出格式。

测试通过真实 HTTP 路由、临时 SQLite 数据库与工作流执行器运行；外部文字模型和生图服务使用替身。因此下列结果证明程序行为，不代表真实模型内容质量或用户视觉验收。

## 三条路径

1. **方向问答**：模糊钢笔请求先展示问题和 A/B/C 选项；选择加自由补充的原文进入下游；等待提示词确认时没有图片提交。补充测试覆盖 Markdown 标题中的问题，修复标题问题被忽略的问题。
2. **完整角色链与提示词确认**：需求、完整视觉方案和生成提示词以 Markdown 交接，原文保存不变。停于 S07 needs_input，刷新不额外调用模型；点击确认后完成一次图片提交。编辑正负提示词原样保存为新快照，旧快照确认返回 409，重复确认不重复生成。
3. **旧会话恢复**：对需求助手、视觉策划师、生成工程师分别注入失败，覆盖旧 JSON 与当前 Markdown 两种来源，共六种恢复场景。查看失败状态不自动重试；用户手动继续后使用 Markdown，保留用户原文，停于提示词确认，最终确认后仅提交一次。额外验证回答方向后视觉阶段超时，恢复不重新询问，回答原文进入视觉与生成角色。
