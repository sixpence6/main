# GF-09/10 发布原子性与事务边界验收

基线：`2b3ef47`（GF-03、GF-01/02/04、GF-05、GF-06、GF-07/08 已完成）。
范围：`version/v3/workflow-gate-remediation-v3.md` §2.6（GF-09、GF-10）。

## 修复的旁路

1. S10 `_publish` 的最终写事务原先只重查 Delivery 是否存在且为 approved；图片批准、清单批准、需求/执行快照、真实文件摘要和跨连接撤销/换图/改摘要都可能在前置检查与最终提交之间失效，仍被发布。
2. 发布记录、任务状态、意图交付、槽位释放原先没有与必要的 `delivery.published` 审计落在同一提交边界。
3. `request_new_version` 原先无条件撤销 `generation_prompt` 批准；已发布运行的历史提示词批准因此被撤销，历史版本视图的 `prompt` 变为空，违反历史不可改写要求。
4. 旧交付测试使用 `GenerationJob.generation_id=None`、无 PreparedPrompt/FinalAuthorization 的种子行，发布路径在最终确认门禁后返回 `FINAL_CONFIRMATION_REQUIRED`；这些夹具不能证明合法发布，已迁移到真实 HTTP 工作流。

## 残余风险

- 发布事务内的文件读取与摘要测量在 SQLite 写事务中完成；大文件会增加事务持锁时间，当前单图上限与本地文件系统下可接受，后续可改为先测量再以摘要条件提交。
- 旧 V2 种子行仍可作为历史只读数据存在，但已不能发布；生产历史数据若缺少 FinalAuthorization 会被稳定拒绝，必须走新的准备/最终确认流程。
