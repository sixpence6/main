# R1 项目归属隔离操作说明

- **适用版本**：v3 R1，ticket #59（代码提交 1436095 及之后的文档提交）
- **适用对象**：部署／运维人员、管理员、普通用户
- **前置阶段**：C0 备份与维护基线（#54）、R1 首管理员与登录（#55）、账号创建与一次性链接（#56）、本人改密与多端会话（#57）、账号停用／恢复与安全事件（#58）已合并
- **状态**：本说明只覆盖项目及其可信子对象的账号归属隔离；不覆盖后台生成任务归属、历史／恢复双门禁、旧数据认领或 R1 全阶段验收

## 1. 范围与硬边界

本票上线后，服务端按已认证账号自动执行：

1. 新建项目写入当前账号为唯一所有者。
2. 对话消息、需求简报、工作流、参考图、生成记录和资源字节通过所属项目继承归属。
3. 项目列表先按所有者过滤，再排序、分页和计数。
4. 本人可访问自己的项目；匿名请求返回 401；他人、不存在和未归属旧项目统一返回 404。
5. 管理员账号不获得读取普通用户项目的通用豁免；伪造 owner_account_id、is_admin 等客户端字段返回 422。

明确不允许：

- 通过改数据库手工伪造项目经理的所有者来“临时共享”；共享／协作不在 v3 范围。
- 给管理员增加“查看所有项目”的旁路，或把管理员身份当作业务数据读取授权。
- 把 owner_account_id 为 NULL 的旧项目直接暴露给任意账号；必须先完成备份、归属认定和受控数据治理。
- 在没有备份与回滚预案时直接在生产数据根执行迁移或回填。

## 2. 前置条件

| 项 | 要求 |
|---|---|
| 服务版本 | 已包含 #55–#59 的构建，迁移目标为 0005 |
| 数据库 | SQLite；迁移前已完成 C0 备份并验证可恢复 |
| 迁移树 | main/backend 与 backend 两处迁移文件一致；不得修改已应用的 0003／0004 |
| 网络边界 | 仅可信内网／局域网；不得直接暴露公网 |
| 账号 | 至少一个可用管理员；普通用户通过管理员创建并完成一次性链接设置 |
| 数据 | 禁止在真实业务数据上做验收演练；演练使用临时 DATA_DIR |

## 3. 操作步骤

### 3.1 升级前备份

1. 按 docs/operations/maintenance-backup.md 停止业务写入或进入维护窗口。
2. 使用 C0 维护 CLI 生成一致性备份，确认 SQLite、引用文件与清单校验通过。
3. 记录备份目录和校验摘要；不要在未验证备份的情况下继续。

### 3.2 执行迁移

在 main/backend 目录执行：

    D:/Desktop/新建文件夹/backend/.venv/Scripts/python.exe -m alembic -c alembic.ini upgrade head

确认：

- alembic current 显示 0005。
- projects 表存在 owner_account_id 列和 ix_projects_owner_updated 索引。
- 外键指向 accounts.id，删除行为为 RESTRICT。
- 既有项目与账号数量、内容不变；其 owner_account_id 默认为 NULL。

### 3.3 启动与健康检查

1. 启动正式入口 uvicorn app.main:app，确认 /api/health 返回 200。
2. 使用管理员登录，打开 /login 与工作区，确认页面可加载。
3. 新建一个测试项目（临时数据环境），确认项目出现在本人列表且不出现在其他账号列表。

### 3.4 验证隔离

使用两个普通账号 A、B：

1. A 创建项目并上传参考图；B 直接访问 A 的项目、工作流、参考图和生成 ID。
2. 预期：B 对所有 A 的资源得到统一 404；B 的项目列表不包含 A 的项目。
3. 使用管理员账号访问 A 的项目：预期 404，而不是管理员代看成功。
4. 用 B 伪造 owner_account_id 或 is_admin 创建项目：预期 422，不产生数据。

生产环境验证应使用临时账号与临时数据根，验证后清理；不要把真实用户项目内容写入工单或日志。

### 3.5 旧项目处理

owner_account_id 为 NULL 的旧项目在 API 中一律不可服务。需要恢复访问时：

1. 先确认项目原始归属和迁移来源，形成书面记录。
2. 在备份与维护窗口内执行受控回填，逐条记录项目 ID、账号 ID、操作者与时间。
3. 回填后由项目本人在正常登录下验证；不得由管理员代看内容。
4. 未完成归属认定前保持不可服务，不要用 NULL 当“公共项目”。

### 3.6 回滚

仅在隔离演练或经批准的维护窗口内：

1. 停止服务并再次备份当前数据库。
2. 执行 alembic downgrade 0004，确认 owner_account_id、索引与外键被移除。
3. 恢复对应版本代码并启动，验证旧路径。
4. 注意：回滚会丢失归属列；回滚后不得继续写入新归属，需按变更流程重新升级。生产回滚必须由维护负责人批准。

## 4. 安全边界

| 边界 | 行为 |
|---|---|
| 所有者来源 | 仅来自服务端已认证 Principal，不接受客户端 owner／role 参数 |
| 过滤顺序 | 先按 owner_account_id 过滤，再排序、limit、cursor 与计数 |
| 子对象继承 | 消息、简报、工作流、参考图、生成记录、资源字节均通过 project_id 校验项目所有者 |
| 统一不存在 | 他人、未知、未归属项目统一 404，响应体一致，不泄露 ID 是否存在 |
| 管理员边界 | 管理员读取普通用户项目同样 404；管理能力只用于账号管理，不用于业务数据代看 |
| 主体重验 | 事务内检查账号可登录、会话未撤销和 session_epoch；停用后旧会话立即 401 |
| 文件前置检查 | 参考图上传／删除在解析和写文件前完成归属检查，避免留下孤立文件 |
| 客户端字段 | owner_account_id、is_admin 等额外字段触发 422；客户端角色永不授权 |
| 事务 | 归属校验在读写事务内再次执行，避免列表读取后状态变化 |

## 5. 常见失败与处理

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 本人项目返回 404 | 当前登录账号不是项目所有者；项目为 NULL 归属旧数据；项目已不存在 | 核对登录账号与项目归属；旧项目按 3.5 做受控治理；不要通过改 URL 或伪造参数尝试 |
| 列表为空但数据库有项目 | 项目归属为其他账号或 NULL | 用项目创建账号登录；确认迁移后新项目是否写入 owner_account_id |
| 管理员看不到用户项目 | 这是预期安全边界，不是故障 | 不要开放管理员代看；由用户本人操作或走受控维护流程 |
| 401 AUTH_REQUIRED | 会话过期、被撤销、账号停用或 session_epoch 变化 | 重新登录；确认账号状态与安全事件 |
| 422 VALIDATION_ERROR | 请求夹带 owner_account_id／is_admin 等字段 | 移除非法字段；客户端只提交服务端允许的输入 |
| 迁移报 SQLite ALTER 限制 | 使用了未采用 batch 模式的旧迁移 | 确认部署的是 #59 的 0005 batch migration；不要手工改表绕过 |
| 迁移后项目全不可见 | 旧项目 owner 为 NULL | 这是兼容策略；先备份并完成归属回填，不能直接放宽 API |
| 上传返回 404 但项目存在 | 当前账号不是所有者 | 用所有者账号重试；检查是否有跨账号 ID 混用 |
