# R1 管理员建号与一次性链接操作说明

- **适用版本**：v3 R1，ticket #56（代码提交 `2f7c2d7` 及之后的文档提交）
- **适用对象**：本机维护者或已登录管理员
- **前置阶段**：C0 备份与维护基线（#54）、R1 首管理员与登录（#55）已合并
- **状态**：本说明只覆盖管理员建号与 setup／reset 链接；完整账号禁用、恢复、审计浏览与品牌化界面分别见 #58、#76

## 1. 范围与硬边界

本操作允许管理员：

1. 创建一个普通账号，初始状态为 `pending_setup`。
2. 为该账号签发一次性 `setup` 链接，或为已激活账号签发一次性 `reset` 链接。
3. 将链接通过管理员自选的可信渠道交给用户；系统不发送邮件。
4. 用户在链接页面主动设置密码，之后回到正常登录。

明确不允许：

- 管理员代替用户设置明文密码、代替用户登录或读取用户密码。
- 通过公网、邮件、聊天机器人或其他第三方服务自动投递链接。
- 把链接写入工单、日志、监控、聊天记录、浏览器收藏或持久化存储。
- 直接修改数据库中的账号、链接、密码或审计记录来绕过流程。
- 使用真实业务数据库做本说明的演练；演练必须使用临时数据目录。

## 2. 前置条件

| 项 | 要求 |
|---|---|
| 服务版本 | 已部署包含迁移 `0004_r1_account_links` 的构建 |
| 数据库 | 已执行 `alembic upgrade head`，版本为 `0004` 或更高 |
| 首管理员 | 已通过本机交互终端完成 `init-admin`（见 `docs/operations/r1-local-admin-init.md`） |
| 可信应用地址 | 必须配置 `APP_PUBLIC_URL` 为实际用户访问的 HTTPS 根地址，例如 `https://app.example.internal`；不配置时签发链接会返回 503 |
| 网络边界 | 仅可信内网／局域网；不得直接暴露公网 |
| 浏览器 | 支持 ES2020 和 SameSite Cookie 的现代浏览器 |

`APP_PUBLIC_URL` 只接受绝对 `http`／`https` 地址，不能带用户名密码、查询串、fragment 或非根路径。生产环境必须使用 HTTPS；本机回环 HTTP 只用于开发冒烟。

## 3. 操作步骤

### 3.1 管理员登录

1. 打开 `APP_PUBLIC_URL` 下的 `/login`。
2. 输入首管理员邮箱与密码。
3. 登录成功后进入工作台；管理员在页头看到“账号管理”入口。

### 3.2 创建普通账号

1. 进入 `/admin/accounts`。
2. 在“创建账号”输入用户邮箱，提交。
3. 成功后列表出现该账号，状态为“待设置密码”，角色为普通用户。
4. 同一规范化邮箱只能存在一个账号；重复创建返回 409，不会覆盖既有账号。

注意：

- 创建账号不会生成密码，也不会自动登录该账号。
- 管理员不能把新账号设为管理员；管理员提升不在本票范围。
- 不存在的账号、普通用户访问管理接口均按统一错误处理，不泄漏额外信息。

### 3.3 签发 setup 链接

1. 在账号行点击“生成设置链接”。
2. 页面只显示一次完整链接；立即通过可信渠道交给用户。
3. 关闭提示后无法再次查看同一 token；如遗失只能重新签发。
4. 重新签发会立刻撤销该账号此前所有未使用的链接；旧链接随即失效。

链接形如：

```text
https://app.example.internal/set-password#token=<一次性随机值>
```

token 位于 `#` 之后，不会随 HTTP 请求发送到服务器，也不会出现在 Referer 中。不要把 `#` 后面的内容复制到任何日志或工单。

### 3.4 用户设置密码

1. 用户在浏览器打开完整链接。
2. 页面显示掩码邮箱、用途与过期时间；打开页面本身不会消费链接。
3. 用户输入新密码并确认。密码要求 15–128 个 Unicode 字符，允许空格，不允许首尾裁剪；常见弱口令会被拒绝。
4. 提交成功后链接立即失效，页面提示返回登录；系统不会自动建立会话。
5. 用户回到 `/login` 用新密码正常登录。

若链接已过期（默认 30 分钟）、已被使用、用途不符、账号被禁用或 token 错误，统一显示“链接无效或已过期”，不提示具体原因。

### 3.5 签发 reset 链接

仅对已激活账号可用：

1. 在账号行点击“生成重置链接”。
2. 交付方式与 setup 相同；签发本身不改变旧密码，也不撤销现有会话。
3. 用户提交新密码后：旧密码立即失效；该账号所有现有会话被撤销；其他未使用链接被撤销；产生重置审计。
4. 用户必须重新登录；不会自动登录。

## 4. 安全边界

| 边界 | 行为 |
|---|---|
| token 强度 | 32 字节 CSPRNG（≥256 bit），base64url；服务端只保存 SHA-256 摘要 |
| 生命周期 | 创建后 30 分钟；单次使用；新签发撤销旧链接 |
| 用途绑定 | `setup` 仅待设置账号；`reset` 仅已激活账号 |
| 地址来源 | 只使用配置的 `APP_PUBLIC_URL`，绝不使用请求 Host |
| CSRF | 链接 POST 需要预认证 CSRF 与精确 Origin |
| 缓存／引用 | 私有响应 `no-store`；页面 `Referrer-Policy: no-referrer` |
| 日志 | 不记录明文 token、密码、Cookie 或完整链接 |
| 会话 | 设置成功不下发登录 Cookie；重置成功撤销全部旧会话 |
| 限流 | 签发：管理员 10 次／15 分钟、目标 3 次／30 分钟；验证：每摘要 5 次失败／15 分钟、每来源 30 次／15 分钟 |
| 审计 | 建号、签发、使用、重置均记录稳定账号 ID；审计写入失败会回滚对应敏感变更 |

## 5. 常见失败与处理

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 签发返回 503 `APP_PUBLIC_URL_NOT_CONFIGURED` | 未配置可信应用地址 | 在部署配置中设置 `APP_PUBLIC_URL` 后重启服务；不要临时用 Host 代替 |
| 签发返回 409 `ACCOUNT_DISABLED` | 目标账号已禁用 | 先按 #58 的恢复流程处理；本票不提供绕过 |
| 签发返回 409 `LINK_PURPOSE_MISMATCH` | setup 用于已激活账号，或 reset 用于待设置账号 | 选择正确用途 |
| 签发返回 429 `RATE_LIMITED` | 超过管理员或目标预算 | 等待 `Retry-After` 后重试；不要重复点击 |
| 用户打开即提示无效 | 链接被新签发替代、已过期、已使用或复制不完整 | 重新签发；确认完整复制 `#token=` 后内容 |
| 设置提交 422 | 密码不足 15 字符、超过 128 字符或命中弱口令 | 按页面提示修改；不得关闭策略 |
| 设置提交 400 | token 无效、过期、重复、用途错误或账号禁用 | 重新签发或按账号状态处理 |
| 设置提交 503 | 认证依赖暂时不可用 | 稍后重试；不要删除链接或改数据库 |
| 登录旧密码失败 | reset 已完成或会话已轮换 | 使用新密码登录；旧密码本应失效 |
