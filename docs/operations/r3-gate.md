# R3 多视口工作台与旧地址跳转操作说明

本说明对应 #77（V3 T25，R3-GATE）。它面向本地维护者和验收人员，说明单一工作台如何使用、旧地址如何表现、如何复核关口证据，以及出现异常时如何安全处理。

## 1. 目的与边界

R3 之后的正常入口只有一个工作台：项目打开后停留在 `/`（describe 子路由）。U1 沟通与当前需求卡、U2 原位授权与安全恢复、U3 当前交付与历史预览都在这个页面内完成。旧四页不再存在，外部旧地址只做无副作用跳转，不会重放确认、生成、恢复或发布动作。

- 前端源码根：D:/Desktop/新建文件夹/main/src
- 测试根：D:/Desktop/新建文件夹/tests、D:/Desktop/新建文件夹/backend/tests
- 工作台组件：DescribePage + ConversationPanel + WorkflowPanel + HistoryPreview
- 路由定义：main/src/router/index.ts
- 后端与数据库：本票没有后端路由或迁移变更；迁移头保持 0010
- 数据边界：临时 SQLite 或已授权数据根；禁止为了演练触碰 backend/data 与 main/backend/data

## 2. 用户路径

1. 打开 `/login`，用本地账号登录。
2. 新建项目或从项目列表打开已有项目；地址形如 `/?project=<project-id>`。
3. 在左侧对话区描述商品与用途、上传参考图；右侧显示当前需求卡、当前问题与下一步。
4. 需求卡通过独立审查且处于待确认时，勾选确认框，点击“确认以上需求并生成图片”（没有额度用量时按钮文案为确认动作的服务端标签）。
5. 原位查看执行进度：编制提示词、生成图片、检查图片、准备交付。系统只轮询读取工作流视图，不自动重发。
6. 交付准备完成后，人工批准交付、发布交付；U3 显示当前交付的合法图片和下载入口。
7. 在历史版本标签中切换旧版本只改变本地预览；要调整时使用“基于反馈生成新版本”，提交后回到 U1。
8. 安全页 `/account/security` 管理密码、会话和安全事件；管理员在 `/admin/accounts` 创建账号、发一次性链接、停用/恢复和设置额度。

## 3. 旧地址跳转

| 旧地址 | 新行为 | 是否产生写请求 |
| --- | --- | --- |
| `/describe` | 重定向到 `/?project=...`，保留 query 与 hash | 否 |
| `/confirm` | 重定向到 `/?project=...`，保留 query 与 hash | 否 |
| `/generate` | 重定向到 `/?project=...`，保留 query 与 hash | 否 |
| `/results` | 重定向到 `/?project=...`，保留 query 与 hash | 否 |
| 其他未知路径 | catch-all 回到 `/` | 否 |

注意：四个已知旧地址会保留 `project` 查询参数和 hash；未知路径只回到 describe，不保证保留任意未知 query。旧生成地址即使带 `action=start_new_generation` 或旧 `request_id`，页面也不会读取旧凭据或提交动作。

## 4. 页面状态与操作

| 状态 | 页面表现 | 用户可以做什么 |
| --- | --- | --- |
| 无项目 | 空工作台，提示先描述商品与用途 | 新建项目或选择项目 |
| U1 需求整理 | 左对话、右需求卡/当前问题；候选需求不展示完整内容 | 继续描述、增删参考图、发送消息；不可提前确认 |
| 待确认 | 需求卡已通过独立审查，复选框 + 单个确认按钮 | 勾选后原位确认；只发生一次受理写请求 |
| S07–S10 执行 | 四步进度、真实状态标签、无百分比；只读轮询 | 等待；失败或未知时使用安全恢复动作 |
| 失败/未知 | 当前问题、真实状态、恢复按钮和说明 | 核实原任务、找回原结果、关闭本地跟踪或确认风险后新建任务；不会自动重发 |
| 待批准/待发布 | 交付预览与批准/发布动作 | 人工检查后批准、发布 |
| U3 当前交付 | 当前版本图片、下载入口、3840×2160 等固定信息 | 下载、切换历史、提交反馈 |
| 当前交付不可用 | “当前交付不可用”，无图片、无下载 | 检查内容门禁或联系管理员；历史标签仍可查看已发布版本 |
| 历史预览 | “历史预览 · 不代表当前需求状态” | 仅本地切换；不修改需求、不调用模型 |
| 会话失效/跨标签 | 先隐藏业务并核验身份，再决定跳转 | 重新登录；不会用旧账号数据填充新会话 |

按钮和提示以服务端返回的 available_actions、issue、delivery、versions 和权限为准。前端不会因为刷新、导航、历史切换或重新登录而额外调用模型。

## 6. 常见问题

### 6.1 打开旧书签后只看到工作台

这是预期行为。四个旧页面已经删除，`/confirm`、`/generate`、`/results` 不会恢复旧界面。若要继续原任务，请在工作台核对当前需求、执行状态和可用动作，不要手工拼动作 URL。

### 6.2 点击确认后没有出现生成

先看“当前问题与下一步”和执行进度：确认请求可能被额度、重放冲突、需求漂移或账号状态阻断；服务端错误码会显示在流程提示中。刷新只会重新读取视图，不会重发确认；不要连续点击按钮。

### 6.3 显示结果未知或恢复按钮

“结果未确认”不等于远端未受理。可先使用“核实原任务”（只读）或“找回原结果”（只轮询/取回原任务），不要新建任务来绕过。只有用户确认风险并选择“基于风险新建任务”才另计一次；关闭跟踪只更新本地占用，不声称远端取消。

### 6.4 当前交付不可用

当前版本虽曾发布，但资产可能被撤销、拒绝、过期或内容门禁不再放行。页面会隐藏图片和下载，历史标签不会提供该资产。联系管理员检查资产审查状态；不要直接访问 generated、published、references 或 locator 路径。

### 6.5 历史版本标签缺失

历史标签只显示已发布、可下载且仍通过内容门禁的版本；被拒绝、撤销、过期或缺少审批的版本不会出现。若旧版本是合法历史，检查交付审批、图片审批和资产状态，不要修改数据库绕过。

### 6.6 768px 出现全局横向滚动

本票修复的是工作台和主操作控件的横向溢出；既有全局壳层在 768px 的文档宽度可能仍为 1020px。先确认是否由侧栏/页头引起，不要把全局壳层问题误判为工作台回归；R3 关口文档已把它列为残余风险。

### 6.7 测试数量比历史基线少

R3-GATE 删除的是旧四页和旧状态路径的测试，共 90 个；替代覆盖在 t65–t76 与 tests/t77-r3-gate.spec.ts。若数字异常，请对照 docs/acceptance/r3-gate.md 的迁移表，而不是直接恢复旧测试或放宽断言。

## 7. 回滚与数据边界

- 本票没有数据库迁移。代码回滚使用 git revert 5ced256 或回退合并提交；回滚后旧四页源码需要从历史提交恢复，但不应把旧页面重新接回 v3 路由。
- 重定向本身不写数据库；如果发现旧地址触发了写请求，按故障处理，先停止服务并保留日志，不要删除审计。
- 浏览器脚本只使用临时 SQLite 和种子账号，不读写 backend/data 或 main/backend/data。
- 不要在生产数据上执行测试迁移、删除资产或重放动作；需要真实数据演练时，先按维护流程完成备份和来源选择。
