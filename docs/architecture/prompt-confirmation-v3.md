# v3 真实提示词预览与最终确认契约

> **2026-11-10 失败验收后的现行规则：** 用户反馈“一轮直接生成、没有引导”，原 P0 的自动图片执行不予通过产品验收。制作请求只启动需求与提示词准备；每次生图必须先展示完整、可编辑的正向和反向提示词，由用户点击“确认使用以上提示词生成”后才执行。包括“直接做”“你来定”、新版本、重新编制和恢复，均不能跳过这次确认。提示词编辑原样保存为新等待快照，不调用模型改写，旧快照失效。模糊主体请求先引导一个关键方向，明确方向可跳过探索但仍须确认提示词。实施与验证见 [失败验收修订记录](../acceptance/editable-prompt-confirmation-2026-11-10.md)。


状态：**本轮实施的技术契约，尚未实现或验收。** 记录日期：2026-11-03（America/Toronto）。依据 [modify_v3](../../version/v3/modify_v3.md) 第 3、5 节；产品规则以 [SRS v3](../../version/v3/SRS_v3.md) 为准。当前基线与验证范围见[实施记录](../../version/v3/modify-v3-start.md)。

本文细化 HLD 的 R2 seam，不新增通用工作流框架、队列或授权引擎。以下是目标逻辑事实与 interface；**命令名、字段与状态不表示现有路由或表已经提供这些能力**。落到物理表和迁移时仍需审查当前结构，并在临时库验证升级与回退保护。

## 1. 必须保持的不变量

1. 明确创作／修改授权准备；只有“确认使用以上提示词生成”授权图片执行。问候、解释、暂停、复制和读取不承担任一授权。
2. 原意图在提示词准备前原子受理，计一次并占原个人／实例／项目槽位。提示词预览、最终确认和原意图恢复均不再计数，不绕过额度。
3. S07 独立批准后持久化等待；未最终确认没有图片执行尝试、供应商提交或通过恢复生成的旁路。
4. 展示的完整实际提示词、实际负向内容、参考依赖和输出参数，与图片提交请求逐字段一致。点击后不得重编或切换。
5. 只有当前有效批准与上下文能确认；过时、异参、错账号、错项目、错登录上下文全部由服务端拒绝。
6. 重复／并发最终确认最多产生一个执行尝试；丢响应重放返回原任务，不重复计数或调用。
7. 已提交或提交事实未知不再发送；真实状态不因刷新、重启、切号、修文本或旧接口被改写为“未提交”。
8. 角色独立审查、候选预算、身份／内容双门禁、G00—G08、原子发布与历史不可变继续有效。

## 2. 资源预算与计数选择

**沿用“已受理逻辑尝试”计数，不改成“最终点击次数”“成功出图次数”或免费无限预览。** 准备受理继续位于需求整理／批准之后、S07 外部调用之前；新增的最终确认只是原意图的执行许可。所有数值只读 SRS 第 12 节。

| 情况 | 次数 | 占用／调用 |
|---|---|---|
| 问候、解释、暂缓、只读加载 | 不新增 | 不准备、不新增意图；已有等待保持原事实 |
| 需求尚缺阻塞项 | 不受理新准备 | 原对话澄清；非准备阶段现有受控角色调用仍独立归因，不冒充完全零 TEXT 成本 |
| 预校验／额度／槽位拒绝或事务回滚 | 不新增 | 不占用、不调用、不排队 |
| 明确准备新意图，事务成功 | 一次 | 原子占三类槽位；可编制／审查，不能提交图片 |
| 编制／文本修复 | 原一次 | 每产物候选上限继续持久化；技术故障自动重试为零 |
| 已批准提示词等待 | 原一次 | 保留占用，无图片执行尝试；不新增等待超时或后台自动释放规则 |
| 最终确认同一有效快照 | 原一次 | 沿用占用，原子记录最终授权与唯一图片执行尝试 |
| 预览重读、相同命令重放、原任务恢复／核实／找回 | 原一次 | 不重复受理／占槽；恢复仍需有效的原最终授权 |
| 已受理后失败或可证未提交的明确放弃 | 原一次，不退款 | 只有已证实终态／合法结案才释放，不因普通错误提前释放 |
| 实质变化后的新受理或明确风险新任务 | 新一次 | 原任务先合法结算；重新检查全部限制，不以修改绕过单项目槽位 |
| 提交事实未知 | 原一次 | 保守保留占用，只核实原任务；结案不代表远端取消 |

前端应在首次准备受理前提供轻量说明：准备占用一次已受理任务额度，最终确认不再重复计数；这不是金额或全部模型费用承诺。不得增加第二套需求确认表单或用“准备”按钮掩饰收费规则。

这里没有批准变更次数、窗口、并发、候选预算或输出参数。如实现需要把计数推迟到最终确认、等待自动到期、免费重编或另设准备额度，先列产品差异并另行确认，不能在实现中自行采用。

## 3. 持久化事实与状态

### 3.1 准备意图

复用 `GenerationIntent`、`GenerationUsage`、`GenerationSlot`。明确创作／修改动作具有稳定请求 ID 与参数摘要；需求确认、意图、用量、占用和必要审计在同一 `BEGIN IMMEDIATE` 中提交。先重验账号／归属，再返回同参原意图；异参冲突。不得把“用户确认需求”记录解释为图片最终授权。

最终需求仍逐项审查并形成不可变快照，用户在原对话核对／补充；不因移除可见卡片而省略需求确认事实。澄清回复或纯交流不能被强行当成新准备授权。

### 3.2 已批准执行快照

S07 获独立批准后，将下列不可变内容和 `awaiting_confirmation` 事实**先持久化**，再对外提供可确认预览。该状态不是客户端内存标记，也不能用 `GenerationJob.submit_pending` 代表未获最终授权的等待。

| 内容 | 最小绑定 |
|---|---|
| 所属上下文 | 稳定快照 ID／契约版本，项目／run／意图，所有者和准备操作者 |
| 原需求 | requirement revision、项目业务 revision、完整执行需求快照及摘要；不只一段摘要文案 |
| 提示词 | artifact ID／revision／摘要，独立批准 ID／规则／契约版本；完整最终有效请求文本 |
| 参考依赖 | 稳定资产 ID、资产实际版本与内容摘要、用途及依赖关系；明确无参考也进入摘要 |
| 输出与服务配置 | 实际单图数量、尺寸、格式等有效参数，适配器／模型／有效服务配置指纹；不含密钥 |
| 生命周期 | 创建时间、等待／已授权／已失效状态、失效原因与关联原任务；历史快照不改写 |

语义快照摘要对上述有效执行字段规范化计算，显示摘要或客户端传入字符串不能替代服务端验证。非业务重命名不使有效快照失效；实际需求、提示词、参考或输出变化则必须失效。

快照持久化与工作流进入等待的写入必须原子；审计或任一写点失败不能留下可执行授权。候选未批准、批准已撤销、依赖错版或快照不完整时不得提供可点击最终确认。

### 3.3 最终执行授权

最终点击的真实操作者、当前有效登录上下文、快照 ID／摘要、稳定命令 ID、授权时间、执行请求摘要与唯一执行尝试的关联在同一短事务保存。不得在网络调用后补写授权。

最终授权沿用原意图的用量与占用；图片执行尝试中的 prompt、参考和输出只从这份冻结请求读取，不再从当前项目可变字段重新拼接。网络等待在事务外，调用前和发布前继续执行既有身份／账号状态／内容绑定检查。

登录上下文绑定与语义快照分开：等待可以跨退出和重启持久保存；原会话的旧点击载荷不能在另一账号或新登录生命周期直接复用。当前有效会话重读时可得到其自己的只读命令上下文，再显式最终确认；读取本身不写批准或授权，不延长轮询会话空闲期。

## 4. 调用者 interface

以下逻辑命令应收在现有工作流／受理 seam，避免前端分别解释额度、提示词和恢复。具体路由由实现提交确定，命名不要求新增一套工作流框架。

| 动作 | 输入要点 | 结果与副作用 |
|---|---|---|
| 明确创作／修改与准备 | 原输入内容／引用、当前 revision、稳定准备请求 ID；服务端识别实质意图并校验已批准需求 | 原子受理后仅驱动 S07；缺项进入澄清；纯交流无新需求／意图 |
| 读取对话／工作流／预览 | 当前有效身份与本人项目 | 返回当前安全预览、原等待事实和真实动作；零模型调用、零新授权 |
| 最终确认提示词 | expected revision、快照 ID／摘要、稳定最终命令 ID、当前登录命令上下文；既有 CSRF／来源校验 | 原子最终授权＋唯一执行尝试；返回原／新同一任务；同参幂等，异参冲突 |
| 明确放弃准备 | 原意图／等待快照、revision、稳定请求 ID；不能把普通“先别生成”直接当删除 | 仅在无未收敛外部调用且可证未创建图片执行尝试时，失效快照并结案／释放；原计数保留 |
| 只读核实 | 原任务与访问边界 | 只读本地提交事实，不调用模型；与可能访问供应商的找回／恢复明确区分 |
| 手动恢复／找回 | 原意图、检查点及有效原授权 | 未最终确认只可恢复准备并回等待；已最终确认按原任务证明推进，未知不重发 |

创建／执行命令受忙碌与可用动作约束，忙时立即拒绝而非排队。准备和最终确认的幂等键是不同命令域；同意图只一行用量，不能用新最终命令 ID 重复提交同一快照。

### 4.1 最终确认事务中的重验

1. 当前会话、账号状态、操作者、所有者与项目／run／意图归属有效；旧登录上下文不匹配则拒绝。
2. 需求 revision／快照、当前等待快照、实际提示词、批准与参考依赖／文件及有效输出配置一致。
3. 在授权成立后查询原最终命令：同 ID 同参返回原记录，异参拒绝；快照已失效或所属意图不再允许执行时不能重放推进业务。
4. 原意图仍有效，原三类占用完整，且不存在不同的进行中执行；不因后来降低次数限额而把有效同意图最终确认重新计成新受理，也不免除账号禁用与安全校验。
5. 原子保存最终授权、唯一图片执行尝试及必要审计；任何故障全回滚。提交后才调度网络调用。

至少以数据库唯一约束保护“同意图／快照仅一个图片执行尝试”；不能只靠 `ProjectLocks` 或前端禁用按钮。两条独立连接应产生同一逻辑结果。

### 4.2 旧动作不能成为旁路

`confirm_requirements` 若保留，只能归入准备授权，不能自动生图。`compile_prompt`、S12、后台 driver、旧 `submit_generation`、`retry_generation` 和风险新任务都必须经过相同最终确认守卫；兼容接口不能用空 payload、旧批准或审核通过跳过停点。

原任务的恢复可复用**真实存在且仍有效**的最终执行授权；不同新图片尝试必须重新展示实际提示词并明确最终确认。不能让重试／风险确认只显示“再试一次”却隐藏本次执行文本。旧已提交／未知任务只核实原事实，不借升级制造新提交。

## 5. 实际请求的统一编制

当前 `prompt_plan` 有正向／负向字段，而 `GenerationRequest` 只有一个 `prompt` 字符串，S08 当前保存正向文本。**这不是“负向内容已经发送”的证据。**

实现时将适配器实际消费的可见业务提示词与参数在最终确认前编制成冻结请求。若适配器只支持单 prompt，确需合入负向内容时在准备阶段完成，并展示合入后的实际全文、重新审查；若原生支持分开的负向字段，则一并展示并固定。不得展示一个未实际执行的负向字段，也不得在点击后暗中合并、翻译、重编或切换。

记录并断言的不是只有前端 `prompt_plan` 文案，而是冻结请求 → 最终授权摘要 → `Generation`／执行尝试快照 → adapter 实际请求。必要内部系统指令、密钥、供应商 locator 和审核自由文本不成为用户预览正文；服务配置变更使待确认请求失效，不泄密。

## 6. 修改、故障、恢复与兼容

| 事件 | 必须发生的处理 |
|---|---|
| 用户仅交流／暂缓 | 不改需求／提示词版本，不自动确认或生成；已有等待仍在，草稿可编辑 |
| 实质需求／用途／参考变化 | 旧待确认失效；原未提交意图按可证事实结算，需求新版本重新准备；旧按钮服务端拒绝 |
| 只修文本候选且原需求不变 | 原意图、原计数与持久预算；新候选独立审查，生成前重新展示新快照，不能继承旧文本授权 |
| 批准撤销／规则契约不兼容／文件变化 | 停止确认与执行，安全说明；历史不重写，不移植旧批准 |
| 最终确认事务失败 | 无最终授权、无新执行尝试、零供应商提交；原等待／计数保持 |
| 事务成功但响应丢失 | 同一命令重放返回同一任务；不能再次受理、再计数或第二次提交 |
| 事务成功、尚未调用时进程退出 | 授权与执行尝试仍在；启动只修本地状态，不自动补调用；仅显式恢复且可证未提交时消费原授权 |
| 已批准等待时退出／重启 | 等待、提示词及用量仍在，零图片提交；重读不准备、不授权 |
| 已提交或事实未知后退出／重启 | 保留原远端任务、计数和保守占用；核实／找回不生成第二次提交 |
| 账号禁用或切号 | 禁用阻止下一调用及发布，迟到返回隔离；另一账号／失效登录上下文不能执行旧确认 |
| 旧数据缺最终确认事实 | 不补造授权。无提交事实的新执行必须按新契约展示确认；已有提交／未知只核实，不重新发；旧交付沿历史快照与当前访问门禁 |

真实历史数据的迁移、认领或数据根切换仍先确认来源、验证完整备份；本轮启动批次不执行。后端迁移只先在临时 SQLite 上测试全新升级、旧结构升级保留、故障回滚与约束竞争。

## 7. 后端证明与 R3 进入门槛

先新增能复现旧自动穿透的真实 interface 回归，再改实现；私有 helper 探针不能单独作为通过证据。受控 adapter + 临时 SQLite 至少覆盖：

| 编号 | 后端必须证明 | 对应验收 |
|---|---|---|
| PC3-01 | 未批准候选／失效批准不公开且不可最终确认；完整实际提示词及依赖可安全读取 | MV3-05 |
| PC3-02 | 明确准备后完整独立审查，但最终点击前零图片尝试／提交；多次 GET 与进程重启仍等待 | MV3-06 |
| PC3-03 | 最终确认捕获请求与展示快照逐字段／摘要一致，含真实负向处理与参考内容版本 | MV3-07 |
| PC3-04 | 改需求／提示词／批准／输出／参考、错项目／账号／旧登录上下文拒绝旧确认；零额外调用 | MV3-08 |
| PC3-05 | 准备和最终确认各自的双击、丢响应、独立连接竞争及同 ID 异参；一个意图／用量／占用／提交 | MV3-09 |
| PC3-06 | 每个授权／执行／审计写点故障全回滚；最终确认不再次做新次数受理 | MV3-09；R2 |
| PC3-07 | 未授权恢复／旧动作不能生图；真实提交／未知只核实原任务；崩溃前后分别取证 | MV3-06、09；R1/R2 |
| PC3-08 | 放弃、实质修改、重命名、纯交流与忙时拒绝分别断言需求版本／账本／槽位／调用数 | MV3-03、08、09 |
| PC3-09 | 历史升级保留、旧未知任务不重发；原内容门禁和发布仍有效 | MV3-10、14；R1/R2 |

PC3、MV3 均为待验证条件。本次旧基线 R1/R2 测试通过只证明原行为的回归起点，不证明新停点。新后端证据及受影响 R1/R2 复验成立后，才开始 R3 重建；真实供应商、浏览器、视觉和手机证据另行完成。
