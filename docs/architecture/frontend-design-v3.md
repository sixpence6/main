## 1. 界面骨架与视觉

### 1.1 品牌与参照

产品名为“电商生图工作台”，助手名为“智能生图助手”。视觉参照是 modify_v3 中给出的 WorkBuddy 页面，不运行其脚本、不依赖其字体、图片、接口或数据，不复制其品牌、模型选择器、思考过程或本地数据库提示。

以下沿用的色值与几何仅是实施起点，**不是本次重新实测的参考页尺寸或视觉验收证据**。实施时在真实浏览器同尺寸对照，按参考页调整比例、留白、颜色、圆角、气泡与输入区。

| 项目 | 起始值 |
|---|---|
| 页面／面板 | 浅灰紫 `#EEF0F8`；白色 `#FFFFFF`；次级背景 `#F5F6FA` |
| 主色／文字 | `#5846E8`；正文 `#1F2438`；次级文字 `#626D88`；边框 `#E5E8F3` |
| 几何 | 桌面外边距和间隔约 12px；侧栏约 288px；顶栏约 68px；消息最大宽约 880px |
| 圆角 | 外壳约 28px；消息约 12—16px；输入约 20px；仅弱阴影 |
| 排版 | 本地系统中文无衬线；正文约 14—16px、行高约 1.6；正常长文换行 |
| 消息 | 用户右对齐紫色气泡；助手左对齐，带自有署名；提示词全文，不折叠成摘要 |

状态、焦点与关键文字须有足够对比度，不仅依赖颜色；尊重减少动态效果偏好，不用等待动画阻碍输入。

### 1.2 唯一聊天主体

```text
浅灰紫页面背景
├─ 圆角白色侧栏
│  ├─ 智能生图助手 / 新建对话
│  ├─ 搜索 / 本人真实会话列表（直接可达，不再嵌套项目抽屉）
│  └─ 账号 / 本人用量 / 必要说明等轻量入口
└─ 圆角白色聊天主面板
   ├─ 当前对话标题；窄屏侧栏按钮
   ├─ 唯一消息流：用户图文 / 助手回复 / 已批准真实提示词 / 已发布图片
   └─ 唯一固定输入区：图文草稿 / 附件预览 / 上传 / 发送
```

新会话只有简短欢迎语和原输入框，例如“发来商品图片，或告诉我你想做什么样的电商图片”。首次明确发送才创建创作记录；不设功能卡、统计、流程教程或第二个开始入口。

移除需求表单、参考用途下拉、复杂确认卡、流程／任务面板、阶段导航、常驻技术报告和重复标题。必要确认、用途、授权及恢复通过对话与轻量动作完成，不把旧工作台整体搬进聊天气泡。主区不提供对话／成果切换，不新增独立成果页面。

## 2. 会话路由与生命周期

### 2.1 目标路由

下表是目标契约，不声明已实现。当前入口查 [router/index.ts](../../main/src/router/index.ts)。

| 路径 | 目标行为 |
|---|---|
| `/` | 新建空对话；只读欢迎语，未发送不创建项目 |
| `/projects/:projectId/chat` | 鉴权后读取原会话、提示词等待、消息与历史图片；不自动执行业务动作 |
| 旧 `/projects/:projectId/results` | 权限核验后定位原会话的当前真实结果；没有结果时说明真实状态，不用别图兜底 |
| 旧成果链接的 `version=<run_id>` | 定位同项目对应历史消息，版本无效／不可访问则安全说明，不静默替换 |
| 旧 `/describe`、`/confirm`、`/generate`、`/results` | 仅保留经验证的必要定位信息进入对话，不重放旧动作 |

URL 不放消息正文、凭据、参考图内容或供应商 locator。旧入口兼容不是保留第二套成果工作流；页面可打开也不表示私有图片可访问。

### 2.2 状态与上下文

U1／U2／U3 来自当前需求、提示词、意图及交付，不由 URL 或历史成功图决定。当前新需求 U1 时可在原位置查看旧图，但它仍是历史，不能被标为当前新成果。

所有成功、失败、finally、搜索、附件、图片 URL、提示词与滚动定位回调匹配稳定账号、登录生命周期、项目和请求序列后才写状态。退出、切号、跨标签失效及时清理；同账号重新登录也使用新生命周期，abort 不能替代匹配校验。401、403 和供应商故障按各自安全语义处理。

### 2.3 发布、历史定位与输入聚焦

**发布不自动跳页。** 仅在当前原会话追加对应已发布图片；别的项目或账号的晚到结果不抢占页面。刷新从服务端历史重建，不重复插入图片，也不为恢复界面启动生成。

旧链接历史定位、放大、下载及回看都只读，不改变修改基准。轻量“继续修改”动作至多聚焦原输入框，不自动发消息、创建版本、准备提示词或确认生成。

## 3. 对话内的完整引导

### 3.1 消息、提示词与图片

用户消息绑定当时文字和附件；助手只展示已获批准且允许公开的内容。需求可用简短摘要解释，不恢复复杂确认卡，也不能把摘要当执行提示词。

| 状态 | 对话呈现与动作 |
|---|---|
| U1 描述／澄清 | 简短回复或阻塞问题；已明确信息不反复追问，信息足够直接收敛 |
| U2 准备提示词 | 同一任务的一条轻量状态，按真实事实更新；准备受理与用量按确认契约说明 |
| U2 等待最终确认 | 完整实际执行提示词默认展开、可复制；实际发送的负向内容一并展示，参考图片版本与输出要求简明可核对；紧随“确认使用以上提示词生成” |
| U2 执行／审查 | 原轻量状态更新，不持续新增进度消息，不展示内部阶段、虚假百分比或思考过程 |
| U3 发布 | 新的助手图片消息，含放大、原图下载、必要版本信息；每轮旧图留在原消息位置 |

旧提示词可回看与复制，但旧按钮不再授权。按钮可用性来自服务端待确认快照，不仅来自组件是否可见；未批准候选、内部系统提示、审核自由文本和模型思考过程不进入消息正文。

### 3.2 原输入框与意图分流

需求、参考用途与提示词修改都在唯一底部输入框提出。问候、解释、“先别生成”只产生适当交流，不擅自更新需求版本、受理准备或生成图片。用户明确要结束已受理准备时，必须与普通交流区分，并经服务端可证未提交的结案动作处理，不能悄悄释放未知任务占用。

实质修改才更新创作要求；必要时进入新版本并重新审查、准备与展示。历史预览不改默认最新方案基准，不承诺局部编辑，也不自动把旧生成图当参考图。助手需要追问时集中询问阻塞缺项，参考用途用自然语言，不靠用途表单。

“好的”“继续”、复制、打开提示词、上传、选择快捷答案、刷新或重新登录均不等于最终生成授权。不增加提示词编辑器、反馈输入框或隐藏表单；快捷动作也不能替代明确的最终确认。

### 3.3 等待、失败与恢复

执行中可以编辑未发送草稿，忙碌期间不能提交新请求或暗排队；等待最终确认时，用户仍能通过原输入框提出修改或暂缓。

| 服务端安全原因 | 对话呈现与允许动作 |
|---|---|
| 需求缺项／真实变化 | 简短问题；在原输入框补充，实质变化才形成新需求版本 |
| 可修复编制偏差 | 原意图的轻量状态；持久预算内修文本，故障后只在后端允许时手动恢复；修复后仍须展示并等待最终确认 |
| 提示词／批准／依赖失效 | 旧确认失效；新提示词准备、批准、全文展示后才可最终确认 |
| 硬项失败／安全拒绝 | 内容未放行及获批准的安全说明；只提供后端允许的后续动作，不自动重生成 |
| 关键证据不足 | 待核实，不称图片合格，不展示未放行图 |
| 契约错误／技术故障 | 安全固定说明；可能调用模型的手动恢复明确区别于只读核实 |
| 远端提交／结果未知 | 保留原任务；只核实／找回原结果，结案不宣称远端取消，新任务另走风险确认与额度检查 |

原因和动作来自服务端类型化事实，不猜错误文案，不把审核员建议直接公开。轮询不重复插入任务状态，也不逐次向辅助技术播报相同进度。

## 4. 内联图片与历史

每张图片绑定原需求、实际执行提示词和交付版本，可访问才展示放大与下载。下载必须是对应发布原图，不用缩略图或其他版本冒充，也不触发生成。

新图追加，不覆盖旧消息；历史提示词来自当时的快照，不能用当前提示词解释旧图。查看旧图不修改当前需求／参考／确认，不新增历史分叉功能。

撤销、过期、文件丢失和访问拒绝收敛到真实安全状态，及时清除失效缓存与临时 URL；未放行图不能因浏览器缓存可见。没有可访问结果时不自动生成，也不静默切到另一张图。

## 5. 会话侧栏与必要入口

侧栏一条项目记录是一段持续创作对话，不是一次出图，也不是登录会话。新建、搜索、切换和重命名直接可达；不保留“先开项目抽屉才看到列表”的主要路径。

搜索使用服务端所有本人标题，先所有者过滤再分页；不新增全文搜索或以已加载页过滤冒充完整搜索。重命名仅改元数据，不改需求 revision、确认、意图和审批，不调用模型。查询变化重置分页，晚到结果匹配账号与请求序列。

必要账号、退出、管理员授权入口、本人用量与数据使用说明保持轻量。移除常驻模型状态面板，不提供模型选择、密钥编辑、余额或充值。服务端未确认的保存不能显示为成功；不新增本地业务数据库、项目删除或批量清理。

## 6. 输入、滚动与小屏

### 6.1 唯一图文输入区

文件选择、粘贴与拖入都在原输入区；发送前可预览／替换／移除，发送后图片属于相应用户消息。引用绑定稳定资产和版本，不能用“当前缩略图”推断历史消息附件。服务端能力不足先补契约和回归，不在 UI 伪装多附件支持；本轮不擅自扩大既有单参考图参数。

输入固定在主面板底部，消息独立滚动，输入增高不遮挡正文和发送按钮。Enter 发送、Shift+Enter 换行；保留既有 Ctrl／⌘+Enter 发送，中文 composition／选字 Enter 不发送。空内容、同次提交和忙碌请求不重复发送，粘贴图片不吞普通文字，拖入文件不导航离页。

草稿与附件准备态只在页内按项目和登录生命周期隔离，离开／切换沿用未发送提醒；刷新不承诺保留。退出、切号或跨标签失效清理，临时图片 URL 及时释放。

### 6.2 响应式、焦点与滚动

| 视口 | 侧栏和聊天 |
|---|---|
| ≥1024 CSS px | 常驻圆角侧栏，主区仍为一个聊天主体 |
| 768—1023 CSS px | 同一侧栏默认折叠为单层抽屉；主区不增加左右工作流分区 |
| <768 CSS px | 抽屉宽不超过视口减 32px；消息、提示词、图片和操作纵排，输入适配软键盘与安全区 |

抽屉管理焦点、锁背景滚动、关闭后回触发按钮，不叠多层导航遮罩。附件操作、放大关闭、复制与最终确认均有键盘焦点及可见标签；放大关闭后焦点回原消息。

用户上滚阅读时不强拉到底，只有适当的新消息提示。320／768／1440 CSS 像素无整体横向溢出；真实手机软键盘、发送按钮与中文输入法必须实测，不能用截图缩放代替。
