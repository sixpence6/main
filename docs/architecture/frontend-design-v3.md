## 1. 界面骨架与视觉

### 1.1 品牌与参照

- 产品品牌保持“电商生图工作台”；对话署名、欢迎语和输入提示统一使用“智能生图助手”。
- 创作工作台参照用户提供的 WorkBuddy 页面于 2026-11-01 观察到的布局：浅灰紫背景、大圆角白面板、左侧列表、主区顶栏、聊天消息及底部常驻图文输入。参考地址仅作设计来源：`https://linche-portfolio-29244.app.workbuddy.host/?sharecode=OMYZKE7RWI`。
- 视觉在本地实现，不运行参考站脚本，不依赖其字体、图片、接口或数据。保持自有品牌，不复制 Aurora 名称、Logo、DeepSeek 选择器、“思考过程”和“本地数据库已保存”等参考站业务。
- 登录、设置密码、账号安全及管理员页面沿用 SRS 的既定范围；本轮不重做登录页，也不新增用户切换模型、密钥编辑、充值或注册业务。

### 1.2 共壳布局

```text
工作台外壳（切换子路由时保持）
├─ 左侧：品牌 / 新建创作 / 搜索项目 / 项目列表 / 账号与必要状态入口
└─ 主区白色面板
   ├─ 顶栏：项目标题 / 当前步骤或成果版本 / 对话与成果的只读视图入口
   └─ Body 子路由
      ├─ 对话：消息与操作卡片 / 底部图文输入框
      └─ 成果：大图 / 紧凑信息与操作 / 折叠历史与已批准提示词
```

侧栏不计作沟通／结果双列；主区一次只呈现对话或成果。对话、需求卡和生成进度共用消息流，不另设常驻工作流栏。顶栏的视图入口不是阶段导航，也不能授权模型调用。没有可访问成果时说明原因；存在可访问历史时可进入明确标为历史的预览。

## 2. Body 子路由与生命周期

### 2.1 目标路由

下表是**待实现的设计**，不是当前接口或页面已存在的说明。现有路由由[路由定义](../../main/src/router/index.ts)核对。

| 路径 | 用途 | 进入时允许的行为 |
|---|---|---|
| `/` | 新建创作的空对话 | 展示欢迎语与输入框；首次明确发送后才按既有流程创建项目 |
| `/projects/:projectId/chat` | 项目的原始对话 | 鉴权后读取消息、当前需求与任务，恢复页内状态 |
| `/projects/:projectId/results` | 当前成果；无当前成果时展示真实不可用状态 | 只读取已发布且可访问的结果，不默认把旧图当新成果 |
| `/projects/:projectId/results?version=<run_id>` | 显式历史预览 | 校验项目与版本归属，读取该版本；无效版本不静默替换成其他图片 |

三个工作台页面共用外壳及其受账号生命周期约束的状态。URL 只放必要稳定标识，不放消息正文、参考图内容、凭据或供应商 locator。登录与账号管理等现有路由维持原权限边界。

旧 `/describe`、`/confirm`、`/generate`、`/results` 书签保持无副作用兼容：仅携带已验证的必要项目定位信息进入对应对话，不重放旧动作。路由可用与资源可用分别核验；SPA 回退能打开页面不代表业务请求已获授权。

### 2.2 页面位置不是业务状态

U1／U2／U3 仍来自当前需求版本、审查、意图与交付事实，不由 URL、列表选中项或历史图存在性决定。例如，当前新需求处于 U1 时仍可查看旧版成果，但预览明确标为历史，当前状态仍为 U1。

路由守卫先核验身份和项目权限，再呈现业务内容。未登录、权限拒绝、本人内容未放行、文件缺失分别使用既有安全结果；不能短暂闪现上个账号或项目的图片。成果页收到撤销、过期或丢失事实时清除失效预览并说明原因，下载继续由后端逐次校验。

### 2.3 自动进入成果的唯一时机

仅在**当前活动项目的对话页**观察到“当前需求版本新交付从未发布变为已发布且可访问”时，自动进入成果子路由一次。匹配账号、登录生命周期、项目、revision、run／交付及请求序列后才处理；使用稳定交付标识防止重复通知或轮询反复跳转。

首次加载、刷新、重新登录、浏览器返回、选历史和点击返回对话，均不算新发布事件。自动跳转保留可返回对话的浏览器历史；返回后不因同一交付再次自动离开。切换到其他项目、账号或已离开对话时，晚到结果不抢占当前页面；原账号的原项目列表在后续正常读取中呈现真实完成状态，不为此额外启动后台任务。

“返回对话”恢复同项目的消息位置与页内草稿；“返回对话修改”进一步定位并聚焦原输入框。两者均不提交消息、不创建 revision、不确认需求、不编制提示词、不触发生图。

## 3. 对话内的完整引导

### 3.1 消息与卡片

普通用户消息、已批准的助手内容与类型化操作卡片共同组成对话时间线。需求卡按版本固定，生成卡按原意图更新，成果入口按交付固定；刷新或轮询不重复插入同一卡片。工作流投影不是伪造的模型回复，也不需要把每次轮询结果写成消息。

助手每轮突出一个当前问题与下一步。用户可一次提供多项信息；已明确的信息不反复询问，只有阻塞项必须补齐。快捷选项填入原输入框，由用户发送；需要自定义时直接编辑同一个输入框。

| 用户状态 | 对话内呈现 | 当前操作与约束 |
|---|---|---|
| U1 描述与完善 | 欢迎／当前问题、已发送参考图、整理与审查状态、已放行的需求摘要 | 用原输入框描述、补充或修改；未通过审查的报告与候选正文不展示 |
| U2 待授权 | 最新获批准的需求确认卡：关键要求、参考用途、输出要求及待核对项 | 唯一主按钮“确认以上需求并生成图片”；必要信息与后端门禁未满足时说明禁用原因 |
| U2 已受理 | 一张持续更新的任务卡：编制提示词 → 生成图片 → 图片质检 → 发布成果 | 依据真实阶段标注进行中、已完成、待核实或失败；不虚构百分比，不再次展示可重复授权的旧主按钮 |
| U3 已发布 | 带版本标识的成果入口卡，可用时包含经门禁放行的缩略图及“查看成果” | 自动跳转按第 2.3 节；用户返回后仍可查看入口，并在原输入框继续提出修改 |

确认卡先突出便于核对的摘要，可展开全部已批准字段；旧卡片保留版本与过时状态，授权能力只属于当前有效卡片。完整执行提示词在实际编制并获批准后才折叠展示，授权前不展示虚构文本。“思考过程”不作为产品功能，不泄露模型原始推理、未审输出或审查员自由文本。

### 3.2 原输入框的修改语义

**所有需求修改只在原对话输入框完成。** 当前交付可调整时，输入区明确提示“基于当前第 N 版交付提出修改”，发送接入服务端实际允许的新版本动作（现有 `request_new_version` 语义），而不是绕过版本／审查的普通消息旁路。前端适配动作所需参数，不把内部动作名暴露给用户。

点击成果页返回修改仅定位输入。用户实际发送实质修改并获服务端接收后，才按既有流程创建新需求版本、进入 U1、重新审查和核对，再次生成仍需明确授权。选中历史预览不会改变修改基准；当前交付不存在或动作不可用时，不以旧图冒充可调整的当前交付。

发送“继续”、点选答案、上传参考图或重新打开对话均不等同生成授权。参考用途与修改边界沿用原规范，不自动把生成图当参考图，不承诺仅改变某个局部区域。

### 3.3 等待、失败与恢复

输入区可保留未发送草稿，提交是否可用按当前服务端动作判断；忙碌时说明锁定原因，不暗中排队提交。区分需求阻塞、明确失败、结果待核实和内容未放行，在原对话提供安全说明和可用动作。

服务端原因是类型化业务事实，不从错误文案子串、HTTP 成功与否或模型自由意见推断。下表为目标交互，不声明这些类别已经是现有 API 枚举；实现应在现有状态接口中提供安全类别、原任务绑定和实际可用动作。此表只适用于已核验归属的任务，身份失效仍按账号生命周期清理。

| 原因 | 对话内呈现 | 允许的用户动作 |
|---|---|---|
| 缺阻塞信息／实质需求变化 | U1 当前问题或需重新核对的需求版本 | 在原输入框补充／修改，形成有效卡片后再明确授权 |
| 可修复编制偏差 | U2 原已受理任务卡显示修复进度或中断原因 | 当前执行预算内修复；中断后仅在后端允许时手动恢复原意图，不重复展示生成授权按钮 |
| 硬项失败／明确拒绝 | U2 标明内容未放行及已获批准的安全说明 | 只提供后端允许的后续动作，必要修改仍回原输入框；不自动重生成 |
| 硬项证据不足 | U2 标明需补证／待核实，不称图片合格 | 显式补信息或可用恢复；未放行图不进入成果 |
| 契约错误／技术故障 | U2 区分校验未完成与处理服务故障 | 安全固定说明；恢复可能调用模型时明确标识，不暗中重试 |
| 远端受理／结果未知 | U2 保留原任务与结果待核实状态 | 只读核实与可能调用模型的恢复分开；不同新任务按风险确认与额度规则处理 |

任务卡以原意图标识更新，卡片与批准内容按 revision／快照绑定；轮询、修复或建议意见不重复插入新任务卡。获批需求卡区分必须满足与偏好建议，确认按钮不把所有偏好升级为硬要求。软反馈只有自身完成内容审查后才可展示，审核员自由文本和未审候选继续隐藏。

状态查询／核实原结果与可能继续调用模型的手动恢复分开标识。恢复按原任务与原授权边界执行，并解释可能的调用风险；创建不同新任务须按既有风险确认与额度规则明确授权。技术失败不自动重试，超时不推断远端未受理；未获可靠支持的远端取消按钮不提供。原因分类不扩展恢复权限，按钮仅依据服务端实际允许动作出现。

## 4. 成果页：展示与导航，不承载需求输入

### 4.1 内容顺序

1. 大图优先：保持原始比例，容器适配可用宽高，不裁掉商品或文字来填满画布。
2. 紧凑信息：当前／历史标签、需求版本、实际尺寸与生成时间；历史信息来自该版本快照。
3. 操作：下载原图、返回对话修改、返回对话。下载只交付实际已发布文件，不把缩略图冒充原图，也不触发生图。
4. 默认折叠：历史版本列表及所选版本实际存在、获批准的执行提示词。缺失提示词明确说明，不用当前提示词解释旧图。

**成果 Body 中没有需求修改输入框、反馈表单、聊天 composer 或可编辑画布；折叠区域中也不能藏入第二套输入。** “返回对话修改”只执行第 2.3 节的导航与聚焦。历史列表允许只读切换与下载可访问版本，不新增“从旧版分叉生成”功能。

### 4.2 历史与不可用结果

当前创作状态与历史预览分别显示。查看历史时标明“第 N 版历史成果；修改仍基于当前第 M 版交付”；若当前已进入新需求且无可调整交付，返回后在原对话继续完善当前需求，不伪造旧版反馈动作。

未发布、被撤销、过期、文件缺失或无可用成果时，显示安全状态与返回对话入口，不展示缓存私图兜底，不自动生成，不把另一版本静默替换为所请求成果。历史记录仍按真实可访问状态列示，缺失／不可用项不提供有效下载按钮。

## 5. 项目列表与必要入口

- 一个项目是一条单商品持续创作对话，其内部保存修改与图片版本；它不是登录会话。点击“新建创作”先进入空对话，首次明确发送才创建项目。
- 标题从首条需求按本地确定性规则生成简短名称，后续可手动重命名。重命名是项目元数据修改，不新增需求版本、确认或模型调用；需保存到服务端，不能仅改浏览器显示冒充成功。
- 搜索范围是**本人全部项目的标题**，由服务端按所有者过滤并分页后返回；不做消息全文搜索，也不以已加载页的前端过滤冒充全量搜索。切换查询重置分页，迟到搜索结果受账号／请求序列隔离。
- 列表提供待补充、待确认、生成中、已完成、需处理等必要标识，按当前版本与任务事实投影。旧版本成功不能把当前待处理项目标成完成；无可靠状态时显示待读取，不猜测。
- 沿用必要的账号安全、退出、管理员授权入口、本人用量／限制与脱敏服务状态，不出现余额或充值。模型状态只读，不提供模型选择器或密钥编辑器。
- 保存说明只反映真实服务端确认；失败时提供恢复指引。未发送草稿不显示为已保存，本版不新增本地业务数据库、跨设备草稿同步、项目删除或批量清理入口。

## 6. 输入、滚动与小屏

### 6.1 唯一需求输入区

输入区常驻对话主区底部，消息独立滚动。输入框增高时压缩消息可视区，不遮挡发送与参考图操作。Enter 发送，Shift＋Enter 换行，Ctrl／⌘＋Enter 同样发送；中文输入法合成／选字的 Enter 不发送，空白或正在提交的同一内容不重复发送。

单张参考图支持文件选择、粘贴及拖入。发送前可核对选图预览，替换／移除有明确提示与状态；粘贴图片不吞掉普通文字，拖入文件不会导航离开页面。类型、大小和内容门禁沿既有服务端契约，客户端提示不是批准证明。上传／替换属于显式业务操作，绑定当前账号、项目与 revision，不夹带到新选中的项目。

同一账号生命周期内，草稿与附件准备状态放在外壳持有的页内状态中，按项目隔离；对话／成果子路由切换不丢失。切换项目或离开应用保留既有未发送提醒；确认丢弃后才清除。刷新不承诺保留未发送内容；显式退出、切号或跨标签身份失效时按 SRS 清理，不借草稿恢复旧账号内容。

### 6.2 响应式与焦点

| 视口 | 项目导航 | 主区与操作 |
|---|---|---|
| ≥1024 CSS px | 常驻约 288px 侧栏 | 消息居中单主体；成果大图、信息和折叠区上下排列 |
| 768—1023 CSS px | 默认折叠为抽屉 | 主区使用可用宽度，不重新塞入左右工作流双列 |
| <768 CSS px | 单层抽屉，宽不超过视口减 32px | 对话／成果一次一页；卡片与操作纵向排列，输入适配软键盘和安全区 |

顶栏与输入区避免盖住正文，页面整体不横向溢出。抽屉打开时管理焦点、锁定背景滚动，关闭后回到触发按钮；不叠加多个导航遮罩。“返回对话修改”将焦点落到带可见标签的原输入框。用户上滚阅读时，新状态提示不强制把消息滚到最底部。

键盘、屏幕阅读器与减少动态效果偏好适用于全部新增操作；等待／失败状态可感知但不逐次轮询播报。320／768／1440 CSS 像素及真实手机软键盘行为属于验收，不只截图缩放。

### 7.1 必须显式承接的后端缺口

核对时[项目路由](../../main/backend/app/routers/projects.py)只有创建、分页列表与详情；全项目标题搜索和手动重命名不能视为已交付。后续实施需在已有项目服务边界补齐最小能力：

- 标题搜索：所有者条件与标题匹配先于分页；空查询退回正常列表，切换查询不能沿用其他查询的游标；前后端明确错误与空结果。列表状态需要足够的当前版本事实，不能仅凭旧 generation 成功推断。
- 重命名：服务端验证身份、所有权、CSRF 与标题；只修改元数据，保留需求 revision、确认、意图及审批快照；失败不显示已保存，成功后列表与详情一致。
- 搜索、重命名与新增路由的读取全部扩展原权限与账号生命周期回归；不引入新模型、搜索服务或绕过项目服务的第二套数据源。

门禁交接还须在原有工作流投影中提供第 3.3 节所需的安全原因、约束强度和原任务动作；正常与恢复返回语义一致。相关后台缺口按[门禁与工作流第 6 节](workflow-gates-v3.md)归属到 R1／R2，前端不通过猜测错误或发起第二次生成来补齐。

### 7.2 实施顺序与收尾

1. 核验 R1／R2 前置门槛与当前代码，列出缺口；补齐必要项目元数据能力及隔离测试，完成后才依赖其制作界面。
2. 核验门禁交接的安全原因与原任务恢复契约；建立共壳子路由与页内草稿边界；导航、刷新、返回与切号用例通过后接入卡片与成果展示。
3. 将需求卡、授权、状态、安全恢复和成果入口迁入聊天，原输入框接入新版本动作；单次受理和版本回归通过后替换旧布局。
4. 完成视觉、附件、搜索、移动端与真实浏览器验收，再删除已无消费者的旧右侧展示和反馈输入；保留仍被新视图使用的业务逻辑与旧 URL 兼容。

文档、测试、截图、脚手架与运行证据位于 `main/` 外；应用代码与后端能力以后续实施变更单独交付。此顺序细化 R3，不重开已完成阶段，也不以样式改版跳过 R1／R2 门槛。
