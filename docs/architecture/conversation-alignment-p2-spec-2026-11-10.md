# 对话对齐 P2：构图示意、色调方向与可解释偏好

日期：2026-11-10（Asia/Shanghai）。状态：用户已确认规格与测试边界，已发布为 [GitHub issue #156](https://github.com/sixpence6/main/issues/156)，标签 ready-for-agent；尚未实施或验收。实施前置：对话对齐 P1（#155）的目标绑定、来源继承和反馈闭环通过本期验收。

## Problem Statement

用户面对“干净克制”“商务稳重”等文字仍可能想象不出区别。多次调整后，用户也需要反复说明自己偏好的产品大小、留白、背景和文字密度。系统如果无说明地记住这些选择，会把一次任务的决定带入其他商品，甚至让用户不知道为什么得到某种画面。

当前已有文本方向选项、字段来源及项目需求累计，尚未发现专门的构图示意协议或可管理的账号长期偏好存储。现有记录不能直接等同于长期偏好能力。

## Solution

在原聊天问题下，用少量明确标注“构图示意”的简图和色块帮助比较方向。示意描述产品大小、位置、留白、文字区及背景色调，配生活化解释；用户选择或自由补充后，继续原来的需求与提示词准备流程。

把多轮选择整理成可解释、可修改的项目偏好摘要；跨项目使用必须由用户明确保存为“我的偏好”。采用偏好时说明来源，用户可查看、修改、删除、清空或要求本次不用。示意、查看和记忆管理不调用图片生成；任何真实生图都沿用完整提示词展示与最终确认。

## User Stories

1. 作为创作者，我希望看见两种构图的大致区别，以便不必仅凭术语想象。
2. 作为创作者，我希望看到产品大小与位置，以便选择主体是否足够突出。
3. 作为创作者，我希望看到留白和文字区域，以便判断画面是否拥挤。
4. 作为创作者，我希望比较浅色、深色和冷暖色调，以便说清“高级”的具体方向。
5. 作为创作者，我希望每张示意都有一句简单解释，以便理解选它会改变什么。
6. 作为创作者，我希望明确知道示意不是实际成图，以便不会误认为已产生商品图片。
7. 作为创作者，我希望查看示意不消耗一次图片生成，以便放心比较方向。
8. 作为创作者，我希望能点选方向，也能直接输入自己的想法，以便表达方式不受限制。
9. 作为创作者，我希望能说“这个布局，但换成浅色”，以便混合表达能被完整保留。
10. 作为创作者，我希望能选择“你帮我选”，以便助手根据当前用途提出推荐。
11. 作为创作者，我希望能说“都不喜欢”或跳过示意，以便继续原聊天。
12. 作为创作者，我希望清晰需求不被强制拉进示意选择，以便保持零额外探索的快路径。
13. 作为创作者，我希望只有当前问题的示意可操作，以便旧选择不会覆盖新版本。
14. 作为创作者，我希望刷新后仍看到同一组方向，以便不会因页面变化重新选择。
15. 作为使用键盘或辅助阅读的创作者，我希望方向有文本名称和描述，以便不依赖看图或分辨颜色。
16. 作为手机用户，我希望示意在窄屏清楚可读，以便不用横向滚动才能选择。
17. 作为创作者，我希望多次修改后的偏好被简短总结，以便检查助手到底记住了什么。
18. 作为创作者，我希望摘要说明偏好来自哪次选择，以便纠正误解。
19. 作为创作者，我希望助手建议与我已选择的方向分开，以便推荐不会被误记为我的偏好。
20. 作为创作者，我希望一次项目选择只用于本项目，以便其他商品不被自动套用。
21. 作为创作者，我希望明确要求“以后都这样”时才保存跨项目偏好，以便记忆由我控制。
22. 作为创作者，我希望保存前能看到即将保存的内容和适用范围，以便模糊指代不会存错。
23. 作为创作者，我希望能查看自己的长期偏好，以便知道后续建议的依据。
24. 作为创作者，我希望修改、删除单条或清空长期偏好，以便调整已经改变的习惯。
25. 作为创作者，我希望说“这次不用我的偏好”而不删除它们，以便尝试新方向。
26. 作为创作者，我希望当前明确要求优先于长期偏好，以便新任务不会被旧习惯绑住。
27. 作为创作者，我希望使用偏好时有简短说明，以便知道画面为何采用该方向。
28. 作为创作者，我希望明确文案、商品事实与禁止项不被当成通用审美偏好，以便跨项目不传播错误内容。
29. 作为创作者，我希望更换商品图后只沿用仍适用的审美倾向，以便旧图的材质和品牌不会被带入。
30. 作为创作者，我希望删除偏好后后续建议不再自动引用它，以便清除操作真正生效。
31. 作为创作者，我希望账号切换、退出和多标签页操作不会串用偏好，以便账号之间保持隔离。
32. 作为创作者，我希望记忆服务失败时仍能手动继续创作，以便非必要功能不阻断制图。
33. 作为创作者，我希望选择示意或保存偏好都不会跳过提示词确认，以便始终知道实际发送的内容。
34. 作为创作者，我希望历史结果和执行快照不因偏好修改而改变，以便过去的作品仍可追溯。

## Implementation Decisions

- **按三个增量串行交付。** P2-A 构图／色调示意 → P2-B 项目偏好摘要 → P2-C 用户主动保存的账号偏好。分别验收、前一项通过再继续；P1 为整体前置。本规格是一张 P2 功能票的完整范围，三个增量不是替代 v3 的 R1 → R2 → R3，也不代表前置架构阶段已经通过。
- **示意使用程序绘制。** 首版以受限、确定性的布局与色板描述生成本地 SVG／CSS 图形，产品以明确占位形状表达，文字用区块表示，避免伪造商品细节或承诺实际字体效果。不调用生图供应商，不下载示例图库，不建设付费示意生成路线。非专业用户只看到可理解的构图内容。
- **示意不是新流程。** 在现有问题投影上增加可选的方向示意描述，绑定同一 question_id、option_id、requirement_revision 和消息；只有当前问题可选择。仍遵守每轮一个主问题、最多三个选项（通常两种方向加委托）、已有探索预算和唯一输入框。需求已明确、纯讨论或用户跳过时不强制展示。
- **示意描述由程序校验。** 仅接受主体位置及占比、留白／文字区域、背景与强调色、简短标题和替代文本等有限数据；几何在标准画布范围内，颜色与枚举受限，文本按普通文字处理。模型继续自然 Markdown 交接，可以提出建议；程序从已明确的需求与方向生成描述，不要求模型输出固定 JSON 状态包或可执行 SVG／HTML。无法形成有效描述时回退现有文本选项。
- **不新增输出能力。** 示意画布采用本轮已支持的输出比例；用户选留白、色调或用途不能改变实际支持的尺寸和数量。图中始终显示“构图示意，非生成结果”，并解释“只表达布局与色调，不代表商品细节或最终效果”。不作为已发布图片资产，不混入结果历史或下载清单。
- **示意持久化并保持稳定。** 保存方向描述、渲染版本和问题绑定，刷新用同一描述重绘，不随机重排或重新调用模型。历史示意只读；选中方向与自由补充共同进入需求来源。A/B 与当前问题一致，过期选择沿用现有过期处理。
- **偏好边界尽量集中。** 项目摘要、账号偏好管理与本轮有效偏好解析由一个偏好上下文边界负责，供现有需求构建读取；对外仍通过现有聊天消息／动作与工作流投影操作，不建立独立记忆工作流或第二个创作输入入口。
- **项目摘要是现有需求的可解释投影。** 摘要只纳入本项目用户已选择或明确表达的审美倾向，标明来源消息／版本、适用范围及是否仍有效；不把助手默认、未选建议和旧图观察升级为用户偏好。多轮之后用简短去重摘要呈现，无新变化不重复弹出；用户主动询问时可随时查看。重复次数不构成账号记忆授权。
- **偏好类别首版收窄。** 只保存背景／色调、产品突出程度、留白及文字密度等可解释的审美倾向。不保存商品身份、品牌、材质、价格、规格、功效、准确广告原文、图像文件或账号敏感信息；禁止项和本项目硬要求继续由需求系统管理。参考图观察不能直接成为长期偏好。
- **跨项目采用明确选择。** 用户要求“记住这个”“以后都这样”且内容和范围清楚时可直接保存，回复具体保存了什么；缺少明确指代则先展示候选内容并用原问题机制澄清。界面提供明确的“保存为我的偏好”动作。多次点击、单次方向选择、默认接受、自动总结及沉默均不触发保存。
- **账号偏好需要真实持久化。** 在后端业务数据库新增账号归属的偏好记录，包含稳定标识、类别、可读内容、适用范围、来源关联、版本及时间；保存与更新均校验登录主体、来源可访问性和预期版本。通过正常迁移创建，旧账号默认为空，不从历史消息批量推断。迁移与测试数据均遵守仓库目录边界。
- **管理操作沿用稳定请求标识。** 查看、保存、修改、删除、清空及本次不用通过现有会话中的领域动作表达，列表或摘要返回当前版本和可用动作；写操作重复请求幂等，旧版本冲突返回当前状态。跨账号 ID 不能读取或修改，多标签页的晚到响应不能复活旧值。
- **生效优先级明确。** 当前用户明确要求与本轮修改最高；其次是当前项目已明确的需求和限制；最后才是用户已主动保存且适用的账号审美偏好。账号偏好作为建议默认，不成为硬约束或审查否决条件。优先级不足以解决用户自身的硬冲突时仍须提问。
- **应用时可以解释。** 需求上下文记录实际采用的偏好标识、版本、范围和来源，向下游提供可读摘要；聊天仅在新采用或改变时简短说明，例如“沿用你保存的浅色、少道具偏好，这次的深色要求优先”。没有有效偏好时按原流程继续，不添加无意义的记忆提示。
- **本次不用与清除区分。** “本次不用我的偏好”只关闭当前制作／修改轮次自动注入账号偏好，不删除账号记录，绑定该轮次并持久化可恢复；同一轮次的刷新、恢复或重新编制不能悄悄恢复注入，“本次恢复使用”重新启用。下一次独立制作请求默认按有效账号偏好解析，不把一次跳过变成永久禁用。“清空我的偏好”清除账号记录；项目内明确需求保持为本项目需求，用户要同时调整时按普通需求修改处理。
- **删除阻止后续复用。** 删除后不再把相应条目注入未来上下文，不通过历史摘要或回放自动重建为账号偏好。历史聊天、已确认需求和已执行快照作为过去的事实保持可读；管理界面明确区分“已删除的记忆”与“历史消息”。未来只有新的明确保存动作可以重新建立同类偏好。
- **快照保持不可变。** 更改偏好不自动重写当前待确认提示词或已提交请求。用户明确要求把偏好变动应用于当前方案时，以新的需求版本准备提示词并使旧确认失效；已提交任务只记录后续修改，不变更执行快照。删除记忆后，旧提示词内容如需改变仍由用户在当前任务明确修改，不能假装历史从未采用过该偏好。
- **故障与账号生命周期。** 偏好不可读时明确说明未能沿用，继续人工表达，不伪称已经保存或清除。管理写入失败不更新界面为成功；退出、切号、会话失效和晚到请求沿用现有身份隔离与取消规则，前端不以本地缓存作为账号记忆的真相。
- **图片执行规则保持不变。** 渲染示意、选择方向、查看摘要、保存／删除偏好都不是最终图片授权；有制作请求时可以继续准备提示词，每次图片提交仍须展示完整可编辑提示词并等待最终点击。刷新、应用偏好、恢复和默认推荐均不能补授权。

## Testing Decisions

- **主要测试边界继续使用 P1 的真实 HTTP 对话／动作链路。** 在临时数据库与资产存储中模拟用户消息、方向选择、偏好管理、切换项目、准备和确认；供应商只替换现有适配器。验证可读投影、持久化状态、下游可读上下文、实际提示词和图片提交次数，不测试内部函数调用顺序或模型措辞。
- **示意额外验证可见行为。** 在现有聊天组件测试中检查“构图示意”标签、文本替代、选择绑定、刷新稳定、键盘访问和唯一输入框；有效与无效描述均从公开响应进入。真实浏览器覆盖 320／768／1440 CSS 像素，比较主体、文字区、留白和色调是否可辨，不依赖整页像素快照作为唯一断言。
- **沿用的测试先例。** P0 的问题与选项恢复、P1 的目标与来源绑定、现有 Markdown 原文交接、可编辑提示词确认、账号项目隔离及跨标签页历史测试提供装置；P2 扩展这些测试边界。真实临时数据库覆盖新增迁移及旧账号空状态；不为记忆引入独立测试框架。

| 验收场景 | 可观察的通过条件 |
| --- | --- |
| 比较主体大／小、文字多／少、浅／深色 | 方向图与文字解释一致，示意标签及文本替代可读 |
| 展示、重绘或选择示意 | 图片供应商提交为零；选中方向进入同一个需求与问题绑定 |
| A 加自由补充、全部不喜欢、委托、跳过 | 不丢自由表达；不强制新流程；沿用探索预算与当前问题 |
| 刷新、失效问题、非法示意描述 | 同一示意稳定恢复；旧选择拒绝；无效描述回退文本且无图片调用 |
| 清晰需求直接制作 | 不强制看示意；准备提示词并等待最终确认 |
| 单次选择及多次重复选择 | 仅改变项目需求／摘要；账号偏好仍为空 |
| 主动保存与指代不明的“记住这个” | 明确内容才能保存；含糊先问；回复内容与持久化记录相符 |
| 新项目采用与当前要求冲突 | 仅采用已主动保存、适用的审美偏好；当前明确要求优先，硬要求不被软偏好替代 |
| 本次不用、恢复使用、修改、单条删除与清空 | 各自作用域明确且刷新后有效；删除不从历史自动重建 |
| 两账号、会话失效、跨标签页并发 | 无串用、无越权读写；晚到和冲突响应不覆盖最新状态 |
| 存储失败及旧账号迁移 | 不虚报管理成功；旧账号为空；手动创作仍可继续 |
| 改偏好后查看历史／现有提示词 | 历史与执行快照不变；用户要求应用到当前任务时更新需求并使旧确认失效 |
| 偏好应用后最终确认 | 实际请求保留用户确认的提示词原文，确认前零提交，重复点击仅提交一次 |

- P2-A 的通过条件是示意可辨、选择与来源可靠且零额外图片调用；P2-B 是项目摘要无捏造、无跨项目传播；P2-C 是保存授权、管理、删除与账号隔离均可恢复。前一增量未通过不进入下一增量实施。
- 实施完成从仓库根运行 `npm run check`，将新核心用例纳入入口；新增账号存储和迁移时运行完整后端套件。测试、临时数据库和视觉证据置于项目本体目录外。
- 真实用户观察延续原规划建议的小规模任务：比较文字与示意是否更容易选方向，检查用户能否说清记住了什么、能否更改或清空。记录主观任务符合度和理解成本，不以点击率或提问变多宣称效果提升；样本不构成统计显著性结论。

## Out of Scope

- 付费样图生成、新示例图库、远程素材抓取、商品写实预览、对最终画面效果的保证。
- 全量历史学习、隐式账号画像、自动跨项目记忆、商品事实记忆、团队共享偏好和跨账号同步。
- 向量数据库、通用长期记忆平台、推荐排序或机器学习训练。
- 新输出尺寸、多图批量、适配器编辑能力升级、历史分叉和独立创作页面。
- 绕过每次提示词最终确认、重启旧阶段审批、生产发布或无关架构清理。

## Further Notes
