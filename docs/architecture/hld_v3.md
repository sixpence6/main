### 1.2 串行门槛

```text
C0 基线／安全清理／数据来源核验
  → R1 账号身份、项目归属、内容双重门禁
  → R2 单次授权、原子受理、额度与持久化恢复
  → R3 账号生命周期、纯对话工作台与内联交付
  → V3-Release 局域网 HTTPS、备份恢复演练、完整验收
```

- **前置验收。** 前一 R 阶段的门槛无失败／未知后，才开始下一 R 阶段的实现与集成。每阶段内部按可演示纵向切片推进；横跨阶段的能力由后继补齐，不能提前标为完整通过。
- **持续安全。** R1 接通入口时即配置默认拒绝、来源校验和私有响应保护；不是等最终发布才补安全。R1—R3 开发验证限隔离环境，正式局域网入口须通过 V3-Release。
- **真实数据。** 任何真实迁移、认领、数据根切换先核验来源、验证备份；冲突由维护者选定。来源尚未确认时可用独立临时数据库开发，不能处理原库。
- **完成证据。** 每阶段保留变更清单、测试命令／结果、路由覆盖与残余问题。文档、issue 关闭、编译成功均不能单独替代行为验收。

## 2. 系统设计与现状差距

### 2.1 保留的形态

单台服务器、单个后端工作进程、FastAPI／Vue／SQLite 单体继续使用；实例可编排多个任务，不等于启用多个后端进程。现有供应商 adapter、测试替身、短写事务、不可变快照、独立审查和原子发布继续复用。引入新依赖需写入唯一运行依赖清单及锁文件，通过目标设备检查。

```text
浏览器：登录／个人账号／管理视图 + 账号上下文内的连续工作台
                         │ 同源 HTTPS；安全 Cookie + CSRF
受控入口：TLS、Host／Origin、可信代理、静态构建资源
                         │
HTTP 薄入口 → R1 身份／项目访问 → R2 确认与受理 → 既有工作流及模型 adapter
                  │                    │                   │
             账号／会话／审计      意图／账本／槽位       审批／发布
                  └────────────────────┴─────────┬─────────┘
                                            SQLite + 私有文件
维护者本机：初始化／管理员恢复、来源核验、备份／受控恢复；无普通网络入口
```

管理员管理账号、额度与必要诊断，不因此获得他人创作读取权。服务器维护者属于受信任主机操作者，与应用管理员权限区分。

### 2.2 三个深 module

| Module | Seam 与 interface 承诺 | 隐藏的 implementation |
|---|---|---|
| R1 项目访问 | 在装载业务对象前取得有效主体与本人项目；按动作返回安全结果或统一拒绝 | 会话、归属、对象关联、状态重验、内容门禁组合、错误收敛 |
| R2 生成受理 | 一个确认命令返回原／新稳定意图或明确拒绝；查询／恢复不等于提交 | 原子确认、幂等、计数、槽位、执行尝试、未知状态与结案 |
| R3 工作台投影 | 当前账号生命周期内提供当前创作状态、历史预览和实际可用动作 | 迟到响应过滤、缓存清理、恢复元数据、revision／交付状态解释 |

调用者不再重复拼接同一组规则。删除 module 后，相关复杂度会回流到多个调用者，才说明它有 depth；仅增加转发层不算深化。不引入微服务、Redis、队列、通用 Repository、授权引擎或新的工作流框架。

## 3. C0：清理与布局收敛

### 3.1 先分类，再删除

“干净”指生产源码只有活路径、发布包只含必要运行内容、验证资产在开发区；**不是测试数量归零**。执行每个候选前查静态引用、动态加载／路由注册、构建与测试入口、迁移和文档用途；不确定即保留并记明原因。

| 类别 | 处理规则 | 证明要求 |
|---|---|---|
| 无引用旧源码、纯占位脚手架 | 确认无运行／测试／动态消费者后删除；同步去除废弃引用 | 类型检查、构建、对应行为回归保持有效 |
| 测试源码与测试替身 | 保留仍验证需求的用例；重复／过时断言随替代路径更新或合并 | 需求覆盖无缺口；不用删失败测试让构建变绿 |
| pytest 运行副本、缓存、编译缓存 | 核验绝对路径、非业务数据、非外部链接后删除；配置忽略或专用临时根 | 明确清单、受限删除；可重新生成 |
| 两套配置、依赖锁、Docker 与启动脚本 | 先确定唯一生产入口，再让开发命令引用它；行为等价后删除复制件 | 本地／容器的配置、import、迁移 head、资源目录一致 |
| `.env`、数据库／WAL、历史图片、备份 | 受保护资产；与源码清理分开处理 | 维护者选来源、验证备份、明确回退；本轮不搬移／删除 |
| ZIP、验收证据、本机工具配置 | 区分交付物、历史证据和凭据；凭据放版本控制排除 | 不随发布包打入，已有独有文件不自动销毁 |

### 3.2 目标目录职责

- `main/`：生产前后端源码、必要运行依赖／锁、迁移、部署配置、配置示例；不放开发测试、测试替身、临时脚手架或评审报告。
- `tests/`、`backend/tests/`：当前前后端开发验证区；保留可运行入口。无需为整齐先迁移全部测试目录。
- `docs/`、`vesion/`：设计、追溯与需求；`.scratch/`：显式隔离的临时验证产物。
- 生产目标收敛为 `main/` 的自包含入口；根目录兼容入口逐步改为引用／转发，最终移除重复运行配置。**这是一项待验证的布局迁移，不是本轮自动删除根 `backend/` 的依据。**
- 实际数据根由受控配置及维护者来源清单确定，不因目标目录改变而自动改库。`node_modules`、虚拟环境、缓存、测试和秘密不进入最终运行镜像／分发物。

### 3.3 分阶段清理

C0 清理已证实的无引用代码和运行残留，记录基线。R1 替换存在性访问和匿名业务分支后删除旧分支；R2 统一受理后删除旁路提交／重复计数；R3 替换旧页后删除四阶段导航及失去消费者的样式、状态和测试夹具。每批先建立替代行为，调用者迁移并回归后再收缩；数据库升级历史和 v2 内容门禁继续保留。

**C0 门槛：**受保护资产和用户原有改动已区分；保留测试可运行；删除项有证据。全量旧布局清理未完成要如实列残项，不阻止隔离环境开发，也不宣称发布布局已收敛。

## 4. R1：账号身份、项目归属、内容双重门禁

### 4.1 持久化与职责

新增账号、会话、一次性凭证、最小安全审计和必要限流事实；在项目上建立唯一所有者关系。子对象通过可信项目关系继承，不为每张业务表重复造权限模型。未认领项目不可服务；操作者 ID 与归属分开，历史操作者未知就保持未知。

账号使用不可变 ID、统一邮箱规范化、待设置／可登录／禁用状态；禁用与激活资格分开保存，恢复不能让未激活账号直接登录。本机首管初始化以事务／唯一初始化事实防并发重入，密码不回显；首管恢复同样仅本机受控操作。

使用 `argon2-cffi` 的 Argon2id implementation，显式指定 SRS 成本，不能依赖库默认值。安装版本及传递依赖在 R1 锁定并核验；库缺失／校验异常安全失败。密码原文不修剪、不截断、不进行未声明的 Unicode 规范化；本地弱口令表随实现版本化。

### 4.2 Interface 行为

1. **身份。** 由服务端不透明会话解析当前主体；每个受保护请求重验有效状态。按 SRS 设置 Cookie、空闲／绝对时限和撤销；轮询不续空闲。退出撤销当前，改密／重置／禁用撤销所需全部会话及凭证。
2. **请求。** 登录／链接消费也有预认证 CSRF 上下文与可信来源核验；认证后变更使用会话绑定上下文。预认证上下文只授予对应表单用途，不取得业务权限。GET 不做业务变更，返回地址限同源。
3. **归属。** 先认证，再按本人项目过滤／校验，再检查关联对象与动作，最后组合既有内容门禁。列表先过滤再排序／分页／计数；管理员创作同样适用。变更在提交事务重验状态与归属。
4. **全出口。** HTTP、后台、找回、历史、预览／缩略图／下载和原始字节执行相同规则。构建资源与私有文件分离；文件路径由核验对象解析，不能把 locator 或旧静态路由当公开资源。
5. **错误。** 未认证、非管理权限和他人／不存在对象按 SRS 区分安全类别；本人待审／撤销／缺失仍显示真实内容阻断。客户端的角色／所有者／批准字段不参与授权。
6. **链接。** 签发绑定用途与可信应用地址，仅展示一次原文，服务端仅留摘要；新签发撤销旧链接。GET 不消费，POST 原子更新密码、消费凭证、撤销会话；成功后正常登录。页面无第三方依赖、无凭证日志及 Referer 泄漏。
7. **审计。** 建号、凭证、状态、撤销、认领和本机维护的敏感变更与审计一致提交；写审计失败就回滚该变更。用户仅看本人必要事件，管理员诊断不含他人正文或秘密。
8. **后台。** 先在当前任务中持久化真实所有者与既有授权关联；退出／过期不取消原任务，每次新增模型调用及发布前重验账号。禁用后隔离远端返回；恢复账号不自动继续调用。R2 再接入统一受理意图。

### 4.3 技术资源预算

下表为本 HLD 选定的首版技术默认值，不是对 SRS 产品参数的改写。R1 需将其落入可配置实现与边界测试，并提交目标设备哈希耗时／内存证据；未满足预算则阻断正式发布，调整要记录原因。

| 项 | 默认与执行方式 |
|---|---|
| 密码有限上限 | 128 个 Unicode 码点；最短及哈希成本仍取 SRS；UTF-8 编码后校验体积，不修剪 |
| 认证 JSON 请求体 | 16 KiB；边读边限制，超限在哈希前拒绝；上传另沿用现有独立上限 |
| 登录失败 | 规范化账号 5 次／15 分钟；可信来源 30 次／15 分钟；任一维度到限即拒绝 |
| 链接签发 | 授权管理员 10 次／15 分钟，目标账号 3 次／30 分钟；先鉴权再计限流 |
| 链接提交验证 | 凭证摘要 5 次失败／15 分钟，可信来源 30 次失败／15 分钟 |
| 哈希计算 | 同时最多 2 个、待执行最多 8 个；超过立即受限，不占数据库长写事务；未知／禁用／未激活走等价 dummy 校验 |
| 限流存储 | SQLite 中的有界时间窗口记录；每类窗口最多 20,000 条有效桶，先清过期；满时安全拒绝，不驱逐有效桶来放行 |
| 重试指引 | 返回安全限流信息与服务端计算的可重试时间；不永久锁账号，不泄露账号是否存在 |

哈希在短写事务外执行，提交前核对账号／凭证版本，防止并发改密或禁用竞争。来源只取连接信息或明确受信任代理链；任意客户端头不改变限流身份。

### 4.4 迁移与门槛

真实认领先核验配置、挂载、库／WAL、引用文件和备份；由初始化管理员明确接收指定范围。重复认领幂等，失败回滚／保持隔离，不批准旧内容、不改历史快照、不伪造历史授权。新账号为空工作区。

最小登录、账号管理、本人会话／安全视图随 R1 提供可操作路径；品牌视觉、完整布局和浏览器生命周期由 R3 完善。R1 完成要求：账号及服务端会话行为、权限矩阵每个组合、全部已注册业务出口／资源字节、后台禁用、认领与原子审计都有证据。R1 未包含的浏览器／额度场景保持待验收。

## 5. R2：单次授权、原子受理与恢复

### 5.1 分开三个事实

- **生成意图：**一次明确创作／修改动作的受理，绑定真实操作者、所有者、项目、revision、最终需求摘要、参考用途／依赖、尺寸和稳定请求标识；快照不可变。它授权有预算的提示词准备，不单独授权提交图片。已批准提示词的最终执行确认是同意图下另一个持久化事实，不另受理或计数。
- **执行尝试：**原意图下的提示词编制／审查、生图提交及供应商结果观察；有提交证据、结果未知、明确失败等区别。已有 `Generation`／`GenerationJob` 按职责关联，不按表名再造重复事实。
- **内容交付：**独立的质量／审批／摘要及发布事实；文件落盘或供应商返回不是发布。

受理账本、用户／实例／项目槽位及恢复状态持久化。`RevisionBudget` 仍是内容候选预算，不当成个人生成次数；内存锁仅作进程内协调。

### 5.2 一次受理，两个不同授权事实

确认契约以[prompt-confirmation-v3](prompt-confirmation-v3.md)为唯一技术细化入口，不从浏览器串联旧“确认→编制→提交”接口模拟停点。

1. 明确创作／修改且需求齐备、最终需求已获独立批准后，在 S06 → S07 的 seam 受理提示词准备。问候、解释和暂缓不受理；普通读取不调用模型。需求缺项只在原对话澄清，不恢复复杂确认表单。
2. 沿用短写事务：重验主体、归属、revision、完整需求／参考／尺寸快照；相同请求和参数复用原意图，异参拒绝；新意图原子写受理、一次计数、个人／实例／项目占用及审计。事务内无模型等待。
3. 提交成功后只允许 S07 编制和独立审查。在 S07 → S08 之间持久化已批准的实际执行提示词与待确认快照；后台必须在这里停下，不能自动创建图片执行尝试。
4. 原对话默认全文展示本次真实提示词、实际发送的负向内容、参考依赖及输出要求。最终“确认使用以上提示词生成”命令核对当前登录上下文、操作者、项目、意图、需求、批准、提示词和执行参数，在同一短事务记录授权与唯一执行尝试；消费原意图，不重复计数／占槽。
5. 图片执行只读取被确认的不可变请求；不在点击之后重新编写、替换或补入未展示的业务提示词。账号、批准或依赖变化均安全拒绝，重新准备和展示后才可最终确认。
6. 等待、刷新、轮询、重新登录和重启不穿透停点。已提交或提交事实未知时仅核实原任务；无证据不得重发。技术修复不能把“准备授权”升级成“图片授权”。

SQLite 仍使用 `BEGIN IMMEDIATE`、唯一约束与持久化账本，内存锁不是竞争证明。每个新增事实写点均需故障回滚测试，独立连接覆盖最终确认、失效与重放竞争。旧动作和恢复入口不能保留绕过最终确认的兼容分支。

### 5.3 计数、占用与人工结案

| 结果 | 次数 | 活跃占用／后续行为 |
|---|---|---|
| 校验／额度拒绝、事务失败 | 不增加 | 不占用、不暗中排队 |
| 明确准备动作的新意图成功受理 | 增加一次 | 原子占用户／实例／项目槽位；之后才可编制提示词，不可提交图片 |
| 提示词已批准、等待最终确认 | 不再增加 | 保留原占用；无图片执行尝试，不因等待超时自动释放或生成 |
| 最终确认同一提示词快照 | 不再增加 | 沿用原占用；原子保存执行授权与唯一图片执行尝试 |
| 同意图重放、只读核实、恢复／找回原结果 | 不增加 | 延续原事实，不自动创建新任务 |
| 受理后明确终态失败或完成 | 保留一次 | 依据已证实的本地终态一致释放，不回退次数 |
| 远端结果未知、重启缺证据 | 保留一次 | 保守保留待核实状态及占用，不能仅凭超时释放后自动重发 |
| 有审计的本地跟踪结案 | 原计数不变 | 按 v2 核实／结案规则更新占用；明确不代表远端取消 |
| 明确风险确认的不同新任务 | 新计一次 | 重新核验全部限额和单项目限制；风险确认不是绕过槽位 |

滚动窗口使用服务端 UTC、统一毫秒时间精度，计数区间定义为 `(now - window, now]`；恰在下界的历史受理退出窗口。禁用、调低额度、跨零点、重启均不改历史计数；配置改动有原子审计。默认值只读 SRS 第 12 节，管理员自身无豁免。

### 5.4 内容门禁修订的接入

规则目录与裁决语义归 R1 内容边界；原意图修复、完整执行快照及正常／S12 一致性由 R2 接入，R3 消费安全原因与可用动作。具体规则只在[门禁与工作流 v3 第 1—5 节](workflow-gates-v3.md)维护，不让调用者分别解释建议、N/A 或错误文案。保留账号／归属、明确授权、幂等、候选预算和原子发布保护。

按该设计第 6 节先统一规则，再修原意图恢复与快照，最后接前端。顺序不改变 R1 → R2 → R3；新发现影响已通过门槛时复验受影响项，不能靠新增文档或旧阶段结论跨过失败／未知。逐角色审查合并仍是待评估候选，不包含在本次修订的默认实施授权中。

### 5.5 门槛

先通过真实 interface 证明提示词准备、批准读取、持久化等待、最终确认与本人用量／限额，不等待 R3 样式改造才证明后端停点。每个事务写点故障回滚，跨连接竞争、重复点击／丢响应／跨标签重放、提示词失败计数、远端未知／进程退出／重启不重发均通过；既有内容审批和原子发布回归通过后才能进入 R3。新增门禁验收 V3-AC-41—44、46 按主责完成相应后端证据，候选修复须同时断言原意图、计数、预算和外部调用。

## 6. R3：账号生命周期与连续工作台

### 6.1 先隔离，再替换导航

先在现有布局建立已核验账号上下文，再收拢投影与替换页面。上下文至少包含稳定账号、登录生命周期版本、项目和请求序列；同账号重新登录也生成新生命周期。

所有异步成功、失败、结束回调匹配完整上下文后才写状态；abort 仅节省资源，不作隔离证明。401 收敛为应用会话失效，403 为应用权限拒绝，供应商故障使用独立安全代码，不再混为模型配置错误。

显式退出、切号、其他标签页身份变化清理列表、查询缓存、草稿、勾选、临时图片 URL 和旧恢复引用；标签页消息仅传播失效信号，不传凭证／业务正文。浏览器返回先核验身份。未发送内容只留页内存，不能在未核验身份时显示。

恢复元数据按账号及项目隔离，只保存最小非秘密标识；无账号的旧键不自动认领。重新登录只查询原意图，任何模型调用仍需 R2 的有效授权和实际可用动作。

### 6.2 三个用户状态与纯对话投影

| 状态 | 后台事实 | 用户操作 |
|---|---|---|
| U1 描述与完善 | 新需求、实质修改或阻塞信息待补；必要需求产物逐项审查 | 在唯一底部输入框说明、补充和发送图文；交流不暗中创建需求版本 |
| U2 准备、待确认与执行 | 原意图准备提示词 → 已批准提示词持久化等待 → 明确最终确认后执行、审查与发布 | 全文核对真实提示词并点击“确认使用以上提示词生成”；执行期间只显示一条轻量状态和实际可用恢复动作 |
| U3 查看与调整 | 当前需求的图片已发布且可访问 | 图片追加在原对话；放大、下载和回看历史只读；实际发送实质修改才回 U1 |

新外壳由直接可达的本人会话侧栏、对话标题、唯一消息流和固定图文输入组成。不复用或隐藏旧需求表单、用途下拉、复杂确认卡、工作流／任务面板或阶段导航来冒充重建。登录与账号页面不重做；必要用量与说明保留为轻量入口。

生成不另建会话，新图片不覆盖旧消息，不自动进入独立成果页。旧阶段／成果 URL 仅在权限成立后定位原会话或对应历史结果；定位与放大、下载均不改变修改基准或调用模型。提示词和图片关联各自历史快照，不能用当前需求解释旧图。

新建、全量本人标题搜索、切换与重命名使用现有项目服务，不造本地业务数据库。所有读取、消息、图片、搜索、附件及提示词操作匹配账号、登录生命周期、项目及请求序列；页面恢复不代表生成授权。具体视觉、附件、焦点与安全原因交接只维护于[前端设计 v3](frontend-design-v3.md)。

### 6.3 登录、账号与清理门槛

品牌登录、密码显示／隐藏、联系管理员指引、设置／重置、本人会话／安全事件及管理账号／额度界面完整衔接。参考视觉只按 SRS 已确认描述本地实现，不重新依赖参考站资源；无假注册、邮件发送或充值业务。

替代工作台及回归通过后，再删除旧四页必经导航、旧右侧布局／独立反馈输入、旧状态计算和确实无消费者的展示／恢复代码；复用中的业务逻辑保留，外部旧 URL 只做无副作用兼容，不能重放动作。迁移旧测试为新用户行为断言，保留权限、恢复、历史隔离、键盘／输入法和防重发覆盖。

**R3 门槛：**后端 MV3-05—09 与受影响 R1/R2 先有当前证据；A→B→A、同账号重新登录、跨标签与迟到回调不串数据；提示词默认全文、旧确认失效、图片追加及历史绑定正确；无旧面板、独立成果切换或自动跳转；搜索／重命名真实且隔离；320／768／1440 CSS 像素、实际手机软键盘与中文输入法可操作；读取和导航不增加模型调用。按前端设计 FE3-AC 与 modify_v3 的 MV3-01—14 逐项举证，不以截图或旧测试通过替代新契约。

## 7. V3-Release：正式运行能力

### 7.1 局域网受控入口

只公开可信 HTTPS 同一应用源；允许监听／Host／Origin、可信代理链、防火墙和局域网地址显式配置。后端端口、数据、备份、API 调试／诊断入口不得成为旁路。开发 HTTP 只在显式回环模式可用；正式入口无需浏览器绕过证书警告。

验证安全 Cookie、CSRF、`no-store`、同源返回地址和 CSP；安全渲染不可信文本，沿用文件解码／体积／路径及远端 locator 限制。启动依赖／鉴权／审计／归属不可证时，按职责停止受影响能力，不能回退匿名服务。密钥及 TLS 私钥经维护者受限配置提供，管理网页不读回原文。

### 7.2 一致备份与受控恢复

备份 module 共用于迁移前回退点和周期备份。服务运行期间到期执行，启动补做，保留与轮换以 SRS 参数为准；本机受限输出，网页无整库下载。

首版一致性方案：进入维护协调、短暂停止业务写入及文件发布／到期删除，完成在途提交的收敛；对明确数据源执行 SQLite Online Backup，复制该数据库快照所需的不可变文件，写摘要／完整性清单，在独立目录校验恢复后才标记备份可用。控制窗口须有超时／失败退出，完成前不轮换旧备份。不能把“数据库快照成功”当成跨文件集合已一致；不得仅复制写入中的主库文件。

恢复先停写、验证备份、保留当前回退点，在隔离位置检查库结构、归属、引用文件和审批关联后切换。撤销恢复出的全部会话／一次性凭证，按原时间执行过期规则，不复活批准。原意图／计数／占用保持保守；快照后存在账本缺口时阻断新生图，直到完整窗口结束或维护者有审计地核实。恢复及重启不自动补发模型请求。

### 7.3 运维与保留

交付唯一启动／数据源说明、TLS 信任及更新、防火墙、管理员初始化／恢复、周期备份／恢复与故障步骤。账号安全审计、普通日志、终态未发布图按不同保留规则执行，启动补执行到期；已发布图、参考依赖、审批证据和未认领旧资产不被普通垃圾清理扫除。

权限最小化、依赖／秘密检查、真实供应商内容门禁回归及另一台局域网设备验证通过，才允许正式开放。代码／HTTP 桩通过不等于真实 TLS、真实模型或多设备验收通过。
