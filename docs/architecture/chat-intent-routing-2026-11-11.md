# 对话意图路由行为契约（2026-11-11）

状态：本次意图路由修复已于 2026-11-12 完成代码审查、组合检查并合入本地 visual/v3；不代表 v3 整体发布或真实服务人工验收。遵守 HLD v3 的 R1 → R2 → R3 串行验收。实际证据见[验收记录](../acceptance/chat-intent-routing-2026-11-11.md)。

## 消息入口与制作授权

新会话先 `POST /api/projects`，然后把首条正文发送到 `POST /api/projects/{id}/messages`，与后续消息共用分类路径。正文使用 `content`，携带 `expected_revision` 和稳定的 UUID `request_id`。前端不得自行把首条正文转为 `submit_request`。仅助手消息 `turn_kind=workflow` 可让前端自动推进已授权准备动作；`conversation`、`prompt` 不触发自动推进，延迟刷新也不能补授权。

闲聊后仍复用已创建项目，即使响应 `workflow=null`。创建项目不等于发起制作。

| 输入及上下文 | 应有行为 |
| --- | --- |
| 新会话中的“你好”“谢谢”“你能帮我做什么”“我们先讨论一下背景风格” | 自然回复；不建立制作授权，不凭空填商品需求 |
| “帮我做一张米色托特包电商主图，极简冷白背景，不加文字” | 启动需求与提示词准备 |
| “米色托特包电商主图，极简冷白背景，不加文字” | 无制作动词仍是有效商品图需求 |
| “你好，帮我做一张钢笔宣传图，极简冷白背景” | 保留明确制作意图，不能因包含问候而拦截 |
| “制作钢笔主图，极简冷白背景，文案为你好” | “你好”是图片文字，仍进入准备流程 |
| 没有当前待答审美问题时，“我觉得冷白背景比较适合钢笔主图” | 是意见表达；即使含商品和图片名词、模型返回 ready 完整 brief，也只回复对话 |
| 等待提示词时“我喜欢这个背景” | 保留同一提示词快照、制作意图、额度和确认可用性 |
| 生成中“我很喜欢这个文案” | 只回复对话，不记录为待执行修改意见或追加 pending_feedback |
| “你可以帮我做一张钢笔主图，极简冷白背景，无文字” | 是礼貌提出的明确制作请求，进入准备流程 |
| “制作钢笔主图，极简冷白背景，文案为为什么选择我们” | “为什么选择我们”是图片文案，不能按疑问或讨论拦截；文案原文保留 |
| “先别生成，讨论一下钢笔主图的背景” | 保持讨论，不调用画面规划、提示词编写或图片提交 |

分类必须依据整句语义、当前问题和已有授权，不能仅使用问候黑名单，也不能凭商品、背景、文案等名词就推断为任务或待执行反馈。模型返回 `image_request/ready` 或完整 brief 也不是用户授权；程序必须兜底阻止闲聊推进制作。

## 全生命周期不变式

新会话、S03 待澄清、等待最终提示词确认、正在生成和生成完成五个上下文中，问候、感谢、能力询问、纯讨论、意见表达和赞赏只增加对话消息。不得调用 `visual_planner`、`generation_engineer` 或新增图片提交；不得修改已保存 brief、待答问题、generation intent、prepared snapshot、job、计数和占用。

明确的暂缓指令（如“先讨论”“我们先讨论一下背景”“请先讨论”）在已有 `requested` 制作意图时不属于状态不变的纯讨论：须将 generation intent 保存为 `paused`，后续普通字段回答不能恢复准备，需用户重新明确请求制作。新会话没有待暂停的制作意图，以上措辞只回复对话且不建立 intent。普通讨论（如“我们讨论一下背景风格”）在新会话或已有制作上下文中都只新增对话、不改变已有意图；图片文案中的暂停词仍是数据。

S03 闲聊不消耗当前问题，问题内容及其 `question_id/message_id/requirement_revision` 绑定保留。等待提示词时闲聊保留同一 snapshot 的全文、ID、digest、command_context 和确认可用性；用闲聊前的确认上下文仍能确认该快照。生成中测试用受控图片适配器暂停提交，隔离任务自然完成造成的状态变化。模型已经返回 conversation 时也必须满足这一保护；程序不能仅因“文案”等名词存在，就把赞赏写入 pending_feedback。

测试比较工作流投影、项目制作字段、持久化 requirements JSON、artifact、job、intent、usage 行；允许消息及更新时间变化。额度视图中随墙钟滑动的窗口起止显示值不作相等比较，真实 usage 记录与额度数字仍必须相等。

## 澄清及最终确认

- 正在询问背景风格、允许自由输入时，“我喜欢冷白背景”“我觉得冷白背景比较适合钢笔主图”包含具体字段值，是有效审美回答，应更新需求并继续准备；同样的偏好表述在等待提示词时仍是对话，不能自动修编制。模糊的“我喜欢这个背景”未提供具体字段值，在待答审美问题下也保持对话并保留问题。当前问题的实际字段回答不能一律按闲聊处理。
- 有效审美问题的绑定选项回答 `A，但别太暗` 必须接受，并保存选项含义及补充约束；不能要求正文只能是单字母。
- 缺商品时，“钢笔”等正常短字段回答可补充商品；“你来定”不能让模型虚构商品，即使模型随后返回完整 ready brief。
- 当前待答问题要求文案原文且没有选项时，“不用”表示无文字，应保存 `texts=[]` 并继续原已授权请求的提示词准备；不能把“不用”作为图片文案。模型 kind 为 `clarification` 或 `requirements_change` 时语义应一致，而问候仍保留原问题。
- “你来定”只可委托已有审美问题；无当前问题时不能单独建立制作授权。
- 明确制作、无动词商品描述、问候加制作请求均只允许准备完整可编辑提示词。任何图片 provider 提交必须在用户执行 `confirm_prompt` 后发生；前端自动动作名单不得包含该动作。
