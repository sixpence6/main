## 4. 实施步骤与完成条件

按以下顺序实施。每一步用其完成条件交付证据；原任务恢复和确认边界遵循既有契约。

### 1. 统一尺寸协商与真实能力

1. 从供应商适配器的真实能力得到允许的输出集合，并明确区分用户期望比例、配置默认值与最终执行尺寸。S03 展示、后续需求快照、提示词预览和图片提交使用同一结果。
2. 核实供应商的方图参数与返回尺寸后，决定是否实现方图端到端支持。支持时，打通能力声明、请求参数、归一化与最终文件验证；暂不支持时，保留用户的 1:1 要求，清楚说明限制并只提供可执行替代选项。
3. 将业务上的尺寸冲突留在可回答的澄清状态，给出具体原因与可行动选项。只有用户明确接受替代比例，才更新需求版本并继续。

**完成条件：** 原始输入中的 1:1 在首轮报告可见；支持方图时能最终下载真实方图；不支持时能看到准确限制，既不会推荐无法执行的选项，也不会将默认横图当成用户已确认。复现输入不再得到通用 503。横图替代必须有用户确认记录，且提示词与下载文件保持同尺寸。

### 2. 保留已知需求并对齐可回答选项

1. 澄清输出保存经过契约与来源验证的已知字段，报告合并当前需求与本轮部分结果，只把实际未知项列为缺失。`data=null` 时显示「尚未结构化」或保留已验证字段，避免把已知信息断言为缺失。
2. 用现有部分 `BriefData` 能表达的字段优先实现；确需新结构时先落实字段契约与来源。默认尺寸只标为服务默认，不计作用户确认。
3. 题目与回答解析共用同一组选项 ID。存在可执行示例时明确显示 A/B/C 与推荐项；自由描述题给自然语言回复示例。显示给用户的简码必须能准确绑定问题和选项。
4. 用「仅留价格空白、后续添加」更新已回答状态，后续问题保留该结论；更新尺寸只重问受影响的构图，不清空主体、用途和无文字结论。

**完成条件：** 第一条输入即显示钢笔、电商主页、石墨黑底、1:1 与价格留白；新增提问只针对缺少的外观等信息。界面显示的每个选项 ID 均可解析，选中推荐项的简码与自然语言两种回答得到等价需求；刷新后已回答项与绑定关系仍存在。

### 3. 收敛 S07 请求并测量时限

1. 对同一已确认需求记录请求分项字符数、模型调用耗时与结果。确认 `final_brief`、`execution_snapshot` 与 `hard_requirements` 中哪些语义被重复传入，定位必要输入与重复副本。
2. 保留一份权威快照和稳定规则／证据 ID，按制图角色需要投影输入；减少重复字段和无关历史。数据库中的不可变快照继续完整保存，提示词仍需覆盖全部有效硬约束。
3. 在相同模型、输入和配置下比较调整前后耗时与预览结果。需要调整超时时，给出测量结果与配置选择，不把本次 180 秒诊断值直接当作修复结论。

**完成条件：** 有调整前后请求分项与调用耗时；原默认时限下可得到有效预览，或已有明确且验证过的新时限策略。所有有效硬约束仍绑定到预览请求，手动恢复复用同一意图；确认预览前图片提交数为 0，用量计数保持 1。单纯增大超时未满足此步。

### 4. 区分故障并约束恢复路径

1. 将「尺寸不支持／冲突」「模型响应无法解析」「模型请求超时」投影为不同的安全原因、用户文案与后续动作；内部保留角色调用 ID 与原错误码。
2. 恢复原任务时保持原输入、版本、意图和用量。对确定性的尺寸冲突提供改选项入口；对模型错误提供明确的手动恢复，遵守技术失败不自动重发的既有契约。
3. 验证请求处理中、等待补充、失败、恢复中与等待最终确认各状态下的输入框和按钮。只给出当前实际可执行的主动作；「正在核实」由真实查询中的状态驱动，查询结束或刷新后显示静态未知原因与下一步。

**完成条件：** 三类错误可分别构造并有对应界面证据；尺寸冲突不会反复引导无效重试；恢复后的输入与已回答项保留。恢复、刷新和重复点击不增加图片提交或原意图的计数。

### 5. 核实供应商长任务与结果找回能力

1. 读取本次原始任务的超时、提交事实、远端 ID 与结果地址记录，区分本地等待时限、网络超时和远端仍在处理。当前未知状态保持为未知，直到获得明确远端证据。
2. 核实实际供应商是否提供异步提交、按请求 ID 核实或原结果查询能力。支持时持久化真实任务 ID／结果定位信息并接通原任务查询；同步接口没有恢复能力时，界面说明当前限制及人工核实所需的本地请求 ID。
3. 核实与找回给出具体反馈，如「当前供应商不支持自动核实」或「暂未取得原结果」，并保留输入、预览、原授权与占用。依据真实测量选择等待策略，避免把增大等待时限或新发一张图片当成找回。

**完成条件：** 当前同步且无定位信息的分支有明确可理解的结果反馈；支持找回的测试分支能恢复同一任务的真实结果。所有核实、找回、刷新只读取原任务，图片提交与用量均保持 1。存在远端未确认事实时不会被错误记为失败、未提交或已取消；重新生成继续走既有显式授权。

1. 用第 2 节原始提示词启动新对话，按系统真实推荐选项作答；保存每轮问题、回答与需求版本。

3. 等待真实结果，检查画面与实际文件比例、黑身银夹、石墨黑背景、无画面文字和价格留白；验证聊天内展示、受保护下载和刷新恢复。

**完成条件：** 原始 1:1 路径存在完整截图、下载文件尺寸和最终交付状态；全程无需处理人员手工改库或伪造角色输出。保留前后两次显式确认，单次授权只提交一张图片、记一次受理；刷新后可查看同一结果。恢复分支和能力不支持分支另有结果，不能相互代替。
