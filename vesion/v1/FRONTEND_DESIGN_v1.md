## 1. 使用本文

本文定义页面结构、视觉、交互、客户端状态和前端验收。后端实现、数据库、模型适配协议沿用原文档。已有 API 是前端消费边界，不在本文新增接口或响应字段。

**前端布局以本文为准：** SRS 第 4 节的常驻左右两栏，以及技术文档目录中组件的示意，按本轮确认细化为 Head／Side／Body 工作台。Body 在需求对话与图片结果之间切换，不同时铺开常驻编辑栏和预览栏。产品范围、真实生图要求及服务端执行约束继续以原文档为准。两份原文档保留原样。

| 实现分支 | 必读内容 | 完成判据 |
|---|---|---|
| 页面、导航与样式 | 第 2–4 节 | 三个布局区域职责正确，窗口变化和阶段导航行为一致 |
| 对话、需求卡、参考图 | 第 5 节及第 8 节 | 本地编辑、服务端保存、整理、确认和生成分别受控 |
| 项目切换与恢复 | 第 6 节及第 9 节 | 刷新、切换、断网均不隐式提交新的生成请求 |
| 模型状态与 API 接入 | 第 7、10 节 | 信息来自已有契约；待核实项可定位，界面不假造能力 |
| 组件划分与交付 | 第 11–12 节 | 每项验收有可观察结果，未接通的真实链路如实标记 |

术语沿用技术文档：**项目**对应 Project，是一个商品的持续制作记录；**生成记录**对应 Generation，包含成功、失败等尝试；**图片版本**是可选择的成功结果。界面中的“当前需求”“当前预览图片”可以属于不同时间，不得把查看旧图解释为恢复旧需求。

## 2. 工作台与响应式布局

### 2.1 三个区域

```text
┌─────────────────────────────────────────────────────────┐
│ Head：电商生图智能体                                     │
├──────────────┬──────────────────────────────────────────┤
│ Side         │ Body 顶部：可点击的阶段导航＋当前状态       │
│ 展开／收缩   ├──────────────────────────────────────────┤
│ 新建项目     │                                          │
│ 已有项目     │  需求对话：消息、需求卡、提示词、生成状态   │
│              │               或                         │
│              │  图片结果：大图、版本、下载、继续修改      │
│              │                                          │
│ 模型状态     │  对话模式底部：参考图入口与文字输入框       │
└──────────────┴──────────────────────────────────────────┘
```

- **Head** 只显示产品名称，采用磨砂质感。不承载模型状态、项目操作或阶段导航。
- **Side** 包含展开／收缩控制、“新建项目”“已有项目”，底部为“模型状态”。图标收缩态保留可访问名称与悬停／聚焦文字提示。
- **Body** 顶部导航保持可见；其下同一内容区按第 4 节切换模式。当前项目标题显示在 Body 内，不挪入 Head。
- “已有项目”打开项目抽屉；“模型状态”打开只读详情抽屉。窄屏侧栏先关闭，再打开目标抽屉，避免叠放两个导航遮罩。

### 2.2 尺寸与滚动

下表为实现默认值；断点基于浏览器视口宽度。

| 视口 | Head | Side | Body |
|---|---|---|---|
| ≥1280px | 高 64px | 默认展开，宽 224px；收缩后 64px | 内边距 24px；对话内容最大宽 880px、结果内容最大宽 1120px，居中 |
| 768–1279px | 高 64px | 默认收缩；允许手动展开 | 内边距 20px，内容随剩余宽度收缩 |
| <768px | 高 56px | 默认隐藏，以抽屉打开 | 内边距 16px，单列展示；侧栏打开按钮放在 Body 导航左侧 |

侧栏开关在同一布局模式内尊重用户本次选择；进入不同断点模式时应用对应默认值，不将开关状态持久化。窄屏侧栏宽度不超过 272px 和视口可用宽度。“已有项目”抽屉桌面宽 360px、模型详情宽 400px，窄屏均限制在视口内。

工作台占满可用视口，Body 使用独立内容滚动区；阶段导航与对话输入区不随消息滚走。输入框增高后，消息区收缩，操作仍可见。抽屉独立滚动，打开时锁定背景滚动。页面不产生横向整体溢出；阶段导航和版本缩略图条可在各自区域横向滚动。

## 3. 视觉与可用性

### 3.1 视觉变量

采用浅色、轻奢 ins 风：暖色中性色、大块留白、克制装饰，以图片和内容为主体。Element Plus 的主题变量映射到以下值，避免出现默认蓝色与香槟棕混用。

| 用途 | 默认值 |
|---|---|
| 页面背景 | `#F4F0E8`，可叠加低对比的暖色渐变 |
| 实色内容面板 | `#FFFCF7` |
| 玻璃面板 | `rgba(255,252,247,0.84)`；背景模糊 16px，细描边 |
| 主文字／次文字 | `#2C2723`／`#6F665C` |
| 主操作／悬停 | `#705239`／`#5B4330`，按钮文字为白色 |
| 分隔边框 | `#DED5C7` |
| 装饰色 | `#B89A68`，用于少量线条和装饰，不作主要正文色 |
| 成功／提醒／错误／信息文字 | `#42664C`／`#7C5A22`／`#A43D35`／`#4F6274`，搭配浅色底及明确文字 |
| 字体 | 系统无衬线字体，优先覆盖 Segoe UI、Microsoft YaHei 与中文系统字体 |
| 字号／行高 | 正文 14/22px，输入正文 16/24px，区域标题 16/24px，产品名称 20/28px |
| 间距 | 4、8、12、16、24、32px |
| 圆角 | 控件 8px，面板 16px，大图容器 24px |
| 阴影 | `0 8px 24px rgba(44,39,35,0.06)` |

Head 必须呈现磨砂效果；Side 和抽屉可沿用玻璃面板。需求卡、输入区和图片区采用清晰的实色或近实色底，不让背景纹理干扰文字、商品或生成图片。基础样式先提供实色面板，仅在 `@supports` 检测支持时启用 `backdrop-filter`。

图片使用 `object-fit: contain`，完整显示内容；检查透明图时使用弱对比棋盘底。占位区域只标明“尚未生成图片”，不显示伪造商品图或模拟成功结果。加载时使用等待图标、文字与真实可得的阶段信息，不显示虚构百分比或剩余时间。

### 3.2 可用性基线

- 所有操作可用键盘触达；输入有文字标签。焦点使用 2px 主色轮廓和 2px 间隔，避免被容器裁切。
- 用文字和图标共同表达状态；正文以 4.5:1 为最低对比目标。玻璃开启与回退两种背景都需检查实际对比。
- 动态状态使用适当的 live region；轮询同一状态时不反复播报。按钮显示具体禁用原因，不能只靠灰色暗示。
- 抽屉和确认弹窗约束焦点，关闭后返回触发按钮；图片大图层支持 Esc 关闭。窄屏图标操作保留清晰的触摸区域。
- 动效仅用于短暂的淡入、颜色变化；响应 `prefers-reduced-motion`，减少装饰过渡。首版仅提供浅色主题。
- 验收环境为 Windows 上验收时的近期 Chrome、Edge；玻璃样式不可用时，功能、结构与阅读仍成立。

## 4. Body 模式与阶段导航

### 4.1 阶段导航

导航显示“描述需求 → 确认需求 → 生成图片 → 查看结果”，旁边用文字标明当前真实状态。按钮的浏览位置与项目的实际进度分别维护；查看旧内容时，实际状态仍然可见。

| 导航项 | 点击结果 | 可进入条件 |
|---|---|---|
| 描述需求 | 切换到对话，定位输入区或当前澄清问题 | 始终可查看；能否输入由第 8 节控制 |
| 确认需求 | 切换到对话，定位最新需求卡与提示词 | 已有需求卡；过期卡可查看，显示需重新整理 |
| 生成图片 | 切换到对话，定位生成前摘要或最近生成状态消息 | 已有可生成需求，或存在生成记录 |
| 查看结果 | 切换到图片结果模式 | 存在成功图片版本；文件缺失时显示对应交付异常 |

导航只切换视图或定位内容；“生成图片”导航项不发送生图请求。未解锁项显示原因，键盘用户也能取得该说明。正在处理的阶段明确标记，未来阶段不因点击而提前完成。

### 4.2 对话模式

消息区按时间展示用户文字、LLM 完整回复、需求卡及生成状态消息。LLM 等待期间显示“正在整理需求…”，不逐字输出；后端尚未提供的阶段不自行推测。

最新需求卡为唯一可操作卡片，之前的卡片标为历史记录，只读查看。历史卡片只在已有记录或快照足以还原时展示，不从普通消息文本拼造字段；数据缺口见第 10.2 节。

底部输入区包含多行文字框、参考图入口和发送按钮。Enter 换行，Ctrl／⌘ + Enter 发送；中文输入法组合输入期间不触发快捷发送。新对话自动定位最新消息；用户正在向上阅读时保留滚动位置，显示“有新内容”入口，由用户回到底部。

### 4.3 图片结果模式

Body 展示大图、版本缩略图、下载和“继续修改”。同时展示所选版本的版本号、时间和可取得的尺寸信息；需求快照与只读提示词放入可展开详情。

- 默认选中最新成功版本。查看旧版本只改变预览，不覆盖当前需求、参考图或确认状态。
- 新图完成时，若用户仍在该项目的对话中或处于跟随最新结果的状态，切换到结果并展示新图。
- 用户明确选中旧版本时保留该预览，显示“有新结果”；切到其他项目后也不强行跳回。
- “继续修改”返回对话并聚焦输入框，提示“反馈基于当前需求；查看历史图片不会恢复旧需求”。点击本身不发送消息。
- 大图层提供适应窗口、原尺寸查看和关闭；超出窗口的原尺寸图片可滚动查看。首版不做并排对比、裁剪、图层或局部编辑。
- 下载始终指向当前所选版本的资源；扩展名、编码及附件交付沿用现有资源接口。

打开或刷新项目时：若正在整理、存在活跃生成，或最近生成需处理失败／未知结果，优先进入对话并定位状态；否则有成功版本时显示最新成功图片，无成功版本时显示对话。旧图通过“查看结果”保持可访问。

## 5. 输入、需求卡与参考图

### 5.1 首屏与首次提交

没有项目参数时展示空白对话工作台、简短用途说明及少量输入示例。“已有项目”入口始终可见，不自动打开上次项目。示例只填入输入框，用户主动发送后才调用模型。

“新建项目”只进入空白工作台。首次发送有效文字或上传通过本地检查的参考图时，先创建项目，再执行该操作；创建期间阻止重复点击。收到项目 ID 后写入 `?project=<uuid>`。上传图片本身不触发 LLM；尚未提供文字时提示继续描述商品及目标。

项目创建成功而后续整理／上传失败时，保留该项目，重试不重复创建。创建回执不明确时保留输入，提示先到“已有项目”核实，不自动再次创建。延迟创建减少空记录，但不承诺上传或整理失败后历史中绝无空项目。

### 5.2 当前需求卡

字段语义沿用 SRS 第 5 节与技术文档第 5 节；下面只规定前端呈现。

| 字段 | 界面与编辑方式 |
|---|---|
| `product_description` | “商品描述”，多行编辑，确认前必须能识别商品主体 |
| `purpose` | “图片用途”，可编辑文字，提示主图／场景图／促销图；传输值遵循实际契约 |
| `style` | “画面风格”，多行编辑，LLM 建议可由用户修改 |
| `composition` | “构图与场景”，多行编辑 |
| `text_content` | “图片中的文字”，可留空；空值明确显示“不要求加字” |
| `image_size` | 固定输出尺寸，只读；未确定时显示“待配置”，不假填像素 |
| `reference_asset_id` | 以当前参考图缩略图和有／无图说明呈现，不要求用户编辑资源 ID |
| `prompt` | “完整生图提示词”，只读；首次展示当前有效版本时展开，长内容可折叠后重新展开 |

用户未提供的材质、功能、认证、价格等事实保持未指定，不由前端占位文案补全。澄清问题显示在对话内，用户通过普通消息集中回答。

编辑遵循以下顺序：

1. 点击“编辑需求”进入本地编辑；字段改变即标记未保存，同时禁用确认、生成。此时服务端版本尚未改变。
2. “取消编辑”恢复当前服务端卡片；“保存修改”提交字段与期望版本。成功后以响应／重新读取的服务端状态为准，显示“需求已更新，请重新整理”。
3. 用户点击“重新整理”，通过现有消息接口请求“按当前需求卡重新整理”。保存本身不调用 LLM。
4. 整理产生当前有效提示词后，用户点击“确认需求”；确认成功后显示独立的“生成图片”按钮。

保存失败保留编辑缓冲；整理失败保留已保存字段、用户原文和旧记录。参考图变化同样使旧提示词与确认失效。旧提示词可作为历史阅读，但显示“已过期”，不能充当本次确认内容。

生成按钮附近必须显示当前用途、完整提示词入口、参考图有无及缩略图、精确尺寸、数量“一张”。尺寸未确定或确认过期时显示阻塞原因。界面不设置自动确认、确认后自动生成或确认与生成合并按钮。

### 5.3 参考图

支持点击选择与拖放单张 PNG/JPEG；首版不做粘贴上传。格式和大小上限沿用 SRS，并取供应商更严格限制；实际字节上限的映射在接入时核实。

- 多文件一次拖入时提示“一次只能上传一张”，不静默截取其中一张。
- 本地检查文件类型、大小与可解码性，服务端校验仍为最终依据。无效文件不替换当前有效参考图，也不触发模型。
- 上传中显示局部等待态；临时本地预览标记为“待上传”，收到成功响应后才作为当前参考图。取消选择不产生修改。
- 提供替换、移除；请求失败保留旧图并显示原因，回执不明时先读取项目核实。浏览器对象 URL 在替换、移除、卸载后释放。
- 无图路径正常可用。有图而模型明确不支持参考图时，阻止生成并提供移除图片的操作；能力未知时显示待配置／待核实，不宣称支持。
- 反馈重生沿用当前原始参考图。成功生成的图片不会自动成为下一轮参考图。

## 6. 项目、草稿与版本浏览

### 6.1 已有项目

抽屉按服务端更新时间倒序展示，使用服务返回的标题；无标题时显示“未命名项目”。时间按浏览器本地时区展示。状态仅在已有响应可提供时显示；当前项目明确高亮。

首次打开加载首批，底部“加载更多”消费现有分页契约。加载期间按钮防重复；后续页失败保留已加载列表并显示重试入口；空列表显示“还没有项目”和新建入口。首版不增加搜索、重命名、删除、批量管理。

选中项目后关闭抽屉，更新查询参数并 GET 详情，不发送整理或生成请求。项目链接无效、资源不存在与服务暂不可达分别展示错误；保留新建和已有项目入口，不悄悄切换成另一个项目或自动创建记录。

### 6.2 草稿与离开

未发送文字、尚未保存的卡片字段属于本地草稿，只保留在页面内存。站内新建、切换项目及浏览器前进／后退涉及放弃草稿时，先提供“放弃修改／继续编辑”；取消后恢复原项目与 URL。已提交并保存的用户原文属于项目记录，不再视作未发送草稿。

仅在存在未保存内容时注册 `beforeunload`，清空或保存后移除。刷新／离站是否出现提示及提示文案由浏览器决定，不能保证关闭、崩溃等场景保留草稿。

生成提交的最小恢复凭据是第 9.1 节定义的例外。浏览器不持久化完整项目状态、对话、Key、图片 Base64 或未发送草稿。

### 6.3 切换与在途请求

开始加载新项目时停止旧项目轮询，清理旧读取，并显示明确加载态。所有异步返回都绑定发起时的项目 ID 与请求上下文；旧项目的晚到结果不能覆盖新项目、改变其图片或跳转其视图。

取消前端读取、隐藏页面、切换项目不等于取消后端操作。对已经提交的写操作保留受理核实上下文，再次打开对应项目时读取实际状态。整理或生成期间允许新建、查看其他项目、浏览旧版本与下载，当前项目的修改权限按第 8 节处理。

## 7. 只读模型状态

入口固定在 Side 底部，缺配置或本次调用出现相关错误时显示提醒标记；收缩态通过可访问名称与提示表达情况。Head 不承担此信息。

详情区分“需求整理模型（LLM）”与“图片生成模型（VISUAL）”，展示可取得的配置完整性、模型名称、能力及缺失项名称。配置完整与真实调用成功分开；没有真实验证信息时显示“尚未验证实际调用”，不把完整配置标成连接成功。

详情通过现有只读接口读取，可手动刷新；不提供修改 Key、切换模型或发起付费连通性测试的入口。缺配置时提示在本机配置 `backend/.env` 并重启应用。对应操作旁也显示可操作原因，不要求用户靠状态标记猜测。

未确定的尺寸、供应商文件限制和等待上限显示待配置／待核实。拿到真实配置后显示精确值；不自行设定模型速度、价格或支持能力。Key 不进入前端状态、构建变量或错误展示。

## 8. 状态与操作规则

### 8.1 两类服务端状态

需求状态和生成状态分别消费技术文档第 6 节的约定，不合并成一个丢失信息的前端枚举。

| 需求状态 | 用户可见状态 | 当前项目的主要动作 |
|---|---|---|
| `draft` | 编辑中／需要重新整理 | 发送文字、编辑卡片或参考图、重新整理 |
| `organizing` | 正在整理需求 | 查看记录，等待或查询状态 |
| `needs_input` | 需要补充信息 | 查看问题、补充文字 |
| `review` | 待确认 | 编辑卡片、查看提示词、确认需求 |
| `confirmed` | 需求已确认 | 点击生成，或修改后重新整理 |

| 生成状态 | 用户可见状态 | 当前记录的操作 |
|---|---|---|
| `queued` | 等待生成 | 查看状态及旧图片 |
| `running` | 正在生成／获取结果 | 按实际阶段显示；查看旧图片 |
| `succeeded` | 图片已完成 | 预览、下载、继续修改 |
| `failed` | 生成失败／结果获取失败 | 按原因显示再次生成或重取现有结果 |
| `unknown` | 结果未确认 | 查看任务信息；明确确认风险后才可再次生成 |

顶部状态优先显示活跃操作；非活动时显示当前需求进度，并在有需处理的最近生成异常时附加提醒。选择旧成功图片不把最近一次失败／未知状态改写为成功，过去失败也不遮蔽新需求的待确认状态。仅有输入草稿时附加“有未保存修改”，不冒充服务端已保存状态。

“提交待核实”“连接中断”“正在重取结果”“正在保存”是客户端提示，不扩展服务端状态枚举。

### 8.2 操作门槛

客户端采用同步互斥标记：在首次异步等待前禁用同项操作。整理、活跃生成、卡片保存、参考图变更、确认、生成提交或提交待核实期间，锁定当前项目新的修改操作；查看、项目导航与旧图下载保持可用。

| 操作 | 可执行条件 |
|---|---|
| 发送／重新整理 | 有有效文字或已保存的当前需求；LLM 已配置；当前项目无冲突操作；需求卡没有未保存编辑 |
| 保存卡片 | 存在字段改动，字段基本校验通过，当前项目可修改 |
| 确认需求 | 当前有效卡片与提示词已生成，提示词版本匹配当前版本，无必需澄清、未发送文字或未保存编辑 |
| 生成／再次生成 | 服务端确认有效，`revision = prompt_revision = confirmed_revision`；VISUAL 配置、尺寸和参考图能力满足要求；无草稿、活跃任务或待核实提交 |
| 恢复本次提交 | 存在经校验的原始提交凭据且用户明确点击；沿用第 9.1 节原请求，不按当前编辑内容重建 |
| 重取现有结果 | 已知结果获取失败，且现有契约能确认存在可重取的结果定位信息 |

输入空白字符不能发送；必要信息不清时通过 LLM 澄清，不由前端猜商品事实。服务端最终判定配置、版本和活动状态，前端禁用只是交互保护。任何拒绝都保留本地输入及成功旧图。

## 9. 提交、轮询与错误恢复

### 9.1 提交待核实与最小凭据

一次生成点击创建一个 UUID `request_id`。发送前同时保留内存中的原请求，并尝试将以下最小凭据写入该来源的 `sessionStorage`：项目 ID、`request_id`、原始 `confirmed_revision`、原请求中 `acknowledge_unknown` 是否存在及其值；拿到回执后可补充 Generation ID。按项目区分凭据，不保存完整卡片或图片。

这些值共同描述**原次提交**。恢复时参数与 ID 完全沿用，即使项目或配置已变化，也不重新计算参数。存储读取、解析、格式校验和写入均可失败；无效记录不能据此发请求。标签页关闭后不承诺保留，其他标签页也不能作为可靠共享来源。

| 情况 | 前端处理 |
|---|---|
| 收到明确受理回执 | 关联返回的生成记录，读取状态；消除“提交待核实”，最小凭据可随记录终态清理 |
| 收到明确拒绝 | 显示业务原因并解锁对应操作，按实际返回处理版本／配置冲突 |
| 发送后断网、超时或响应无法判定是否受理 | 显示“提交待核实”，锁住新生成；保留原凭据，提供“重新查询”“恢复本次提交” |
| 刷新后发现待核实凭据 | 先 GET 项目／已知生成记录；如实际响应可关联原 `request_id`，恢复已有记录；关联能力未明确时按第 10.2 节处理 |
| 查询无法确认原提交 | 保持待核实，由用户手动“恢复本次提交”，以相同 ID、相同参数请求现有生成接口；不自动创建新 ID |
| 已知需要恢复原提交，但凭据缺失或不可用 | 从服务端记录核实，明确显示恢复信息不可用；状态未明时不自动提出新提交替代原请求 |

自动恢复仅包含读取。没有凭据也没有待核实证据的普通首次进入，不凭空显示提交异常。点击“恢复本次提交”可能在原请求未受理时执行该次生成，按钮旁需说明这一含义；它与查看状态、主动再次生成是三种不同操作。

项目 GET 未查到记录不单独证明原请求已失败。凭据恢复及相同 ID 重试依赖现有技术契约，不宣称远端调用绝对不会重复计费。

### 9.2 查询规则

1. 当前项目处于 `organizing` 时查询项目详情；有 `queued/running` 生成记录时查询其状态。以最新成功读取结果决定后续查询对象。
2. 可见页面在前一次查询结束约 2 秒后发下一次，同一工作台至多一条自动状态查询在途；使用可清理的调度，避免请求堆积。
3. 每次成功读取清零连续失败计数。连续三次查询读取失败后停止调度，显示“连接中断，生成状态暂不可知”和“重新查询”。HTTP 成功但任务为 `failed/unknown` 属于业务终态，不计为读取失败。
4. 用户手动“重新查询”只发 GET；成功且仍活动时恢复查询，失败保留暂停提示。明确资源不存在时直接显示资源错误，不无休止查询。
5. 切换项目、卸载、进入终态时清理定时器及旧读取。页面隐藏时停止调度并清理对应读取；这些主动中止不计入读取失败。重新可见时读取最新状态再决定是否继续。因连续失败暂停的情况仍等待用户操作，不因切回页面偷偷恢复循环。
6. 新生成成功后 GET 项目详情同步版本列表，再按第 4.3 节决定预览；刷新或恢复整理状态不重新发送消息。

页面隐藏、查询暂停和读取超时都不代表取消后端生成。没有取消接口时不提供伪“取消生成”按钮。

### 9.3 错误与确认

错误及恢复入口留在对应消息、表单或结果区域；短暂通知只作补充。确认弹窗用于用户必须做选择的动作，不替代持久错误说明。

| 情况 | 展示与用户操作 |
|---|---|
| LLM 调用失败或整理中断 | 保留原文和已保存卡片，显示原因；用户主动“重新整理”，不自动重发原文 |
| 参考图校验／上传失败 | 在上传区域说明原因，保留原有效图；可替换或移除 |
| 普通生图明确失败 | 保留记录和旧图；“再次生成”是新的明确请求，仍检查当前需求确认 |
| 最近生成 `unknown` | 显示“上次请求可能已计费”；再次生成先弹窗“我已了解并再次生成／返回查看”，确认后携带 `acknowledge_unknown=true` 与新 ID |
| `RESULT_FETCH_FAILED` 且可重取 | 显示“重取现有结果”；只调用现有结果重取接口，加载期间防重入；失败保留旧图，成功刷新该记录 |
| 无可重取信息／本机文件缺失 | 明确显示无法重取或文件缺失；不显示成功下载，也不将“重试下载”连接到生图接口 |
| `409` 版本或活动冲突 | 停止当前修改流程，保留本地文字／字段供复制；用户选择加载最新记录或继续查看本地内容，后者不提交过期版本 |
| `413/422` | 定位相关字段或文件，保留输入；不自动缩图、改字或发送修正请求 |
| 模型缺配置、认证或额度问题 | 持久说明对应角色及可操作原因，提供模型状态入口；保留输入与图片 |
| 后端重启 | 按重新读取的实际状态呈现中断／结果未确认；已有记录和图片继续读取，不重发生成 |

冲突继续查看本地内容时，它是只读保留副本；复制后再主动加载服务端最新数据，不静默覆盖或自动合并。生图受理后的失败以生成记录为准，不把 GET 的 HTTP 成功误认为生成成功。

等待过程中可显示经过时间与服务明确提供的等待上限；前端本次请求的经过时间不冒充完整远端执行耗时。未提供的阶段、上限、费用和恢复能力保持未确定。

## 10. 前端与现有 API 的边界

### 10.1 使用方式

技术栈沿用技术文档第 2 节：Vue 3、TypeScript、Vite、Element Plus；`ref/reactive` 与工作台 composable；不引入 Router、Pinia。相对 `/api` 请求、统一错误处理放入 `src/api/`；不在组件中请求模型供应商。

完整方法、路径和关键输入以技术文档第 7 节为准。前端额外遵循以下调用后果：

| 已有接口类别 | 前端调用规则 |
|---|---|
| 健康与配置 GET | 只读诊断、展示；不作为付费模型验证 |
| 项目创建 POST | 仅首次有效发送／上传触发，创建成功后复用 ID |
| 项目列表／详情 GET | 项目抽屉、刷新、状态恢复和冲突核实；不触发后续写操作 |
| 消息 POST | 用户发送或明确重新整理才调用；使用当前期望版本 |
| 需求卡 PATCH | “保存修改”调用；成功后显示需重新整理，不自动调用消息接口 |
| 确认 POST | 只确认所展示的当前有效版本，不接着自动生图 |
| 参考图 POST／DELETE | 用户上传、替换、移除触发；携带当前期望版本 |
| 生成 POST | 仅生成按钮或明确恢复本次提交触发；参数归属见第 9.1 节 |
| 生成状态 GET | 第 9.2 节自动／手动查询，不附带生图提交 |
| 结果重取 POST | 仅用户点击重取现有结果；受理／完成方式待实际契约映射 |
| 资源 GET | 使用资源 ID 预览，下载采用已有 `download=true` 交付；不拼接本机文件路径 |

客户端不设置通用写请求自动重试。错误先解析已有统一错误体；无结构化内容时显示可理解的请求失败信息，不原样输出供应商响应、认证信息或堆栈。网络读取失败与业务拒绝分别映射到第 9 节。

### 10.2 接入待核实项

当前两份文档没有完整 OpenAPI 响应结构。以下是前端接入依赖，不是本文新增的后端方案；实现时读取实际 OpenAPI 和已有响应，再更新 `api/types.ts` 及字段映射。

| 编号 | 需核实内容 | 未明确时的处理 |
|---|---|---|
| FE-DEP-01 | 配置响应中的精确尺寸、供应商字节上限、等待上限及单位、能力表示 | 显示待配置／待核实；关键生成条件无法确认时禁用生成，不填假值 |

| FE-DEP-03 | 项目详情的消息与历史卡片关联、生成快照、版本排序、`request_id` 可关联性 | 仅展示实际可还原的记录；待核实提交无法匹配时保留原凭据供手动恢复 |

| FE-DEP-06 | 配置完整性与真实认证／调用结果是否有独立数据来源 | 无真实证据时显示“尚未验证实际调用”；会话内真实调用结果可作本次提示，不伪造持久验证记录 |

需求整理不要求前端识别参考图内容；模型供应商、实际输出尺寸及协议继续属于原文档的接入待定项。本文不增加模型配置写入、任务取消、项目删除或恢复旧版本为当前需求的接口。

| FE-AC-05 | 修改已确认卡片、输入未发送反馈或替换参考图 | 未保存／未发送内容阻止确认和生成；参考图保存后需重新整理确认 |
| FE-AC-06 | 拖入多图、无效／过大文件，或取消选择 | 不调用模型，不替换旧有效图；支持有效单图的上传、替换与移除 |
| FE-AC-07 | 快速重复点击发送、确认或生成；使用中文输入法和快捷键 | 同项在途操作不重复发出；组合输入不误发送，Enter 可换行 |
| FE-AC-08 | 首图成功后输入反馈并完成新版 | Body 切换结果；继续修改回到对话；原始参考图沿用；旧版和新版都可选择下载 |
| FE-AC-09 | 新图完成时正在看旧版或另一个项目 | 不覆盖主动选中的旧图、不跳回旧项目；当前项目可见新结果提示 |
| FE-AC-10 | 生成提交回执前断网，然后同标签页刷新 | 显示提交待核实，先 GET；无自动生成 POST；手动恢复使用原 ID 与原参数 |
| FE-AC-11 | 存储不可用、无效凭据、关闭标签页后重开 | 从记录核实并提示恢复信息限制；不因凭据丢失自动创建新生成 |
| FE-AC-12 | 查询连续失败三次，再点击重新查询 | 暂停自动查询，保留旧图；手动操作只发 GET，成功且仍活动时恢复 |
| FE-AC-13 | 隐藏／恢复页面，快速切换项目，制造旧 GET 晚到 | 无多路状态查询；晚到结果不覆盖新项目；读取暂停不显示任务已取消 |
| FE-AC-14 | 生成中刷新／服务重启后打开 | 读取原记录，按实际状态显示活动或结果未确认；不自动整理、不自动重新生图 |
| FE-AC-15 | `unknown` 后点击再次生成并先取消、再确认 | 取消不提交；确认说明可能已计费，并用新 ID 与明确确认标记提交 |
| FE-AC-16 | 结果获取失败，点击重取现有结果 | 调用结果重取接口；没有生成 POST；失败仍保留旧图，成功更新原记录 |
| FE-AC-17 | 另一个标签页修改需求，当前保存／确认收到冲突 | 本地内容可复制，用户主动加载最新；不覆盖服务端新状态或自动合并提交 |
| FE-AC-18 | 有草稿时切换、新建、前进／后退或刷新 | 站内可取消离开并保留原项目；离站提醒只在脏状态注册，不承诺浏览器一定拦截 |
| FE-AC-19 | 空配置、认证失败、文件缺失、项目不存在 | 原因与入口清楚；已有内容可保留查看；不显示假连接成功、假图片或成功下载 |
| FE-AC-20 | 键盘遍历、开关抽屉／大图层、减少动态效果、禁用毛玻璃 | 焦点和名称清楚，焦点可恢复；状态不限于颜色；回退后文字和操作清晰 |
| FE-AC-21 | 已有项目为空、多页、下一页读取失败 | 空态可新建；加载更多不重复，失败保留已加载项目；当前项目高亮 |
| FE-AC-22 | 配置真实两类 API，分别执行纯文字、参考图及反馈重生并下载 | 可实际打开生成文件；前端验收对应 SRS 的真实闭环，不以测试替身通过替代 |

布局与交互可通过受控响应验证；真实 API、文件交付和重启恢复沿用 SRS 第 7 节的完整验收。本文交付只表示前端设计已确认，不表示这些实现或验收已经完成。

## 13. 浏览器事实依据

以下资料已在本轮查阅，用于第 3、6、9 节的实现边界：

- [MDN：backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/backdrop-filter) 与 [@supports](https://developer.mozilla.org/en-US/docs/Web/CSS/@supports)：背景模糊及条件启用，基础样式保留实色回退。
- [MDN：beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)：需要用户交互、提示文字由浏览器控制、事件并非总会触发；仅在未保存时注册。
- [MDN：sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage)、[Storage.getItem](https://developer.mozilla.org/en-US/docs/Web/API/Storage/getItem)、[Storage.setItem](https://developer.mozilla.org/en-US/docs/Web/API/Storage/setItem)：页面会话内的最小凭据恢复、标签页生命周期及存储失败处理。
- [MDN：Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)：使用页面可见性决定前端查询；后台定时器节流不构成服务端任务取消。
